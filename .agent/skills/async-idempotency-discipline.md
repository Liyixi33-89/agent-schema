# 异步任务与幂等纪律

## 何时使用

实现领域事件投递、Kafka 生产/消费、异步任务（导入导出/DDL 执行/数据体检）、定时任务时。真源：`docs/详细技术文档/10-基础设施与工程规范.md` §3（统一异步基建）+ §A.4（任务协议）。

## 规则/经验

1. **异步通道唯一**：Kafka（ADR-001 定版）+ 统一异步任务框架（10BE §3）——**禁自建轮询表/新引 MQ/直接 new Thread 跑业务**；任务统一走任务协议（提交→进度→完成/失败，§A.4），前端 TaskCenter 消费同一协议。
2. **Outbox 模式发布事件**：领域事件同业务事务写 outbox 表，独立投递器异步发 Kafka——**禁事务内直接发 MQ**（事务回滚消息已飞出去 = 脏事件）；投递器至少一次语义 + 消费端幂等收口。
3. **消费幂等三板斧**：业务唯一键去重表（事件 id/业务号唯一约束）或版本号比对（旧版本事件丢弃）；**默认按「会重复投递」设计消费者**——无幂等设计的消费代码不予合并。
4. **重试纪律**：可重试错误（网络/限流）指数退避，**上限固定**（如 5 次后入死信）；不可重试错误（校验失败/数据不存在）直接死信不空转；**禁无条件无限重试**（毒丸消息堵死分区）；重试次数与原因入结构化日志。
5. **死信处置闭环**：死信队列必须有人工处置通道（后台查询/重放/放弃操作）+ 告警接入（积压阈值）；死信不是垃圾桶——超阈值守卫值班响应（G4 告警演练含此项）。
6. **任务进度与取消**：长任务（DDL/导入导出）进度百分比回写任务表；支持取消的任务定期查取消标记（任务协议 §A.4）；任务失败原因面向用户可读（不含堆栈）。
7. **定时任务**：走统一调度（禁散落 `@Scheduled` 各自为政——登记调度清单）；分布式锁防多实例重复执行；执行历史入任务表可审计。
8. **顺序与分区**：需要顺序的流（同租户同聚合事件）按聚合 id 分区键；消费者不假设跨分区顺序。

## 反模式（踩过的坑）

- 事务提交后发 MQ 写在 Service 最后一行「看着没事」 → 提交前异常回滚但消息已发；一律 Outbox。
- 消费者「处理失败重抛」不设上限 → 毒丸消息无限循环堵分区；退避 + 死信。
- 用 Kafka 传大 payload（整文件内容） → 消息膨胀拖垮 broker；传引用（文件 id/任务 id）。
- 定时任务多实例重复跑（无锁） → 重复通知/重复扣减；分布式锁 + 任务表幂等双保险。

## 验证方式

消费幂等测试（同消息投递两次断言业务效果一次）；重试上限用例（超限入死信断言）；Outbox 与业务事务原子性用例（事务回滚后无消息）。
