# 变更验收四边界（执行步骤）

> 规则真源：`AGENTS.md` §7「变更验收四边界」。本 skill 只写核对动作与自检问题。

## 何时使用

任何涉及请求、异步状态、组件拆分或功能入口的改动，提交前逐项过一遍。

## 一、请求边界

- [ ] 错误类型携带 `status`/`code`；**403 按状态码判定，不匹配错误文案**
- [ ] 响应做契约校验；**校验失败进入错误态，不得显示成空数据**
- [ ] 请求可取消（`AbortSignal`）；过期响应按序号丢弃
- [ ] 权限与环境隔离（主站/验收面 Cookie 路径、租户头）未被绕过

## 二、状态边界

- [ ] 明确「谁拥有状态」：服务端数据 / 全局 UI / 字段级 / 组件私有
- [ ] 查询身份变化（月份、租户、筛选）→ **重置**，不展示上一个身份的数据
- [ ] 相同查询刷新 → 保留旧数据但标 `refreshing`/`stale`，不冒充最新
- [ ] 衍生值渲染期计算，不重复存储（避免双源漂移）

## 三、生命周期边界

- [ ] 定时器 / 事件监听 / 订阅 / 在途请求在卸载时清理
- [ ] 轮询不重叠（上一次完成后再调度下一次）
- [ ] 组件类型稳定（同位置不切换不同组件类型导致全量重挂载）
- [ ] 拆分不丢表单状态（受控值、校验态、焦点）

## 四、交付边界

- [ ] 实现范围写清（做了什么 / 明确没做什么）
- [ ] 回归场景列出（正例 + 负例），并说明哪些**实际跑过**、哪些没跑
- [ ] 被测版本（commit / 构建产物）明确
- [ ] 剩余风险与未支持能力显式登记
- [ ] 重构 PR 不混功能扩展、不换库、不全仓格式化

## 自检五问（PR 描述固定回答）

1. 改了哪个业务边界？
2. 是否改契约、权限或状态生命周期？
3. 为什么抽组件/Hook，复用点是什么？
4. 哪些正负例实际验证？哪些没跑？
5. 是否引入新依赖、环境变化或未支持能力？

## 验证方式

`scripts/verify.ps1 -Level commit` 通过；关键请求/状态变更有对应回归用例；
发布候选跑浏览器主链（真实交互，不用纯函数测试替代）。
