# 持久化与查询纪律

## 何时使用

编写任何数据库访问代码（MyBatis Mapper/JPA/原生 SQL）、设计查询接口、处理 JSONB 字段时。真源：`docs/详细技术文档/01-元数据服务.md`、`02-数据引擎.md`。

## 规则/经验

1. **参数化铁律**（sql-injection-guard 联动）：一切用户输入走参数绑定 `#{}`；`${}` 仅限**代码内白名单常量拼接**（表名列名白名单映射，禁用户输入直达）；动态 SQL 用 `<choose>`/`<if>` 结构化生成，禁字符串拼 SQL。
2. **排序与过滤白名单**：排序字段必须是显式白名单数组内的合法列（防排序注入 + 防走错索引）；过滤操作符走 ConditionTree 11 个协议操作符，**禁接口层透传任意操作符字符串**。
3. **禁 N+1**：列表 + 关联数据用 JOIN 或批量 IN 查询（`WHERE id IN (...)` 后内存组装）；审查信号——循环体内出现 Mapper 调用。集合映射用 MyBatis collection 或手动二次查询组装，不用懒加载触发隐式 N+1。
4. **无界查询禁止**：所有列表接口强制分页上限（pageSize ≤ 100 硬约束）；导出类全量读取走游标流式 + 异步任务（10BE §A.4 协议），**禁同步接口全表返回**；`SELECT *` 禁用——显式列清单（配合 DTO 契约）。
5. **JSONB 操作规范**：读写走数据引擎统一管线（提升列维护、路径查询）；高频过滤字段标记提升为物理 STORED 列（PRD 01 变更策略）；JSONB 内部查询用 GIN 索引配套（建索引走元数据服务，禁手写 DDL）；**去提升只软失效，永不 DROP COLUMN**（flyway-migration-discipline 联动）。
6. **软删统一**：删除 = 逻辑标记（元数据层 DELETED 状态）；查询默认过滤已删；需要含删数据的场景显式声明（历史版本/审计读取）。被引用字段删除走影响面扫描（PRD 01 §3.5）。
7. **租户条件不可绕过**：租户过滤由 MyBatis 拦截器统一注入（tenant-isolation-guard 联动）——新表必须含 tenant_id 并登记拦截清单（02 篇 TC-ISO-05 表清单资产）；**禁手写绕过拦截器的原生 SQL 查业务表**。
8. **连接与游标纪律**：单请求查询数控制（审查信号：Service 方法超 3 次 DB 往返考虑重组）；长事务游标独占连接需评估池水位（容量测试 PERF-01 观察项）。

## 反模式（踩过的坑）

- 深分页 `LIMIT 100000, 20` → 扫描浪费；游标分页（WHERE id > lastId）或预声明「深翻页禁止」产品约定。
- MyBatis `${orderBy}` 直通用户输入 → 排序注入 + 全表扫描攻击面；白名单映射表。
- 一个接口聚合 8 张表 JOIN「减少往返」 → 优化器失控难索引；按聚合边界拆 + 必要时读模型宽表。
- 乐观更新无 version 条件 → 并发覆盖；WHERE 带 version（事务纪律联动）。

## 验证方式

慢查询断言（集成测试执行计划无全表扫描——高频路径）；N+1 检测（p6spy/日志统计单请求 SQL 数）；越权用例每 Service 必附（10BE §7.1 合并硬条件）。
