# 文档防腐与上下文预算

## 何时使用

更新 AGENTS.md / 新写或修订 spec / skill / 向会话粘贴大段内容前。

## 规则/经验

1. **防腐判据**：写下的每句话问「一个月后还成立吗？」——任务进度、具体行号、临时 TODO、实时配置值（端口/路径/版本号）不成立，删掉或改为现场读取。
2. **实时状态走工具，静态规范走文件**：依赖树/路由/Schema 现状从代码读取（outline → 局部读），永远不誊抄进文档。
3. **预算表**（AGENTS.md §5）：AGENTS.md ≤200 行常驻；spec 单份 ≤500 行；代码禁止整仓投喂。
4. **长内容/含特殊字符内容走文件通道**：公钥、证书、带引号/`$` 的命令脚本一律写文件再引用，**不经过 LLM 复述**——转录错误不可检且难排查（真实教训：750 字符公钥两次转录错误致 SSH 认证失败）。
5. **AI 工具写回复查**：AI 编辑器/AI Agent 重写 `.ps1` 等含 BOM 文件后必复查前 3 字节——本轮实证：`replace_in_file` 每次重写都会剥 BOM，脚本随即按 GBK 解码语法错乱（连续触发两次才定位为系统性行为，非偶发）。
6. **PowerShell 5.1 读写中文文件三铁律**（本项目实证，2026-10-26）：
   - 读：`Get-Content -Encoding UTF8` 不加参数 = GBK 误解码（frontmatter 校验全部误报的根因）；
   - 写：`Set-Content -Encoding UTF8` 会**加 BOM**——保无 BOM 用 `[System.IO.File]::WriteAllText($p, $s, [UTF8Encoding]::new($false))`；
   - **GBK 读 + UTF-8 写 = 静默数据污染**（`待定`→`寰呭畾`）：凡 AI 流程中经手过的中文文件，交付前用独立通道（Python 按 UTF-8 读）抽查关键行字节。
7. spec 结项即回填：`status → done` + 沉淀记录；范围与交付不符当场修正，不留「下次再说」。
8. 检查器防腐：verify 脚本的检查项用目录动态扫描，不做硬编码清单（硬编码 = 新增项漏检无人察觉）。

## 反模式

- 文档里写「当前共 N 个接口/第 X 行」——一周后就是毒数据，AI 据此做错误决策。(体系原则 §2.4)
- 把整份 30KB 技术方案塞进会话「让 AI 全了解」：噪音淹没关键小节，烧 token 且质量下降。(预算表)
- 防腐检查只验证「文件存在」不验证「内容正确」：过期内容静默存活，比缺失更危险。(元问题 §3.6)

## 验证方式

`pwsh scripts/verify.ps1 -Level quick` 的文档防腐检查通过（AGENTS.md 行数 ≤200、specs/skills 必填字段、动态扫描完整性）。
