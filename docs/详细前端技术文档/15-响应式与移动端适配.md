## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| 断点检测系统（useBreakpoint Hook + CSS 容器查询降级） | 移动端原生壳（PWA/App 打包——P3 评估） |
| 渲染管线的断点注入点（P1 保底规则的执行层） | 设计器移动编辑（不做，PC Only） |
| P2 断点级配置的 Schema 协议扩展与执行 | 移动专属业务逻辑（物料只管交互形态） |

## 2. 断点系统

```ts
// 单一断点定义（与 AntD Grid 对齐，避免两套栅格）
type Breakpoint = 'xs' | 'sm' | 'md' | 'lg';      // <576 | ≥576 | ≥768 | ≥992
// 二元视图模型（产品语义是 PC / 移动两态，xs/sm=移动，md/lg=PC）
type ViewMode = 'desktop' | 'mobile';

// useBreakpoint：matchMedia 监听 + SSR 安全（设计器预览可强制注入）
function useBreakpoint(force?: Breakpoint): { bp: Breakpoint; view: ViewMode };
```

- **为什么 Hook 而非纯 CSS**：P1 保底需要执行结构性变换（表格降级卡片=换组件渲染，不是样式调整）——CSS 只能做显隐/堆叠，做不了「Table → CardList」的组件替换；
- CSS 容器查询用于**样式级**响应（栅格堆叠、间距收缩），组件级响应走 Hook 判定——两机制分工不混用；
- 断点值全局唯一来源：`schema-protocol` 常量导出（双端一致；后端不需要，但设计器预览与运行时必须同源）。

## 3. 渲染管线注入点（P1 保底规则的执行位置）

```
渲染管线（文档 02FE §2）的断点注入：

PageSchema → validate/migrate → collectDependencies → RenderScope
                                                │
                          ⑤ responsiveTransform(layout, viewMode)   ← 新增步骤
                                                │
                                        NodeRenderer 递归

responsiveTransform（P1 保底，纯函数）：
  输入：layout 树 + viewMode
  desktop → 原样输出（零开销：desktop 短路直接返回原树引用）
  mobile  → 按规则逐节点变换：
    ① Grid 栅格：col span 忽略 → 全部堆叠单列（flexDirection: column）
    ② Table 物料 → MobileCardList（降级渲染器：前 5 列卡片化 + 展开详情行）
    ③ 多列布局容器（左右分栏）→ 单列纵向
    ④ 原生触控优化：日期/选择器交给物料自身（AntD 移动形态自动切换）
  输出：变换后 layout 树（不修改原 Schema——只读变换，落库仍是 desktop 布局）
```

- 变换是**渲染前纯函数**：同一 Schema 两态渲染，不产生 Schema 副本落库（设计器保存的永远是 desktop 视图）；
- 性能：变换结果按 `(pageId, viewMode)` 记忆化；窗口 resize 跨断点时重建一次（<1ms 级，非拖拽热路径）。

## 4. P2 断点级配置协议

```
Schema 扩展（LayoutNode 级，协议层 schemaVersion minor 升级）：

interface LayoutNode {
  ...
  responsive?: {
    mobile?: {
      hidden?: boolean;              // 移动端隐藏该节点
      order?: number;                 // 移动端显示顺序（未设按原顺序）
    };
  };
}

设计器配置面：
  物料属性面板「高级」分组增加「移动端」折叠区（x-group: 'responsive'）
    → 显隐开关 + 顺序拖拽（仅当页面开启「移动端配置」模式时显示）
  设计器顶栏「PC / 移动」视图切换：
    移动视图 = responsiveTransform 结果 + 移动端配置叠加渲染
    （所见即所得：配置即时反映到 375px 视口）

执行优先级（运行时）：
  mobile 视图 = responsiveTransform 保底变换 → 应用 responsive.mobile 覆盖
    （hidden 节点剔除；order 重排；用户配置覆盖保底规则）
```

- 协议兼容：`responsive` 字段可选，旧 Schema 无该字段走 P1 保底——协议层 zod 向后兼容（minor 版本不迁移）；
- 仪表盘页（type=dashboard）P2 不开放移动端配置：图表卡片默认双列堆叠，复杂配置延到需求验证后。

## 5. 移动端专属物料（P2，PRD 02 §2.9）

| 物料 | componentName | 要点 |
|---|---|---|
| 拍照上传 | `biz.mobile-camera` | `accept="image/*" capture="environment"` 调系统相机；直传 file-service 预签名链（文档 11 §A.1 四步） |
| 扫码输入 | `biz.mobile-scanner` | BarcodeDetector API + 手输降级（兼容性）；结果写入字段值 |
| 定位采集 | `biz.mobile-geo` | Geolocation API；HTTPS 强制（浏览器约束）；拒绝授权降级为手填地址 |

- 三物料 `widgetFor` 声明仅在 mobile 视图可拖入（设计器拖拽校验读 viewMode）；
- 权限提示：定位/相机首次调用物料内嵌引导浮层（授权被拒的操作指引），不静默失败。

## 6. 性能预算落地（PRD 02 §2.9 性能表）

| 指标 | 手段 |
|---|---|
| 移动端表单首屏（3G 快速档）< 3s | 物料分片按需加载（桌面 Table chunk 移动端不加载，MobileCardList 独立 chunk）；Schema 压缩传输（gzip）；首屏只请求当前页数据 |
| 移动端交互流畅 | 触控目标 ≥44px（物料移动态样式基线）；图表惰性实例化（文档 12FE §7） |
| 弱网容错 | 请求失败统一占位 + 重试（不白屏）；提交中禁用按钮防重复提交 |

## 7. 单元测试硬性要求

- [ ] 保底变换：desktop 短路零开销（引用相等断言）；mobile 下 Grid 堆叠/Table 降级/分栏单列三类变换快照
- [ ] P2 覆盖：hidden 节点移动端不渲染；order 重排生效；用户配置优先于保底规则
- [ ] 协议兼容：无 responsive 字段的旧 Schema 在 mobile 视图正常走保底（zod 向后兼容）
- [ ] 断点切换：resize 跨断点重建变换且无内存泄漏（监听器清理断言）
- [ ] 移动物料：相机/扫码/定位在非安全上下文（http）降级路径正确；授权拒绝引导浮层出现
- [ ] 性能基准（CI 门禁）：3G 节流模拟下移动表单首屏断言；移动视图无 Table chunk 加载（network 断言）
