# 详细前端技术文档 13 · 主题引擎与品牌定制（theme-engine）

> 上游：详细 PRD 02 §2.10（主题与品牌 P2）、PRD 07 §2.1（应用主题配置）；后端文档 13 §3.1（`app.theme` 存储）
> 本文定位：**实现级技术设计**——主题 token 体系、ThemeProvider 注入链、CSS 变量映射、登录页/登录态/热切换时序
> 形态：`packages/shared-ui` 内的 theme 模块（不独立成包——消费方是全部应用，随 shared-ui 走）
> 红线：**仅开放变量级定制，不支持自定义 CSS 注入**（PRD 02 §2.10——CSS 注入 = 存储型 XSS 面，产品层已封死）

---

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| 主题 token 定义与默认值（design token 体系） | Logo 文件上传存储（file-service，后端 11） |
| 应用级 token 覆盖 → CSS 变量注入 | 物料组件内部样式实现（物料只消费变量） |
| AntD ConfigProvider 动态 token 同步 | 设计器自身主题（设计器永远平台默认蓝——平台品牌与客户品牌分离） |
| 登录页品牌渲染与热切换 | 租户级品牌（一期主题只到应用级；租户级 P3 预留） |

## 2. 主题 token 体系

```ts
// 三层结构：平台默认 → 应用覆盖 → （预留）租户覆盖
interface AppTheme {
  logoFileId?: string;          // 导航壳 Logo（file-service）
  primaryColor?: string;        // 主色（hex，校验后注入）
  loginBgFileId?: string;       // 登录页背景
  tokens?: {                    // 可选扩展变量（白名单键）
    colorSidebar?: string;
    borderRadius?: number;      // 4 | 6 | 8
  };
}
// 白名单校验（zod）：颜色 hex 正则、borderRadius 枚举——未知键拒绝（防 token 面积失控）
```

- token 白名单**封闭集合**：一期仅 5 个键（logo/主色/登录背景/侧栏色/圆角）——每加一个键都是全物料适配成本，走需求评审扩展；
- 色板推导：主色 → 10 级色阶（AntD `theme算法` generate）→ hover/active/disabled 自动派生，**用户只配一个主色**。

## 3. 注入链（ThemeProvider）

```
AppBootstrap（运行时容器启动管线，文档 06FE §2）
  ① 应用清单响应携带 theme（随 /api/runtime/apps/current 下发，无额外请求）
  ② ThemeProvider.resolve(appTheme)：
       平台默认 token → merge 应用覆盖 → 产出生效 token 集
  ③ 双通道注入：
     CSS 变量：document.documentElement.style.setProperty('--schema-primary', ...)
       → 自研物料/图表（ChartKit 主题板，文档 12FE §2 ④）消费 CSS 变量
     AntD token：<ConfigProvider theme={{ token: { colorPrimary, borderRadius } }}>
       → AntD 系组件（基础物料薄封装层）消费
  ④ Logo/背景：主题资源 URL 走 file-service 下载凭证（5min 时效，内存缓存按需刷新）

设计器内预览：应用设置「主题」页保存 → 即时调 ThemeProvider.resolve 预览壳
  （预览态与运行态同一 resolve 函数——所见即所得）
```

- **为什么双通道**：AntD 5 的 CSS-in-JS token 无法被自定义物料/Shadow DOM 场景读取；CSS 变量是唯一能穿透 Web Component 边界（继承进 Shadow DOM）的全局机制——嵌入形态（文档 06FE §5）下品牌一致性靠 CSS 变量兜底；
- 性能：token 注入在启动管线同步完成（无闪烁）；色阶推导结果按 primaryColor LRU 缓存。

## 4. 热切换时序

```
应用管理员改主题并保存
  → PUT /api/apps/{id}（theme 字段，后端 13 §A.1）
  → 保存成功后前端本地 ThemeProvider.apply(newTheme)（同会话即时生效）
  → 已打开的其他会话：应用清单无版本号字段，采用「下次启动生效」策略
    （主题变更低频且非关键业务，不做 WS 推送——避免为它扩长连接协议）

登录页品牌：
  登录页在鉴权前，拿不到应用清单——登录页按「租户默认主题」渲染：
  GET /api/tenant/branding（公开接口，只含 logo/背景图 URL，无敏感配置）
  租户未配 → 平台默认（SaaS 官方品牌页）
```

## 5. 物料侧消费契约

| 消费方 | 契约 |
|---|---|
| 基础物料（AntD 薄封装） | 禁止硬编码颜色；AntD token 自动生效，物料不自设色 |
| 业务/图表物料 | `var(--schema-primary)` 等 CSS 变量；ChartKit 主题板从 CSS 变量读色阶（文档 12FE §2 ④） |
| 自定义物料（轨道 B） | 产物内只消费 CSS 变量；CI 静态扫描禁止硬编码 hex（白名单：黑白灰中性色） |
| 导航壳/登录页 | 同上；Logo 尺寸约束 24×24 SVG/PNG |

## 6. 单元测试硬性要求

- [ ] 注入链：appTheme 覆盖后 CSS 变量与 ConfigProvider token 同步更新（双通道一致）
- [ ] 白名单：未知 token 键保存被拒；非法 hex 被拒（zod 校验）
- [ ] 色阶推导：同一主色 LRU 命中；hover/active 色阶与 AntD generate 一致
- [ ] 热切换：保存后同会话即时生效；未保存的编辑不泄漏到运行时
- [ ] 登录页：租户未配主题时渲染平台默认；branding 接口失败静默降级（不阻塞登录）
- [ ] Shadow DOM：Web Component 嵌入形态下 CSS 变量穿透生效（变量继承断言）
- [ ] 硬编码扫描：物料/产物中非白名单 hex 出现即 CI 失败
