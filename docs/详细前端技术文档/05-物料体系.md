## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| MaterialMeta 协议定义与运行时注册表 | 物料被渲染的分派（schema-renderer） |
| 基础物料/业务物料实现（薄封装 AntD） | 属性面板表单渲染（schema-form 消费 propsSchema） |
| 物料按需分片加载（设计器与运行时共用） | 物料市场上架/审核流程（应用管理域） |
| 第三方/自定义物料的协议约束与加载 | 编译产物生成（后端 build-service） |

## 2. MaterialMeta 协议（两轨统一）

```ts
interface MaterialMeta {
  componentName: string;                       // 全局唯一，命名空间约定：基础 `basic.*` / 业务 `biz.*` / 自定义 `custom.{tenant}.*`
  category: 'basic' | 'business' | 'layout' | 'custom';
  propsSchema: JSONSchema;                     // 驱动属性面板（扩展关键字见 §4）
  defaultProps: Record<string, unknown>;
  component: React.ComponentType<any> | (() => Promise<{ default: React.ComponentType<any> }>);
  runtime: 'dynamic' | 'compiled';             // 轨道分派标记（§02 §3）
  acceptChildren?: boolean;                    // 画布嵌套校验依据
  previewImage?: string;                       # 物料面板缩略图
  widgetFor?: Partial<Record<FieldType, string>>;   // 作为字段默认 widget 的映射声明
  isFieldWidget?: boolean;                     // 可绑定 fieldRef 的表单类物料
  events?: string[];                           // 可挂动作的事件名（onClick 等）
}
```

## 3. 注册表与分片加载

```
materialRegistry（Map<componentName, MaterialMeta>）

内置物料：静态清单（name → dynamic import 工厂），构建时按物料独立分片：
  Vite 多入口配置：每个物料一个 async chunk（basic-input.js / biz-user-picker.js ...）
自定义物料：租户物料清单接口（运行时拉取 name → artifactUrl 映射），import(artifactUrl) 注册

注册时机：
  设计器：物料面板展示即预取全部内置物料元数据（不拉实现）；拖入画布才加载实现
  运行时：collectComponents(pageSchema) 精确收集本页 componentName → 按需并行加载
  （首屏只加载当前页面用到的物料——技术方案 §3.9 性能要求）

缺失物料：注册表查无 → UnknownWidget 占位（含 componentName 提示），上报遥测
版本冲突：同 name 二次注册以先注册为准 + 控制台告警（防自定义物料覆盖内置）
```

## 4. propsSchema 编写规范（属性面板可生成性的根基）

JSONSchema 之上约定扩展关键字（设计器识别）：

| 扩展 | 用途 | 示例 |
|---|---|---|
| `x-group` | 属性面板分组（基础/数据/联动/高级） | `"x-group": "data"` |
| `x-widget` | 该属性用哪个配置控件渲染（含 `expr-editor`） | `"x-widget": "expr-editor"` |
| `x-field-binding` | 标记为字段绑定属性（下拉列 ACTIVE 字段） | `"x-field-binding": true` |
| `x-actions` | 标记为动作绑定属性（动作编排面板） | `"x-actions": ["onClick"]` |
| `x-enum-remote` | 枚举选项来自远程元数据 | `"x-enum-remote": "models"` |

**物料作者契约（CI 校验）**：

1. 每个物料必须有 propsSchema/defaultProps/component 三件套，缺一构建失败；
2. propsSchema 中引用的 x-widget 控件必须在设计器注册过；
3. 受控契约：`isFieldWidget=true` 的物料必须实现 `value/onChange`，Storybook 用例验证受控行为；
4. defaultProps 必须能通过自身 propsSchema 的 zod 校验（自洽）。

## 5. 内置物料清单与实现要点

**P1 基础物料**（薄封装 AntD，受控适配 + `data-node-id` 透传）：

Input、TextArea、InputNumber、Select、DatePicker、Switch、Radio、Checkbox、Upload、RichEditor（基于 tiptap 受控封装）、UserPicker、DeptPicker、Table（虚拟滚动 + 列配置消费方）、FormContainer、Card、Tabs。

**RichEditor 安全约定（XSS 防线，2026-10-28 定版）**：
- 存储内容为 tiptap JSON 文档（**不存原始 HTML**）——持久层天然无脚本注入面；
- HTML 粘贴入口：DOMPurify 白名单模式清洗（`ALLOWED_TAGS/ALLOWED_ATTR` 收敛到 tiptap 支持集，`FORBID_ATTR: style`）后才进编辑器模型；
- 渲染出口：tiptap ReactRenderer 渲染 JSON → React 组件树（不经 `dangerouslySetInnerHTML`）；导出 HTML 场景走服务端同规则清洗（双端规则文件 `rich-text-policy.json` 入契约 CI diff）；
- 链接协议白名单：`http/https/mailto`（禁 `javascript:`/`data:`）；外链统一 `rel="noopener noreferrer"` + 新窗口；
- 平台级 lint 禁令：物料与 packages 内 `dangerouslySetInnerHTML` 出现即 CI 失败（白名单例外集中在 RichEditor 出口并注释理由）。

**P2 业务物料**（差异化竞争力，重点投入）：

AddressPicker（省市区数据内置离线包，不依赖外部 API——私有化红线）、OrgTreeSelector、FilePreview、AmountInput（千分位 + 大写金额）、ApprovalTimeline（消费流程实例接口）。

**布局物料**：`acceptChildren=true` 且无数据语义；Grid 栅格 24 列（与仪表盘一致）。

**图表物料**（P2）：`chart.line/bar/pie/number-card/table-card`，协议扩展 `acceptsDataSource` 与 `dimensionMapper`——实现设计见前端文档 12（ChartKit 封装、聚合数据源、图表联动）。

**移动端专属物料**（P2）：`biz.mobile-camera/scanner/geo`，仅 mobile 视图可拖入（断点系统见前端文档 15 §5）。

## 6. 自定义物料接入（轨道 B，P2）

```
脚手架：物料模板仓库（含 MaterialMeta 导出 + propsSchema + Storybook 样例）
本地开发：npm 包 + 本地注册（设计器 dev 模式读取本地物料清单）
发布：源码提交 → build-service 编译（红线扫描同文档 08 §3）→ 产物注册到租户物料清单
上架市场：管理员审核 componentName 命名空间与 propsSchema 自洽性（CI 校验规则同 §4）
加载：设计器与运行时统一走注册表异步加载路径（与内置物料无差别）
```

## 7. 单元测试硬性要求

- [ ] 协议三件套 CI 校验：全量内置物料通过；defaultProps 自洽校验通过
- [ ] 注册表：异步注册 Suspense 正常；重复注册先到先得；未注册渲染 UnknownWidget
- [ ] 分片加载：运行时按 collectComponents 精确加载（network 断言无未使用物料 chunk）
- [ ] 受控契约：所有 isFieldWidget 物料的受控行为 Storybook 快照测试
- [ ] 字段绑定：x-field-binding 属性在设计器只列 ACTIVE 字段
- [ ] **RichEditor XSS**：含 `<script>`/`onerror=`/`javascript:` 链接的 HTML 粘贴后，编辑器 JSON 模型与导出 HTML 均无危险节点（清洗前后断言）；渲染出口无 `dangerouslySetInnerHTML`（lint 规则单测）
