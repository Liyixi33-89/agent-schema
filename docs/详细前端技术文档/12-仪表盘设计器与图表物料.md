> 上游：《技术方案-前端(React).md》v0.2 §1（ECharts 选型）；详细 PRD 02 §2.6（仪表盘设计器 P2）
> 本文定位：**实现级技术设计**——ECharts 封装层、图表物料协议、24 列栅格画布、聚合数据源绑定、图表联动
> 包：`packages/component-materials` 图表子集 + 设计器仪表盘模式（复用 Canvas 引擎，文档 04FE）
> 数据契约：后端聚合接口 `POST /api/data/{modelId}/aggregate`（后端文档 02 §3.6/§A.4）、`useModelAggregate` hook（文档 07FE §3）

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| ECharts 按需引入封装（ChartKit）与 React 受控封装 | 聚合 SQL 执行（后端 data-engine） |
| 图表物料协议（LineChart/BarChart/PieChart/NumberCard/TableCard） | 布局引擎（复用页面设计器栅格，文档 04FE §2） |
| 三种数据源绑定（模型聚合/模型列表/静态 JSON） | 数据口径（后端权限注入后的聚合结果即最终值） |
| 图表联动（点击扇区 → 跳转带筛选参数） | 自由 BI（自定义 SQL/跨模型 join——PRD 02 §2.6 红线） |
| 仪表盘渲染性能（视口内实例激活、resize 归并） | 图表导出图片（P3 不做） |

## 2. ECharts 封装层（ChartKit）

```
设计原则：物料组件不直接 import echarts；全部经 ChartKit 收口。

ChartKit 能力：
  ① 按需引入：只打包用到的图表类型 + 组件
     （LineChart/BarChart/PieChart → echarts/charts；tooltip/grid/legend → echarts/components）
     —— bundle 断言：component-materials 中 echarts 全量引入为零
  ② 受控生命周期：props.option 变化走 setOption(notMerge=false) 增量更新；
     组件卸载 dispose；严格模式双挂载不泄漏（React 18 StrictMode 兼容）
  ③ resize 归并：容器 ResizeObserver → rAF 合帧 → chart.resize()
     （24 列栅格拖拽宽度变化时每帧只 resize 一次）
  ④ 主题注入：option 合并顺序 = 基础主题 → 图表物料默认 option → 用户 props.option
     （主题色板来自主题引擎 CSS 变量，文档 13FE §3——品牌定制不改图表物料代码）
  ⑤ 事件桥：onClick/onEvents 透传 ECharts 事件 → 联动协议（§5）
```

## 3. 图表物料协议

五个图表物料均遵循 MaterialMeta（文档 05FE §2），`category: 'chart'`：

```ts
interface ChartMaterialMeta extends MaterialMeta {
  category: 'chart';
  acceptsDataSource: ('aggregate' | 'modelList' | 'staticJson')[];  // 该图表可用数据源
  defaultOption: EChartsOption;       // ChartKit 合并基座
  dimensionMapper: (dsResult: DsResult, props) => EChartsOption;  // 数据源结果 → option 的映射器
}
```

| 物料 | componentName | 数据源 | dimensionMapper 要点 |
|---|---|---|---|
| 折线图 | `chart.line` | aggregate(时间分桶) / modelList | rows → xAxis: dimension, series: values |
| 柱状图 | `chart.bar` | aggregate(分组) / modelList | 同上 |
| 饼图 | `chart.pie` | aggregate(分组单度量) | rows → {name: dimension, value} |
| 数值卡 | `chart.number-card` | aggregate(无分组单度量) | 单值 + 同比环比（P3） |
| 表格卡 | `chart.table-card` | modelList(前100) / staticJson | 复用 Table 物料列配置（文档 05FE §5） |

- 图表物料的 propsSchema 扩展 `x-data-source` 配置控件（设计器生成数据源绑定面板，§4）；
- `acceptsDataSource` 决定数据源类型切换时保留兼容绑定（如聚合切列表时清空 measures）。

## 4. 三种数据源绑定

```
① 模型聚合（主路径）：
   绑定面板配置：modelId → measures[{fieldKey, func}] → group/timeBucket → topN
   → 存入 props.dataSource = { type:'aggregate', modelId, agg: AggregateRequest }
   → 运行时：useModelAggregate(modelId, agg)（文档 07FE §3，staleTime 60s）
   → 响应 rows 经 dimensionMapper 转 EChartsOption

② 模型列表（前 100 条）：
   { type:'modelList', modelId, filter, fields, sort } → useModelList(size:100)
   → 设计态提示「仅取前 100 条，不做全量统计」（防口径误解）

③ 静态 JSON：
   { type:'staticJson', data: [...] } → 属性面板 Monaco JSON 编辑器（设计态 zod 校验）
   → 用于演示模板/占位

数据源失效处理：
   modelId 被删/字段 DELETED → dimensionMapper 抛 DataSourceInvalidError
   → 图表区渲染「数据源失效」占位卡（不白屏，错误分级 L-Node，文档 02FE §8）
   设计器内：绑定面板字段下拉只列 ACTIVE 字段（R2 规则），存量失效绑定标黄
```

**设计态实时预览**：属性面板数据源配置变化 → 设计器画布内图表用「采样数据」即时预览（前 20 行聚合或 mock）；点「应用真实数据」按钮才发真实聚合请求（防高频配置抖动打爆聚合接口——后端聚合有 3s 熔断，文档 02 §3.6）。

## 5. 图表联动（点击扇区 → 跳转列表带筛选）

```ts
// 联动协议：图表物料 props.chartLink
{
  type: 'navigate',                        // P2 仅 navigate；P3 预留 filterPeer（联动同级卡片）
  target: { pageId },                      // 目标列表页（本应用内）
  filterMapping: [{ dimensionField, targetFilterField }]  // 点击维度值 → 目标页筛选参数
}
```

- 执行链：ChartKit 事件桥捕获点击（维度值 x）→ `chartLink` 解析 → `navigate(`/${appPath}${targetPage.path}?filter.${targetFilterField}=${x}`)`；
- 目标页接收：列表页数据源读取 URL query 的 `filter.` 前缀参数合并进 ConditionTree（运行时容器路由参数约定，文档 06FE §2）；
- **约束**：目标页必须是本应用页面（权限校验走路由守卫）；跨应用跳转不支持（权限边界）。

## 6. 24 列栅格与仪表盘画布

- 仪表盘页面类型（`PageSchema.type: 'dashboard'`）复用页面设计器 Canvas 引擎（文档 04FE §2），差异仅在：
  - 布局约束：顶层只允许 GridContainer（24 列）+ ChartCard 容器两层嵌套（PRD 02 §2.6，比表单页约束更紧）；
  - 物料面板：只显示 `category: 'chart'` 与 Card 容器；
  - 无表单/动作语义：ActionDispatcher 不挂载（仪表盘只读）；
- 拖拽落点计算、撤销栈、大纲树全部复用既有 Canvas 命令系统——**零新引擎代码，只加配置**。

## 7. 渲染性能

| 场景 | 预算 | 手段 |
|---|---|---|
| 10 卡片仪表盘首屏 | < 2s | 图表物料按需分片（echarts chunk 独立于基础物料）；聚合请求并行（React Query 自动并发） |
| 视口外图表 | 不渲染 | IntersectionObserver 惰性实例化（滚到才建 ECharts 实例） |
| 栅格拖拽 | 不掉帧 | resize rAF 归并（§2 ③）；拖拽中图表显示骨架截图 |
| 定时刷新 | 服务端友好 | staleTime 60s + 不做轮询（数据新鲜度让用户手动刷新或进页触发） |

## 8. 单元测试硬性要求

- [ ] ChartKit：option 增量更新不整图重绘（setOption notMerge=false 断言）；卸载 dispose 无实例泄漏
- [ ] bundle 断言：echarts 按需引入（无全量 import）；图表 chunk 与基础物料 chunk 分离
- [ ] dimensionMapper：三种数据源 → 五种图表的映射快照测试（固定输入断言 option 结构）
- [ ] 数据源失效：DELETED 字段/已删模型 → 占位卡而非报错白屏
- [ ] 联动：点击扇区生成正确目标 URL 与 filter 参数；目标页合并 URL 筛选进 ConditionTree
- [ ] 性能基准（CI 门禁）：10 卡片仪表盘首屏渲染断言；视口外实例零创建断言
- [ ] 画布复用：仪表盘模式撤销/拖拽/大纲树行为与表单页一致（同一命令系统回归）

## 附录 · 对接接口清单（消费方视角）

| # | 接口 | 用途 | 来源（后端文档） |
|---|---|---|---|
| 1 | `POST /api/data/{modelId}/aggregate` | 聚合数据源（measures/group/timeBucket/topN）；`useModelAggregate` 直连 | 02 §A.4 |
| 2 | `GET /api/data/{modelId}`（size=100） | 列表数据源（前 100 条提示口径） | 02 §A.1 |
| 3 | `GET /api/runtime/pages/{pageId}` | 仪表盘 Schema 加载（type=dashboard） | 04 §A.4 |
| 4 | 字段元数据摘要 | 绑定面板 ACTIVE 字段下拉 | 04 §A.4（随 Schema 下发） |

**对接约束**：

- 聚合参数协议与后端 `AggregateRequest` 一一对应（measures 上限 5、topN 上限 50、桶数 >1000 返回 400 引导缩小范围——后端 02 §3.6 护栏同步透传给设计器提示）；
- `X-Suggest-Index` 响应头 → 属性面板显示「建议将该字段设为索引字段」运营提示（后端聚合性能引导闭环）；
- 权限：聚合结果已按行级权限过滤（后端 02 §3.6 第 2 步），前端不做二次过滤——「看不到明细但统计含沙数」由后端杜绝。
