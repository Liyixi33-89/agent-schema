# 详细前端技术文档 06 · 运行时容器（apps/runtime）

> 上游：《技术方案-前端(React).md》v0.2 §3.7；详细 PRD 06（运行时与发布）；后端文档 04 §1.4（ETag 协议）
> 本文定位：**实现级技术设计**——动态路由、Schema 拉取与 ETag 缓存、鉴权守卫、租户上下文、嵌入能力
> 应用：`apps/runtime`（低代码应用运行时容器，产物与设计器完全隔离）

---

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| 应用路由表 → React Router 动态路由生成 | Schema 渲染本体（schema-renderer） |
| PageSchema 拉取/ETag 缓存/失效刷新 | Schema 存储（page-service） |
| 路由守卫（菜单可见性 + 按钮权限） | 权限判定服务端逻辑（auth-sdk 只做前端缓存与拦截展示） |
| 租户上下文注入（subdomain/path → 请求头） | 租户解析服务端逻辑 |
| 嵌入形态（iframe / Web Component） | Module Federation 物料热加载（P3） |

## 2. 启动与路由管线

```
① 运行时配置：GET /config.json（API base / 埋点 endpoint / CDN 覆盖）→ 注入 AppConfig
   （零硬编码地址——私有化红线，技术方案 §7）
② 鉴权初始化：auth-sdk 恢复登录态（token 刷新）→ 拉取当前用户 { userId, roles, perms, tenantId }
③ 租户上下文：subdomain 优先（{tenant}.saas.example.com），回退 path 前缀（/t/{tenant}/）
   → request-sdk 拦截器统一注入 X-Tenant-Id 头
④ 应用清单：GET /api/runtime/apps/current → { pages: [{pageId, path, name, perm}] , menus }
⑤ 路由生成：
   pages.map(p => <Route path={p.path} element={<PageLoader pageId={p.pageId} />} />)
   未在菜单的页面同样生成路由（直链可访问，受页面权限控制——详细 PRD 02 §2.8）
```

## 3. PageLoader：Schema 拉取与缓存

```
三层缓存（目标：二次进入页面 < 100ms 可交互）：

① 内存 LRU（Map<pageId, {schema, etag, fetchedAt}>，容量 20 页）
② HTTP 缓存：GET /api/runtime/pages/{pageId} + If-None-Match → 304 复用
③ 失效：应用级发布广播（WebSocket 'app:released'）→ 清内存缓存 → 已打开页面提示
   「应用已更新」+ 刷新按钮（不打断用户输入——发布不发版的体验闭环）

加载流程：
  memory hit 且未失效 → 直接渲染（同步路径，无骨架屏）
  miss → Suspense 骨架屏 → fetch → zod validate + migrate（协议层）→ 渲染
  SchemaError → 占位页 + 上报（§02 §8 错误分级）
```

## 4. 鉴权守卫

```
路由级（页面可见性）：路由表元素包裹 <PageGuard perm="page:view:{pageId}">
  无权限 → 403 占位（不打回登录，保持导航可见性配置一致）

按钮级（动作放行）：ActionDispatcher 执行前校验 action.perm ∈ user.perms
  无权限按钮：默认隐藏（菜单权限控制可见性，按钮权限控制放行——双层一致）
  权限快照：auth-sdk 缓存 perms，登出/切换应用时失效

数据级：前端不做行级/字段级隔离展示（服务端 response 已按字段权限过滤——后端 §5）；
  前端只处理「响应里没有的字段不渲染」的容错（列缺失降级）。
```

## 5. 多应用与嵌入

- **多应用**：同一租户多个应用各自路由空间；应用切换 = 重拉清单 + 重建路由（保持登录态）；
- **iframe 嵌入**：postMessage 协议（`{ type: 'schema.runtime.ready' | 'schema.resize' | 'schema.nav' }`）；高度自适应上报；外链 token 传递走一次性 code 换取（禁止 URL 传 token）；
- **Web Component（P2）**：`<schema-page app="x" page="y">` 自定义元素，Shadow DOM 隔离样式；认证依赖宿主注入的 token provider 回调；
- **CSP**：`script-src 'self'`；轨道 B 产物域名加入 `script-src` 白名单（artifacts CDN 域名单独列出）。

## 6. 长连接管理

```
统一 connection-manager（WebSocket）：
  用途：应用发布广播、流程状态推送（待办/审批结果）、协同通知
  策略：指数退避重连（1s→2s→...→60s 封顶）+ 心跳 30s + 页面可见性暂停
  恢复后：seq 比对补拉缺失事件（发布失效必须可靠触达）
降级：WS 不可用回退轮询（发布检查 5min 一次），功能不缺失仅时效降低
```

## 7. 私有化部署预留（现在就守，技术方案 §7）

- [ ] 全部后端地址来自 `/config.json`（API/WS/埋点/产物 CDN 四类）；
- [ ] 产物相对 publicPath（任意子路径可部署）；
- [ ] 无外部字体/图标/分析脚本依赖（自托管打包）；
- [ ] 租户标识运行时获取（subdomain/path），不进 bundle。

## 8. 单元测试硬性要求

- [ ] 路由生成：应用清单 → 路由表映射正确；未发布页面 404 占位
- [ ] ETag：304 路径不重新渲染组件（渲染次数断言）；发布广播后缓存失效
- [ ] 守卫：无页面权限 403；无按钮权限动作被拦截（ActionDispatcher 层）
- [ ] 租户头：所有请求带 X-Tenant-Id（request 拦截器单测）
- [ ] WS 断连重连：指数退避序列断言；恢复后补拉事件
- [ ] 配置外置：无 config.json 时清晰报错（不回退硬编码默认地址）

## 附录 · 对接接口清单（消费方视角）

> 本模块是运行时全部接口的宿主；路径与参数详见对应后端文档附录 A。

| # | 接口 | 用途 | 来源（后端文档） |
|---|---|---|---|
| 1 | `GET /config.json` | 启动①运行时配置（API base/WS/埋点 endpoint/产物 CDN）——静态文件非后端 API | 部署层 |
| 2 | `POST /api/auth/exchange`（嵌入 code 换 token）/ `refresh` | 嵌入宿主认证通道（URL 禁传 token） | 03 §A.1 |
| 3 | `GET /api/me` | 权限快照 `{userId, roles, perms[], dept, tenantId}`（守卫与 auth-sdk 共用） | 03 §A.2 |
| 4 | `GET /api/runtime/apps/current` | 启动④应用清单 → 路由表生成（§2） | 04 §A.4 |
| 5 | `GET /api/runtime/pages/{pageId}`（`If-None-Match`） | PageLoader 三层缓存核心（§3）；304 复用 / 200 更新 ETag | 04 §A.4 |
| 6 | `GET /api/me/menus?appId=` | 导航菜单（可见性即权限过滤结果） | 03 §A.2 |
| 7 | WS 事件流（§6 长连接） | `app:released`（缓存失效）/ `flow:task-created`（待办）/ `flow:instance-finished`（刷新）；断线 seq 补拉 | 10 §A.5 |
| 8 | 404 占位 | 未发布/已删除页面：运行时读取返回 404 → 路由级占位（清单有而 Schema 无即此态） | 04 §A.4 |

**对接约束**：

- 所有请求经 request-sdk 拦截器注入 `X-Tenant-Id`（租户上下文解析：subdomain 优先，回退 path 前缀——服务端三源校验为准，后端 10 §A.1）；
- 权限双层消费：路由守卫用 `page:view:{pageId}`（清单 perm 字段），按钮拦截用 `action:{key}`——同一 `perms` 快照（后端 03 §A.2）；
- iframe postMessage 协议（`ready/resize/nav`）与 code 换取时序见 §5 与后端 03 §A.1。
