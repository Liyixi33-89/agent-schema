> 包：`packages/schema-renderer` 内 `script-host` 模块 + 设计器侧测试台（apps/designer）

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| L2 脚本的运行时执行（钩子调度/超时/兜底） | 脚本编译（设计器保存时提交 build-service，后端文档 04） |
| 受控 ctx 的构造与冻结 | API 鉴权（ctx.api.call 走网关，服务端拦） |
| 执行日志采集与上报（logger 通道） | 脚本编辑器 UI（Monaco，测试台内嵌） |
| 测试台：mock ctx 执行 + 结果展示 | 执行日志中心存储（后端日志服务） |

**铁律：脚本报错不能导致页面白屏；红线靠代码强制不靠文档。**

## 2. 钩子契约（PRD §7.2 全量）

```ts
type HookName = 'onLoad' | 'onFieldChange' | 'beforeSubmit'
              | 'afterSubmit' | 'onActionClick' | 'onBeforeDelete';

interface ScriptBinding {
  scriptId: string;
  hook: HookName;
  artifactHash: string;        // 编译产物 hash（同轨道 B 加载约定）
  sourceHash: string;          // 源码 hash（审计"哪版源码"）
}
```

- 脚本保存流程：Monaco 编辑 → 前端**实时静态扫描**（§3 第一道闸）→ 提交 build-service 编译（第二道闸）→ 产物 hash 回写 PageSchema.scripts；
- 编译失败：测试台展示错误详情，`artifactHash` 不更新（线上继续跑旧版——与轨道 B 同兜底策略）。

## 3. 红线强制（三道闸）

```
第一道：编辑期（Monaco linter 插件，实时标红）
第二道：保存提交前（前端 AST 扫描，与后端扫描器同规则文件 redlines.json）
第三道：运行期（不注入全局 + 超时硬中断）

redlines.json（唯一真源，前端 linter / 后端 build-service 共用，CI diff 校验）：
  禁标识符：window, document, localStorage, sessionStorage, fetch, XMLHttpRequest,
           navigator, globalThis, process, require, eval, Function, importScript
  禁语法：动态 import()、with、赋值全局
  禁依赖：白名单外的 npm import（仅平台 SDK + 白名单库）
```

## 4. ScriptHost 执行器

```ts
interface ScriptHost {
  mount(page: PageInstance, user: UserInfo): void;
  run(hook: HookName, payload?: unknown): Promise<HookResult>;
  dispose(): void;      // 页面卸载：中断进行中执行、清日志缓冲、解绑订阅
}

run(hook, payload):
  const script = bindings.get(hook); if (!script) return { ok: true, skipped: true };
  const mod = await loadArtifact(script.artifactHash);    # import() + 缓存（hash 键）
  const ctx = createCtx(page, user);                      # 每钩子每页面独立实例
  try {
    return await withTimeout(
      mod[hook](payload, ctx),
      { warnMs: 500, hardMs: 10_000 }                     # 500ms 告警日志；10s AbortSignal 硬中断
    );
  } catch (e) {
    logger.error({ hook, err: e, scriptVersion: script.sourceHash });  # 结构化上报
    return { ok: false };                                 # 不上抛——页面继续
  }
```

- 钩子调度点：渲染管线挂载完成 → `onLoad`；formStore.set → 节流 50ms 的 `onFieldChange(fieldKey, value)`；ActionDispatcher 提交前/后 → `beforeSubmit`/`afterSubmit`；按钮动作 → `onActionClick(actionKey)`；删除确认前 → `onBeforeDelete(record)`；
- `beforeSubmit` 返回 `false` → 阻断提交（ActionDispatcher 停止后续动作链）；
- 页面卸载后完成的异步回调：`disposed` 标志丢弃（防 setState on unmounted）。

## 5. 受控 ctx（冻结 + 白名单）

```ts
function createCtx(page: PageInstance, user: UserInfo): ScriptContext {
  return Object.freeze({
    form: { get, set, getValues, setValues },   # set 走 formStore → 触发联动重渲染（§03 §6）
    api: { call: (name, params) => platformApi.invoke(name, params) },
                                                 # 仅平台注册名；后端网关鉴权 + 继承用户权限
    ui: { toast, confirm, dialog },
    logger: scopedLogger(page.id),              # 自动带 pageId/traceId/scriptVersion
    user: pick(user, ['id', 'roles', 'dept']),  # 脱敏白名单（无手机号邮箱）
    page: { params: page.params, query: page.query, mode: page.mode },
  });
}
```

- 运行期无 `window`/`document` 注入：脚本模块在独立 module scope 执行，全局对象不可达（静态扫描兜底）；
- `ctx.api.call` 不接受 URL，仅注册名 → 外部调用全部经网关（保鉴权/审计/限流/密钥托管）；
- 不提供定时器：防 `setTimeout` 递归死循环；确需延迟用平台受管 `schedule`（P2 评估）。

## 6. 脚本测试台（上线前置条件）

```
右侧抽屉：Monaco 编辑器（TS + 平台 SDK d.ts 提示 + 实时红线 linter）
          + mock ctx 面板（可编辑 form 样例值 / user / params / mock api 响应）
          + 运行按钮 → 执行选中钩子（真实 ScriptHost + mock ctx）

结果区：console 输出（logger 拦截）/ 返回值 JSON / 耗时 / 报错堆栈（行号映射回源码 sourcemap）
保真承诺：测试台与线上的差异仅 ctx 数据源（mock vs 真实）——执行器与扫描器是同一实例
```

## 7. 执行日志面板

- 按 hook 分组，最近 N 次真实执行（默认 50）：耗时/异常/`logger` 输出轮转；
- 客户自助排障入口（应用工作台 → 页面 → 脚本日志）；日志直传后端日志中心（`scopedLogger` 通道）；
- 渗透率指标：含脚本的页面占比（北极星过程指标，应随平台成熟下降——详细 PRD 10 §6）纳入埋点（§10 文档 usage-tracker）。

## 8. 单元测试硬性要求

- [ ] 红线三道闸：含 `fetch`/`document`/动态 `import()`/白名单外依赖的脚本在编辑期与保存期均被拒
- [ ] 超时：500ms 告警日志落账；10s 硬中断后页面正常
- [ ] 抛错不白屏：钩子异常后页面其余功能完好且日志可查
- [ ] `beforeSubmit` 返回 false 阻断动作链；`onFieldChange` 50ms 节流合并
- [ ] ctx 冻结：尝试改写 ctx 属性静默失败；`user` 字段集恰为白名单
- [ ] dispose：卸载后异步回调丢弃；产物缓存随页面释放
- [ ] 测试台保真：同一脚本在测试台与真实页面执行结果一致（集成用例）

## 附录 · 对接接口清单（消费方视角）

> 本模块是 `ctx.api.call(name, params)` 的路由消费方——脚本只能调注册名，注册名 → 实际接口的映射在此固化。

| # | 接口 | 用途 | 来源（后端文档） |
|---|---|---|---|
| 1 | `POST /api/build/pages/{pageId}/code` | 脚本保存即编译（§2：三道闸第二道在后端；红线规则与 redlines.json 同源）；成功回写 `{artifactHash}` 到 PageSchema.scripts | 04 §A.5 |
| 2 | `import(artifactUrl)` | 钩子产物加载（ScriptHost.loadArtifact，hash 键缓存） | 04 §A.5 |
| 3 | `POST /api/data/{modelId}` 系列 | `ctx.api.call` 注册映射：平台注册 API 即模型 CRUD + 已注册自定义 API（**继承当前用户权限**，服务端鉴权兜底——前端隔离不可信） | 02 §A.1 |
| 4 | `POST /api/flows/{defId}/instances` | `ctx.api.call('triggerFlow', ...)` 注册映射 | 05 §A.2 |
| 5 | `POST /api/data/{modelId}/unique-check` | 脚本内常用注册 API：唯一性预检 | 02 §A.3 |
| 6 | 脚本日志通道 | `ctx.logger` 结构化上报（自动带 pageId/traceId/scriptVersion）直传日志中心——与埋点通道分离，不带 HMAC 计费语义 | 10 §A.5（可观测） |

**对接约束**：

- 测试台 mock 的仅是 ctx 数据源（form/user/params/api 响应），ScriptHost 与红线扫描器为同一实例（保真承诺 §6）；
- 注册名表（`platformApi.registry`）必须与后端网关注册 API 清单一致（后端 06 §2）；新增注册名走双端契约变更流程（skill：schema-contract-first）；
- 编译失败 `SECURITY_BLOCKED` 时测试台展示规则标识（redlines.json 条目名），`artifactHash` 不更新——线上旧版兜底。
