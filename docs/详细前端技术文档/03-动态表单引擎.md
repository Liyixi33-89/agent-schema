# 详细前端技术文档 03 · 动态表单引擎（schema-form）

> 上游：《技术方案-前端(React).md》v0.3 §3.3；PRD §3.2、详细 PRD 02 §2.3/§2.2.3（联动规则）
> 本文定位：**实现级技术设计**——FieldSchema→Controller 映射、声明式联动、统一校验管线、跨步骤状态
> 包：`packages/schema-form`（基于 react-hook-form 封装）

---

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| FieldSchema[] → 表单组件树（Controller 映射） | 表单 Schema 的存储/保存（设计器状态归 designer store） |
| 声明式联动（显隐/禁用/必填/选项过滤/值联动）的依赖编排 | 表达式求值本体（协议层 ExprEngine） |
| 校验管线：内置规则 + 正则 + 异步校验（唯一性） | 提交后的业务动作（ActionDispatcher 消费提交结果） |
| 分步/分组表单跨步骤状态 | 列表筛选区（同为表单但走独立的 FilterForm 轻量模式） |

## 2. FieldSchema → Controller 映射

```
formSchema: { fields: FieldSchema[], groups?: GroupConfig[], steps?: StepConfig[] }

渲染：每个 ACTIVE 字段 →
  <Controller
    name={field.key}
    control={formControl}
    rules={buildRules(field)}          // §4 校验管线
    render={({ field, fieldState }) => {
      const Widget = materialRegistry.getWidget(field);   // 按字段类型默认 widget + 覆盖
      return <Widget {...field} label={field.label} required={effect.required}
                    disabled={effect.disabled} error={fieldState.error?.message} />;
    }}
  />

widget 推断默认表（可被 LayoutNode.props 覆盖）：
  text→Input / enum→Select / date→DatePicker / boolean→Switch
  / relation→UserPicker|DeptPicker（按 targetModel 类型）/ richtext→RichEditor
  / file→Upload / computed→只读展示
```

## 3. 声明式联动（reaction 编排）

配置来源：详细 PRD 02 §2.2.3 的四种联动，全部声明式存储在 Schema 中：

| 联动 | Schema 字段 | 引擎行为 |
|---|---|---|
| 显隐 | `visibleWhen: ExpressionBinding` | 求值 false → 卸载字段（不注册校验） |
| 禁用 | `disabledWhen` | 求值 false → 字段 disabled，值保留 |
| 必填 | `requiredWhen` | 动态增删 required 规则 |
| 选项过滤 | `optionsFilter: ExpressionBinding` | 求值结果作为 Select/UserPicker 的过滤参数 |

**依赖编排算法**：

```
buildReactions(fields):
  graph = {}                                  # fieldKey → Set<被依赖字段>
  for f in fields:
    for e in [visibleWhen, disabledWhen, requiredWhen, optionsFilter]:
      if e: for dep in e.dependsOn: graph[dep].add(f.key)
  return graph

运行时：字段 A 变化 → formStore.set(A)
  → effects 按 graph[A] 逐个触发（微任务批处理，一帧内合并）
  → 各 effect 重新求值表达式 → 更新对应字段 effect 状态（走字段级订阅，§02）
```

- 循环依赖：构建期检测 `graph` 成环 → 设计态报错阻断保存（运行态忽略环上多余边并告警）；
- 值联动（`单价×数量=金额`）：优先引导用**计算字段**（模型层 computed，READ_TIME）而非表单钩子——表单侧只做展示订阅；确需表单内即时联动时用 L2 `onFieldChange`（详细 PRD 02 §2.2.3）。

## 4. 校验管线（统一 resolver）

```
buildRules(field) → RHF 规则集：
  ① required（静态 required 或 requiredWhen 求值结果）
  ② 类型规则：number → valueAsNumber + NaN 拦截；date → 格式；enum → options 值域
  ③ validators 逐条编译：
     range → min/max；regex → pattern；expression → 自定义验证函数（ExprEngine 求值 false 即错误）
  ④ uniqueFlag → 异步校验（debounce 500ms 调后端唯一性接口，仅失焦触发）
     竞态防护：last-call-wins，旧请求结果丢弃（响应比对 requestId）

校验时机：失焦校验单字段 + 提交时全量校验（详细 PRD 02 §2.3）
错误展示：字段下方文案；错误定位滚动到第一个错误字段
```

## 5. 分步/分组表单

- Wizard 容器：每步独立校验（`trigger(fieldsOfStep)` 通过才允许下一步）；跨步骤状态由 formStore 全程持有；
- 分步暂存模式：`SAVE_DRAFT` 动作仅序列化当前 values（草稿不跑唯一性校验，提交态才跑）；
- Group 容器：折叠不影响校验注册（折叠仅 UI 状态，不卸载字段——与 visibleWhen 卸载语义区分）。

## 6. 与渲染引擎的集成契约

- formStore 即 §02 RenderScope 的表单原子：`ctx.form.get/set/getValues/setValues` 的底层实现（L2 脚本写入走 `formStore.set` 自动触发联动与重渲染）；
- 字段组件必须是**受控组件**（value/onChange 契约），禁止内部自持状态；
- DELETED 字段在表单树构建阶段即被过滤（§02 §6 的表单侧执行点）。

## 7. 单元测试硬性要求

- [ ] 四种联动：依赖字段变化后目标字段 effect 正确变化；无整页重渲染（渲染次数断言）
- [ ] visibleWhen=false 字段卸载后其值不参与提交、不参与校验
- [ ] 异步唯一性校验竞态：快速连续输入仅最后一次请求生效
- [ ] 分步表单：步骤校验阻断下一步；暂存草稿跳过唯一性校验
- [ ] DELETED 字段过滤后表单 values 不含该字段
- [ ] L2 写入（ctx.form.set）触发联动重算（与文档 08 的集成用例）
