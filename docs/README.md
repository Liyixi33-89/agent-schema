## 详细技术文档统一结构

1. **职责边界**——负责/不负责表格
2. **表结构 / 核心模型**——DDL 与状态机
3. **接口契约 / 核心算法**——伪代码级流程
4. **关键工程决策**——一致性分级、幂等键、安全管线
5. **单元测试硬性要求**——上线前 checklist

## 详细 PRD 统一结构

1. **模块概述**——是什么、服务角色、入口与信息架构
2. **页面与操作明细**——每个界面元素的操作触发、系统行为、配置项规则
3. **业务规则汇总**——编号规则表，可追溯来源决策
4. **权限点**——本模块涉及的权限点清单
5. **验收标准**——可测试的验收条件
6. **边界与不做的事**——明确本期不做内容，防范围蔓延

## 术语表

| 术语 | 定义 |
|---|---|
| 模型（Model） | 用户定义的业务数据结构，对应一张物理表 |
| Schema | 模型/页面/流程的定义 JSON，平台的"单一事实来源" |
| 物料（Material） | 遵循 `MaterialMeta` 协议的可配置组件，走动态渲染轨道 |
| L1-L4 | 逃生舱四级：表达式 / 前端钩子 / 受管后端函数 / 外部服务连接器 |
| 席位（Builder Seat） | 有设计器操作权限的账号；三口径严格区分——**授权**（持设计能力授权的账号数，配额硬限）/ **活跃**（滚动 30 天有写操作者，明细展示）/ **账单**（出账口径，P3 冻结定义）——真源见详细 PRD 04 §2.1 |
| 提升列 | JSONB 字段被标记为索引字段后生成的物理 STORED 列 |
| 轨道 A/B | 双轨渲染：动态解析 / 编译产物加载 |
| L-Pilot / L-GA / L-Enterprise | 三级上线等级：受控试点 / 正式商用 / 行业交付（门禁 G1-G9，真源见详细 PRD 11 §3） |
