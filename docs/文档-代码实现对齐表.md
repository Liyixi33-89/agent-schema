## 3. 选型漂移（文档描述 vs 实际实现）

| 文档描述 | 代码现状 | 裁决 |
|---|---|---|
| react-hook-form / valtio 具体选型 | 自研 FormStore（RenderScope 字段级订阅）+ 命令系统 | **合理替代**：字段级订阅已满足性能红线（02FE §4），测试覆盖充分。修正文档：架构总纲与 03FE 的选型表述改为「自研 FormStore（字段级订阅内核）」，删除 react-hook-form/valtio 引用 |
| request-sdk 四层统一请求 | 各应用独立装配（auth-sdk 共享认证通道） | 功能等价、边界清晰；SDK 化收口为 Phase 2 重构项（见 §1） |
| React Router 动态路由 | runtime 自研 hash 解析（route.ts） | **合理替代**：单容器 hash 路由零依赖、测试可注入；designer/admin-console 为 SPA 无路由库需求。修正文档：06FE §2 路由表述改述为「自研 hash 路由（runtime）」 |
| immer 结构共享，禁止 JSON 深拷贝 | page-designer store.ts 用 JSON 快照（注释声称「专项规格允许」） | **规则冲突裁决（本表最重要项）**：架构总纲 §5 反模式「用 JSON.parse/stringify 做深拷贝」针对的是**通用业务状态**（Date/undefined 语义丢失风险）；设计器撤销栈快照对象是**协议 PageSchema**（纯 JSON 值域，无 Date/undefined/function），序列化安全无损。裁决：**设计器快照属协议纯值域，JSON 快照为批准的实现策略**；总纲反模式条目补注「例外：协议纯值域快照（设计器撤销栈）——见对齐表 §3」。两个真源以此表为准归一 |
| Monaco 编辑器 | 未接入，源码登记 P2 评估 | 与源码注释一致，无冲突；脚本编辑用 TextArea + 校验反馈为 P1 降级实现 |
| Playwright/RTL 测试方案 | Vitest 单测 + CDP 真实浏览器验收 | **合理替代**：CDP 链路已验证真实交互（M12-M15 验收全靠它）；RTL 未引入（宿主包零 jsdom 红线）。修正文档：11FE §5 测试栈表述改述为「Vitest 单测 + CDP 浏览器验收（Playwright 评估随 Phase 2）」 |
