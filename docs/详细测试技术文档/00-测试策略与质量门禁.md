# 详细测试技术文档 00 · 测试策略与质量门禁

> 版本：v1.0 | 日期：2026-10-28 | 定位：全平台测试体系的**操作级真源**——测试分层、职责边界、环境矩阵、阶段门禁、阻断规则、验证报告与 SKIP 管理
> 输入来源：PRD §5.1 三级上线门禁、详细 PRD 11 §3（G1-G7）、`.agent` 三级验证管线（quick/commit/ci）、前端 11FE（测试金字塔）、后端 10BE §7（CI 硬性项）
> 关系声明：本篇不重复各服务域的「单元测试硬性要求」（那些在各篇 §7/§8 已列），本篇回答的是——**这些测试在哪个层级跑、由谁维护、挂到哪个门禁、失败了阻断什么**

## 1. 为什么需要独立的测试文档体系

详细 PRD 与技术文档各篇已含验收标准与测试硬性要求，但存在四个缺口：

1. **分散**：协议校验测试在 01FE §7、租户隔离测试在 03BE §7、L2 隔离在 08FE §8——没有一个视图回答「上线前到底要跑多少测试、哪些没跑」；
2. **层级未定**：哪些测试进 `quick`（秒级）、哪些进 `commit`（分钟级）、哪些只在 CI 与试点前执行，从未统一裁决；
3. **SKIP 失控**：当前 `verify[quick]` 的 frontend-tsc/backend-compile/contract-diff 三项均为 SKIP——SKIP 的退出条件与截止里程碑需要显式管理，否则会沦为永久豁免；
4. **验收证据缺追溯**：G1-G7 要求「验收报告 + 证据物编号」，但目前没有任何机制把「测试用例 → 需求编号 → 证据物」串起来。

## 2. 测试分层模型（测试金字塔 + 平台特有层）

| 层级 | 工具链 | 运行时机 | 目标耗时 | 职责边界 |
|---|---|---|---|---|
| **L-Unit 单元** | 前端 Vitest / 后端 JUnit5 | quick / commit | < 60s（quick 子集）/ < 5min（全量） | 纯函数与类级：协议校验、表达式求值、迁移管线、权限判定链、SQL 生成器——**禁 IO、禁网络、禁真实数据库** |
| **L-Contract 契约** | Vitest + JUnit 双端执行器、zod-diff、openapi diff | commit / ci | < 10min | 双端共享物一致性：expr-test-vectors.json、functions.json、JSON Schema 结构 diff、枚举值集合专项比对、错误码表比对 |
| **L-Integration 集成** | Testcontainers（PostgreSQL 真实实例）+ Spring Boot 切片 | ci | 10-30min | 服务域内部：DDL 生成、JSONB 读写、行级权限 SQL、Flyway 迁移、乐观锁并发——**用真实 PG，不用 H2** |
| **L-E2E 端到端** | Playwright（真实浏览器）+ 真实后端栈 | ci（冒烟）/ 试点前（全量） | 冒烟 < 15min / 全量 1-2h | MVP 业务闭环（02 篇）、Worker 隔离（真实浏览器断言）、发布回滚 |
| **L-Perf 性能** | k6/Gatling | 试点前（G5）+ 大版本回归 | 每次 30-60min | 250/500 并发压测、单模型 100 万行容量回归 |
| **L-DR 恢复演练** | 人工 + 脚本辅助 | 试点前（G3）+ 每季度 | 每次 2-4h | 备份恢复、故障注入、告警触达——**不可全自动化，但流程与证据必须脚本化记录** |

**分层铁律**：
- 用例只下放不上收——能在 Unit 层断言的（表达式语义、权限判定）不允许写成集成测试拖慢全量反馈；
- 集成层只用真实 PostgreSQL（Testcontainers），**禁止 H2**——JSONB 与提升列行为差异本身就是被测对象；
- E2E 只覆盖「跨模块不可降级」的链路（发布→运行→回滚、Worker 隔离、租户隔离贯穿），模块内部回归靠下层测试。

## 3. 三级验证管线与测试分层的映射

现有 `.agent` 管线（quick/commit/ci）是**提交触发机制**，本节定义它跑什么：

| 管线档 | 触发 | 包含测试层 | 硬阻断范围 |
|---|---|---|---|
| `quick` | AI 每次编辑后 / 保存时 | doc-anti-corruption + Unit 子集（受影响文件的差异测试） | 文档防腐规则、协议文件格式、编译期语法 |
| `commit` | 每次 git commit | Unit 全量 + Contract 全量 + lint | 编译、类型、契约 diff、单测回归 |
| `ci` | push / PR（GitHub Actions，Linux） | commit 全量 + Integration 全量 + E2E 冒烟 | Testcontainers 集成测试、跨端契约、冒烟链路 |
| **试点前手动** | M15/M16 完成后 | E2E 全量 + Perf + DR 演练 + 攻防用例 | G1-G7 门禁逐项出证据 |

**管线与门禁的关系**：管线管「代码合入质量」，门禁管「版本对外发布」。ci 全绿是 G1 的**必要非充分条件**——G1 还需要 demo 演示与验收报告。

## 4. 环境矩阵与数据策略

| 环境 | 用途 | 数据 | 网络 | 生命周期 |
|---|---|---|---|---|
| **本地开发** | Unit + 快速集成 | 本地 PG / Testcontainers | 内网 | 随会话 |
| **CI 环境** | Integration + E2E 冒烟 | 每次运行容器化新建，跑完销毁 | 隔离（无外网出口，模拟 CSP 生效前提） | 单次 job |
| **预发布（staging）** | E2E 全量 + Perf 基线 | 脱敏数据集 + 预置容量数据集（100 万行） | 与生产同构配置 | 常驻 |
| **恢复演练环境** | DR 演练（G3） | 从真实备份恢复 | 隔离（演练后销毁） | 单次演练 |
| **试点生产** | 真实租户 | 真实数据 + 备份 | 生产 | L-Pilot 期 |

**测试数据三原则**：
1. **固定种子公司（seed corpora）**：跨模块共享的测试 Schema 样本（含全部 12 种字段类型、递归布局、表达式绑定、动作绑定）作为版本化资产放 `contract/fixtures/`——契约测试、E2E、性能压测共用同一份种子，避免「各层测的数据不一样导致结论不可比」；
2. **不变量优先**：数据恢复、权限隔离、席位判定等关键测试必须断言**精确不变量**（如「恢复后行数一致 + 抽样 1000 行逐字段比对」），禁止只断言「接口 200」或笼统通过率；
3. **数据工厂不复原生产**：E2E/Perf 用数据工厂生成，**禁止从生产复制数据到非生产环境**（合规红线，PRD 11 §2.3）。

## 5. 阶段门禁与阻断规则（测试视角）

依赖图 M0-M16 的每道里程碑门，从测试角度定义「过门条件」：

| 门 | 时点 | 测试过门条件 | 阻断对象 |
|---|---|---|---|
| **协议冻结门（M1.6）** | 协议评审 | 01 篇契约测试全绿：expr-test-vectors 双端执行零差异、JSON Schema 结构 diff 为空、枚举值集合比对通过（评审稿 §7.3 遗留项在此闭环） | 不过则 M2/M4/M6 不开工 |
| **元数据门（M2 末）** | 元数据服务完成 | DDL 生成集成测试（Testcontainers）全过：12 种字段类型建表/改配置/索引提升/软删全路径 | 不过则 M5 不开工 |
| **渲染门（M6 末）** | 渲染引擎完成 | 种子公司渲染快照测试全过 + Playwright 冒烟（种子页面可渲染可交互） | 不过则 M12/M13 不开工 |
| **闭环门（M15）** | demo 完成 | 02 篇业务链路 E2E 全量 + 攻防六类用例全过 | 不过则 M16 不启动 |
| **试点门（M16）** | 上线评审 | 03 篇性能/可靠性验收全过，G1-G7 证据物齐备归档 | 不过则不接入试点租户 |

**阻断规则**：
- 任何门禁失败，**修复优先于绕过**——SKIP 需登记（见 §7），临时注释测试代码视为违规（10BE §7.1）；
- 安全类测试（越权、隔离、凭证）失败**无条件阻断**，不允许以「功能先上、安全后补」降级；
- 回归测试发现既有功能破坏时，提交人负责修复或显式回滚，不允许「先合入再修」。

## 6. Mock 边界（哪些允许 Mock、哪些禁止）

| 对象 | Mock 政策 | 理由 |
|---|---|---|
| 数据库 | ❌ 集成层禁止（用 Testcontainers 真 PG）；Unit 层不涉及 | JSONB/提升列/行级权限行为差异是核心被测对象 |
| HTTP 网关（下游服务间调用） | ✅ 服务域内单测可 Mock；跨服务集成测试用 WireMock 声明式桩 | 契约先行：桩即契约的消费方测试 |
| 鉴权/租户上下文 | ⚠️ Unit 层用构建器构造 TenantContext；**集成/E2E 层必须走真实登录流程** | 伪造租户头/越权是被测行为本身，Mock 掉等于没测 |
| Worker / 浏览器环境 | ❌ L2 隔离测试**必须真实浏览器**（08FE §3 红线：jsdom 模拟不了 Worker CSP 与 terminate 语义） | 环境隔离断言依赖真实浏览器能力面 |
| 对象存储 / 消息队列 | ✅ 集成测试用 MinIO/嵌入式 Kafka（Testcontainers 同族） | 接口行为与生产等价，成本可控 |
| 第三方外部系统（邮件等） | ✅ P1 无邮件通道已定版；P2 恢复邮件通道用捕获式桩（greenmail） | 不依赖外部网络 |
| 时钟 | ✅ 全平台测试注入固定时钟（表达式 NOW() 向量已定版注入时钟） | 日期时区语义锁死 |

## 7. SKIP 管理与豁免登记

SKIP 不是豁免，是**有截止日的缓期执行**。登记表（本表即真源，verify-log.jsonl 记录执行事实）：

| SKIP 项 | 当前状态 | 退出条件 | 截止里程碑 | 未退出的后果 |
|---|---|---|---|---|
| frontend-tsc | SKIP（schema-frontend 未初始化） | 前端 Monorepo 骨架建立且 tsconfig 就绪 | M0.2 | M1 协议开发无法开工 |
| backend-compile | SKIP（schema-platform 未初始化） | 后端 Monorepo 骨架建立 | M0.1 | M1.4 DTO 镜像无法开工 |
| contract-diff | SKIP（contract/ 未导出） | zod-to-json-schema 首次导出 + 后端校验规则文件落库 | M1.5 | **协议冻结门（M1.6）不得通过** |
| expr-test-vectors 双端执行 | 待建 | 前端 Vitest 执行器 + 后端 JUnit 执行器就绪 | M1.5 | 同上——这是 M1.5 的组成件 |
| E2E 冒烟 | 待建 | Playwright 项目 + 种子公司首个页面 | M6 末（渲染门） | 渲染门不得通过 |
| 攻防六类用例 | 待建 | L2 Worker + 预览凭证 + 网关落地 | M15（闭环门） | 闭环门不得通过 |
| 250 并发压测 | 待建 | 预发布环境 + k6 脚本 + 预置数据集 | M16（试点门，G5 证据） | 试点门不得通过 |
| 备份恢复演练 | 待建 | 备份策略落地 + 演练脚本 | M16（试点门，G3 证据） | 试点门不得通过 |

**豁免审批规则**：截止日到期仍未退出的 SKIP，需项目负责人书面决策「延期 + 新截止日」或「降低验收范围」，记录归档——不允许静默续期。

## 8. 验证报告与证据物追溯

### 8.1 用例追溯格式（全平台统一）

每条测试用例（无论写在哪篇文档或哪个测试文件）必须携带：

```
需求编号 → 契约/设计出处 → 前置数据 → 操作步骤 → 预期结果 → 自动化层级 → 所属门禁 → 验收证据
```

示例（摘自 02 篇）：

> REQ-06-发布回滚 | PRD 06 §3 回滚契约 + 04BE §A.6 page_release_version 表 | 种子公司应用「订单管理」+ 已发布 v1/v2 两版本 | 发布 v2 → 运行时验证 → 回滚到 v1 → 再访问运行时 | 运行时页面与 v1 完全一致（逐组件比对），page_release_version 两行记录都在且 status=rollback 的事件已审计 | L-E2E | 闭环门（M15）+ G1 | Playwright HTML 报告 + 录屏编号 EV-M15-ROLLBACK-01

### 8.2 证据物编号规则

```
EV-{里程碑}-{主题}-{序号}
例：EV-M16-DR-01（试点门备份恢复演练报告）
```

- 证据物归档在 `docs/evidence/`（按里程碑建目录），报告类为 PDF/MD，执行日志类为原始输出附件；
- G1-G7 验收报告中每个门禁项必须引用至少一个证据物编号——**无编号的「已通过」视为未通过**（PRD 11 §3 五方会签要求）。

### 8.3 verify-log 与验证通过率

- `.agent/metrics/verify-log.jsonl` 持续记录 quick/commit/ci 执行事实（已有机制，不变）；
- 新增**门禁执行报告**：每道里程碑门出一份 `gate-{门名}-report.md`（放 `docs/evidence/`），内容 = 该门全部用例的执行结果矩阵 + SKIP 状态 + 证据物编号列表。

## 11. 边界与不做的事

- 不建设独立测试管理平台（TestRail 等）——用例真源在测试代码与文档，追溯靠统一格式与编号规则；
- 不追求 MC/DC 全覆盖指标——以门禁通过 + 关键不变量断言为准，覆盖率作参考性度量（jacoco/vitest coverage 输出归档但不设硬阈值）；
- 不在 MVP 期做生产流量录制回放——留待 L-GA 后评估；
- 性能测试不模拟真实用户地理分布——单区域部署（PRD 11 §2.2），压测环境与生产同区域。
