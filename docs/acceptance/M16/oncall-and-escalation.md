# 试点期值班表与升级路径（G5 证据物）

> 定位：PRD 11 §3 G5 人工支持门禁——「值班表 + 升级路径文档；试点客户支持群建立；P0/P1 响应 SLA 内部承诺签署」。
> 单人项目声明：产品/研发/安全/运维/客户成功五方角色由 human-lead 统一承担（singleReviewerMode 已登记），
> 本文档为内部承诺签署的载体——human-lead 签发 gate-lpilot-report.md 即视为签署生效。

## 1. 值班表（试点期）

| 角色 | 承担人 | 值班时段 | 联系通道 | 响应承诺 |
|---|---|---|---|---|
| 一线支持（业务咨询/操作答疑） | human-lead | 工作日 09:00-19:00 | 试点客户支持群（IM） | 当日响应 |
| 后端/数据库应急处置 | human-lead | 7×24（P0 电话叫醒） | 电话 + IM | P0 ≤ 30min 响应 |
| 前端/渲染异常处置 | human-lead | 7×24（P0） | IM | P1 ≤ 2h 响应 |
| 安全事件（越权/注入告警） | human-lead | 7×24 | IM + 邮件 | 按事件级别走 P0/P1 |

**备份值班链**：无人替补（单人项目）——P0 事件若值班人不可达，按 §3 升级路径第 4 步执行（暂停试点流量保护数据），恢复后复盘补记。此为试点期已知限制，已写入 G6 试点协议的风险告知段。

## 2. P0/P1 响应 SLA 内部承诺

| 级别 | 定义 | 响应 | 修复目标 | 举证 |
|---|---|---|---|---|
| **P0** | 服务不可用（健康探针死/数据损坏/安全入侵） | ≤ 30min | ≤ 4h（RTO 目标同 PRD 11 §2.2） | 故障时间线 + 处置记录归档 |
| **P1** | 核心功能受损但服务可用（表单提交失败/列表不可查/告警通道断） | ≤ 2h | ≤ 24h | 同上 |
| **P2** | 非核心功能缺陷（样式错乱/非关键提示误导） | 当日 | 下一迭代窗口 | 缺陷登记 |

**响应承诺签署**：human-lead 签发本文件（随 gate-lpilot-report.md 上线批准一并生效）；试点协议（G6）中向客户披露的响应时效**不高于**本内部承诺（试点期 SLA 例外条款：不适用赔付）。

## 3. 升级路径（事件→处置→复盘）

```
① 告警触发（webhook 告警位：备份失败/探针死/健康页状态异常）
   └→ ② 值班人响应（P0 电话通道；当前自建 webhook 通道覆盖 IM 语义，
        第三方短信/电话凭据到位后升级接线——FT05 报告 §1 诚实边界）
        └→ ③ 处置（按已演练规程执行）：
             · 数据库故障 → DR 恢复规程（dr-drill-full.sh，含属主重赋；RTO 实测 0.1min）
             · 应用故障   → systemd 重启 / 发布回滚（schema-release.sh 版本目录切换）
             · 坏迁移阻断 → 勿强制启动（TC-UP-02 已验证阻断），回滚 jar + 恢复迁移前快照
             · 安全事件   → 收敛入口（nginx 层）→ 审计取证（SECURITY 审计表）→ 修补
             └→ ④ 若值班人 30min 未响应（无人替补）：
                  自动保护动作已预置——每日备份链路独立于应用（03:30 cron），
                  数据安全不依赖响应时效；恢复后补记事件复盘
        └→ ⑤ 复盘归档：事件时间线 + 根因 + 改进项入 docs/acceptance/（沿用演练报告格式）
```

## 4. 试点客户支持群

- 建立：试点开放时由 human-lead 创建（客户联系人拉群），群名约定「schema-platform 试点支持群」；
- 群内响应时效即 §2 承诺；群公告固定值班表（§1）与升级路径摘要（§3）；
- 单人项目限制如实告知：非 7×24 多人值班，P0 电话通道待第三方凭据接入（已声明为增强项非阻断）。
