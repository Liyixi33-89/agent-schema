## 2. 演练暴露的真实缺陷（已修复并沉淀操作规程）

**恢复属主错配（严重级）**：`pg_dump` 经 postgres 灌入后，表属主=postgres，应用账号（schema_accept）无权——恢复实例 Flyway 启动即 42501 permission denied。
**此前所有恢复演练均未暴露此问题**，因为旧版只做行数比对、从不启动应用实例。本轮恢复实例业务冒烟首次暴露。
**修复**：恢复操作规程补属主重赋步骤（ALTER DATABASE/SCHEMA OWNER + 批量表/序列 OWNER TO 应用账号）；脚本步骤 4 内置，后续每次演练自动执行。

**次要发现**：
- 验收后端（18081）文件落盘在 `/opt/schema/staging/data/files`（工作目录相对路径），与主服务 `/opt/schema/data/files` 是两棵树——备份脚本必须按服务实例区分文件树根。
- 登录会轮换 csrf cookie——演练脚本所有登录后请求须重取最新 csrf（双提交契约细节）。
