## 1. 职责边界（与文档 03 的分工线）

| tenant-service（本文） | permission-service（文档 03） |
|---|---|
| 租户生命周期：注册/配额档位/停服/注销 | 用户/角色/权限点 CRUD |
| 应用生命周期：创建/归档/恢复/删除审批 | 行级/字段级数据权限规则 |
| 应用成员（应用角色授予的入口）与席位判定 | 权限判定 RPC（被本服务调用） |

## 2. 租户生命周期与配额

### 2.1 租户模型

```sql
CREATE TABLE tenant (
  id           BIGSERIAL PRIMARY KEY,
  name         VARCHAR(128) NOT NULL,
  plan         VARCHAR(16) NOT NULL DEFAULT 'FREE',   -- FREE / PRO / ENTERPRISE（档位）
  status       VARCHAR(16) NOT NULL,                  -- ACTIVE / SUSPENDED(停服) / CLOSING(注销中) / CLOSED
  quota_profile JSONB NOT NULL,      -- 档位配额快照（应用数/席位数/存储/月流程执行量，见 §2.3）
  expire_at    TIMESTAMPTZ,          -- 订阅到期（FREE 为空）
  created_at   TIMESTAMPTZ NOT NULL
);
```

### 2.2 状态机

```
ACTIVE ⇄ SUSPENDED（停服：欠费/违规/管理员操作）
  停服行为：全租户登录拦截（除租户管理员）+ 运行时只读 + 设计器禁写 + 数据保留
  恢复：管理员操作即时生效（数据保留期内随时可恢复）

ACTIVE/CLOSING → CLOSING（注销：管理员发起 + 全员二次确认 + 延迟期 30 天）
  注销期行为：仅数据导出通道开放（应用导出包 + 业务数据导出任务）
  30 天后 → CLOSED：元数据标记 + 业务数据归档 + 文件前缀清理（文档 11 §5）+ 计量停止
  恢复窗口：CLOSING 期间可撤销回 ACTIVE（管理员操作）；CLOSED 不可恢复（审计留痕）

规则来源：PRD 04 §租户生命周期 + 详细 PRD 11 §2.3（数据生命周期真源）；停服/注销全部记审计（SENSITIVE_OP，文档 03 §6）

注销清理管线（P2 交付，详细 PRD 11 §2.3 落地；30 天延迟任务幂等）：
  ① 业务数据物理清除/匿名化（data-engine 动态表按模型批量 DELETE）
  ② 元数据置 CLOSED 标记（Schema 定义保留审计追溯，不物理删元表行）
  ③ 文件前缀清理（file-service tenant/{id}/ 前缀，文档 11 §5）
  ④ 计量停采（metering 取消订阅该租户事件）
  ⑤ 对象存储备份随保留期滚动自然覆盖——不追溯清除历史备份（写入服务条款，PRD 11 §2.3）
  ⑥ 注销证明文件生成（file-service scope=legal，租户管理员可下载）

恢复工单（P2，详细 PRD 11 §2.2 落地）：
  租户管理员发起（选恢复时间点/范围）→ 平台管理员审批 → 从备份重建到隔离验证环境
  → 客户确认后回灌 → 全程审计；接口见 §A.4
```

### 2.3 配额档位与扣减

| 项 | 归属 | 说明 |
|---|---|---|
| 应用数上限 | tenant-service 校验（创建应用时） | 软限：超限提示 + 宽限 7 天（09 §6 软限口径） |
| 席位数上限 | tenant-service 判定 + metering 计数 | 席位=「开发者或应用管理员」（设计能力授权口径，见 §2.4）；硬限：超限禁止新增设计能力角色 |
| 存储 / 月流程执行量 / AI 额度 | metering QuotaFilter 统一扣减（09 §6） | 本服务只存 quota_profile，不重复实现扣减 |

- **席位三口径判定实现**（口径定版 2026-10-28，规则定义见文档 03 §5 与 PRD 04 §2.1；本节是唯一实现点）：
  - **授权席位**：`COUNT(DISTINCT user) WHERE 任一应用角色 ∈ {应用管理员, 开发者}`——两角色均携带设计能力故均计；授权即计（无论是否操作），是**配额硬限**口径（超限禁止新增设计能力角色）。若未来引入纯管理角色（无设计能力）明确不计。每日快照 + 成员变更事件即时重算；
  - **活跃席位**：授权席位 ∩ 滚动 30 天服务端写操作埋点（09BE §4 终审；仅登录不算）——席位明细页展示、客户自助清理、CSM 跟进口径；
  - **账单席位**：出账口径（计费周期冻结、月中撤权折算等）——**P3 出账启动时另行冻结定义**（09BE §7），当前不实现不预支；
  - 三口径不得混用：配额扣减只看授权；计量报表只看活跃；账单未定义前禁止用活跃直接出账。
- 配额调整（升级档位）：写新 quota_profile 快照 + 通知 metering 刷新缓存（事件 `tenant.plan.changed`）。

## 3. 应用生命周期

### 3.1 应用模型

```sql
CREATE TABLE app (
  id           BIGSERIAL PRIMARY KEY,
  tenant_id    BIGINT NOT NULL,
  name         VARCHAR(64) NOT NULL,
  icon_file_id BIGINT,                    -- 头像/图标（file-service，文档 11）
  description  VARCHAR(512),
  theme        JSONB,                     -- {logo, primaryColor, loginBg}（主题定制消费）
  nav_tree     JSONB NOT NULL DEFAULT '[]',  -- 导航菜单树（§3.3）
  status       VARCHAR(16) NOT NULL,      -- ACTIVE / ARCHIVED（归档只读可恢复）/ DELETING(审批中)
  created_by   BIGINT, created_at TIMESTAMPTZ NOT NULL,
  UNIQUE (tenant_id, name)
);
```

- **创建**：创建者自动获得该应用「应用管理员」角色（写 sys_user_role，经 permission RPC）；
- **归档**：全部资源（模型/页面/流程）进入只读——设计器保存接口校验应用 status，运行时访问保留（PRD 07 R2）；
- **删除**：**P1 降级为「归档 + 手动确认」**（flow-service Phase 2 上线前无审批流可走：管理员二次确认 + 影响面清单，直接置 DELETING → 30 天后物理归档，全程审计）；**P2 起走审批流**（审批动作由 tenant-service 发起流程，flow-service 执行）+ 数据保留期说明；审批通过置 DELETING → 30 天后物理归档（与租户注销同节奏）；
- 强归属约束：模型/页面/流程表均已含 app_id 列（文档 01/04 元数据表），跨应用引用按 PRD 07 §2.7 只读授权。

### 3.2 应用成员

| 操作 | 接口语义 | 规则 |
|---|---|---|
| 添加成员 | 授予应用角色（应用管理员/开发者/使用者） | 成员必须先存在于租户组织（sys_user 同租户）；角色写入经 permission-service RPC |
| 移除成员 | 撤销该应用全部角色 | 最后一名应用管理员不可移除（防孤儿应用）；待办按配置转移（文档 03 §5） |
| 变更角色 | 覆盖式更新 | 开发者→使用者触发席位释放判定（**授权口径实时生效**：成员事件即时重算授权席位并同步 metering 缓存——§2.4；**报表展示口径次日快照体现**：usage_daily 快照按日聚合，两口径时点不同不矛盾） |
| 成员列表 | 按应用查询 | 含角色/加入时间；与席位判定共用查询逻辑 |

### 3.3 导航菜单树

```json
[ { "id": "m1", "type": "PAGE", "refId": 9001, "label": "报销申请", "perm": "page:view:9001" },
  { "id": "m2", "type": "GROUP", "label": "审批", "children": [ { "type": "PAGE", "refId": 9002, ... } ] },
  { "id": "m3", "type": "LINK", "url": "https://...", "label": "帮助文档" } ]
```

- 校验：PAGE 节点 refId 必须为本应用 ACTIVE 页面（保存时强校验）；拖拽排序纯前端 + 整树提交（乐观并发 version 比对，409 冲突协议同文档 04）；
- 运行时消费：导航壳按当前用户过滤渲染（菜单可见性 = 节点权限 ∩ 页面权限，PRD 07 §2.3）；接口 `GET /api/apps/{id}/nav` 返回**已过滤**的树（服务端过滤为准，前端不做权限二次判断）。

## 4. 模板中心与导出导入（P2）

### 4.1 模板安装

```
安装流程（PRD 07 §2.5）：
  选模板 → 起应用名 → 依赖完整性检查 → 可选示例数据 → 完成
    依赖检查：模板引用的物料是否在平台注册表（前端文档 05）；连接器定义是否可复用（租户级共享，PRD 07 R1）
    安装 = 一次性拷贝：批量复制模型 Schema（新 modelId）+ 页面 Schema（引用重写）+ 流程 Schema
    引用重写：页面/流程 Schema 中的 modelId/页面 id 全局替换为拷贝后的新 id（映射表留存）
    示例数据：显式勾选才导入（batch-upsert，文档 02 §3.4）
  失败回滚：安装为单事务（模块化单体内本地事务）或 Outbox 补偿（拆分后）；失败清理半成品应用
  升级不回写：模板版本记录与已装应用零关联（安装完成页告知，PRD 07 R3）
```

```sql
CREATE TABLE app_template (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL,  -- 官方模板租户为平台租户
  name VARCHAR(64), version VARCHAR(32), category VARCHAR(32),
  snapshot JSONB NOT NULL,        -- 完整快照：models[]/pages[]/flows[]/sampleData(标记是否含)
  is_official BOOLEAN DEFAULT FALSE, installed_count INT DEFAULT 0,
  UNIQUE (tenant_id, name, version)
);
```

### 4.2 应用导出/导入

- **导出**：`{manifest:{platformVersion, appMeta}, models[], pages[], flows[]}` → `.schema-app` JSON 包（file-service scope=template 存储）；**不含**：业务数据、连接器密钥、成员信息（PRD 07 R4）；
- **导入**：同租户复制应用；资源名冲突自动加后缀（`报销管理 (2)`）并返回新旧名映射表；跨租户迁移 P3；
- 校验：platformVersion 兼容矩阵（大版本不一致拒绝导入并提示）；Schema 结构校验复用前端协议层 zod schema 的服务端镜像（契约测试锁定）。

## 5. 发布记录归档

- 应用级发布 = 全部 draft 页面生成发布快照（执行在 page/build，文档 04 §1.3）；本服务维护**按应用的发布记录索引**：`(appId, releaseId, version, operator, changedPages[], releasedAt)`；
- 回滚入口在本服务（选择历史版本），执行转发 page-service（04 §回滚流程）；权限点「应用管理」覆盖发布与回滚（PRD 07 §4）。

## 6. 对平台运营（admin-console）的支撑

| 能力 | 说明 |
|---|---|
| 租户清单/检索/停服恢复 | 平台管理端专用接口（@TenantIgnore 白名单，文档 03 §2.2 纪律），每次操作记审计 |
| 档位与配额调整 | 写 quota_profile 快照 + `tenant.plan.changed` 事件 |
| 模板上架管理 | 官方模板的创建/更新/下架（installed_count 统计） |
| 席位报表 | 席位判定查询 + metering seat.active 日汇总联查（只读，不出账） |

## 7. 单元测试硬性要求

- [ ] 租户状态机：停服后非管理员登录被拦截、设计器写操作被拒；注销 30 天清理任务幂等
- [ ] 注销清理管线（P2）：六步清理按序执行；任一步失败可从断点重跑（幂等）；注销证明文件生成
- [ ] 恢复工单（P2）：申请→审批→隔离环境重建→回灌全流程审计；未审批不可执行
- [ ] 席位三口径：**授权**——有角色无操作仍计（授权即计）、**授权口径角色变更实时生效**（撤销角色后立即释放席位，若该用户在其他应用仍持设计能力角色则**不释放**——席位判定看全租户跨应用聚合而非单应用）、应用管理员计授权（设计能力口径）、每日快照留存；**活跃**——仅登录不计、滚动 30 天窗口外的不计；**两口径独立可同值**；账单口径未冻结前出账接口不存在
- [ ] **授权并发控制**：新增设计能力角色时实时比对授权席位上限（SELECT FOR UPDATE 租户席位行 + 计数校验，同一租户并发授权不突破上限）；触限返回 403 `SEAT_LIMIT_EXCEEDED`
- [ ] 应用删除 P1 降级：无审批流时归档+手动确认路径生效且记审计；P2 审批流路径回归
- [ ] 导航校验：PAGE 节点引用他应用/已删除页面保存被拒；无权限用户拿到的 nav 树不含该节点
- [ ] 成员规则：最后一名应用管理员不可移除；添加租户外用户被拒
- [ ] 模板安装：引用重写后页面 Schema 无旧 modelId 残留（全量扫描断言）；失败回滚无半成品
- [ ] 导出导入：往返 Schema diff 为空（PRD 07 §5 验收）；导出包含密钥/成员字段断言失败
- [ ] 越权：伪造租户操作他租户应用/模板全部被拦截（文档 03 纪律）

### A.4.1 数据恢复与注销证明（P2，详细 PRD 11 §2.2/§2.3 落地）

**恢复工单（平台审批→隔离重建→客户确认回灌，全流程状态机）**：

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/tenant/recovery-requests` | `{scope:'TENANT'\|'APP', pointInTime, reason}` | `{requestId, status:'PENDING_APPROVAL'}`（租户管理员发起；pointInTime 须落在备份保留窗口内，越界 422 `RECOVERY_POINT_OUT_OF_WINDOW`） |
| GET | `/api/tenant/recovery-requests/{id}` | — | `{status:'PENDING_APPROVAL'\|'REJECTED'\|'REBUILDING'\|'AWAITING_CONFIRM'\|'CONFIRMED'\|'FAILED', verifyEnvUrl?, progress?, rejectReason?}`（客户侧轮询） |
| POST | `/api/tenant/recovery-requests/{id}/confirm` | `{}` | `{status:'CONFIRMED'}`（仅 AWAITING_CONFIRM 态可调；触发回灌） |
| POST | `/api/admin/recovery-requests/{id}/approve` | `{}` | `{status:'REBUILDING'}`（平台管理员审批；未审批不可执行——状态机强制） |
| POST | `/api/admin/recovery-requests/{id}/reject` | `{reason}` | `{status:'REJECTED'}` |

- 状态机：PENDING_APPROVAL →（平台审批）→ REBUILDING →（隔离环境就绪）→ AWAITING_CONFIRM →（客户确认）→ CONFIRMED（回灌执行中/完成）；审批拒绝/重建失败为终态；
- 安全约束：重建环境仅租户管理员可访问（独立随机 URL + 有效期 72h）；回灌前二次确认（覆盖生产数据的破坏性操作）；全程审计（SENSITIVE_OP）。

**租户注销（申请→延迟期→清理→证明）**：

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|

### A.6 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `APP_NAME_EXISTS` | 409 | 同租户应用重名 |
| `APP_ARCHIVED` | 409 | 归档应用的写操作（设计器保存拦截） |
| `APP_ADMIN_REQUIRED` | 409 | 移除最后一名应用管理员 |
| `TENANT_SUSPENDED` | 403 | 停服租户的非管理员登录/写操作 |
| `NAV_VERSION_CONFLICT` | 409 | 导航树乐观并发冲突 |
| `SEAT_LIMIT_EXCEEDED` | 403 | 新增设计能力角色超授权席位上限（§3.2 并发控制；附 `{licensedSeats, limit}` payload 走升级引导弹层） |
| `CLOSING_STATE_INVALID` | 409 | 非 CLOSING 期撤销注销（§2.2 状态机） |
| `RECOVERY_POINT_OUT_OF_WINDOW` | 422 | 恢复时间点越出备份保留窗口（§A.4.1） |

### 前端对接要点

- 工作台卡片墙消费 `GET /api/apps` 的 `myRole` 直接渲染角色徽标；创建流程三步向导（名称/图标/模板可选）；
- 应用设置四页签与本附录 A.1/A.2/A.3 一一对应（成员页消费 A.2，导航树编辑器整树提交带 version）；

- 停服拦截 `TENANT_SUSPENDED` 与配额 `QUOTA_EXCEEDED`（09）走同一升级引导弹层体系（前端文档 07FE §4）。
