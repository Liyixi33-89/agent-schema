# 详细技术文档 06 · 网关与开放平台（gateway-service / open-api-service）

> 上游：《技术方案-后端(Java).md》v0.2 §1/§5/§7；PRD §3.5
> 本文定位：实现级技术设计——网关过滤器链、API Key 体系、动态 OpenAPI、限流配额
> 服务：`gateway-service`（Spring Cloud Gateway）、`open-api-service`

---

## 1. gateway-service

### 1.1 过滤器链（顺序固定）

```
① TenantResolveFilter     子域/路径前缀/JWT claim → tenantId → header 透传
② AuthFilter              JWT 验签（内部路由）或 API Key 验签（/api/open/**）
③ PermissionFilter        页面/动作级功能权限预校验（粗粒度，细粒度在服务内）
④ RateLimitFilter         网关级限流（租户维度兜底，Key 级见 §2.3）
⑤ QuotaFilter             配额前置扣减（Redis Lua，§09 文档）
⑥ AuditLogFilter          登录事件/敏感路径访问记录
```

- 网关**无状态**：全部状态查 Redis（本地 Caffeine 短 TTL 缓存 JWT 验签结果）；
- 限流算法：滑动窗口（Redis ZSET）或令牌桶（Redis Lua），按 `tenantId` 与 `apiKey` 双维度。

### 1.2 错误协议统一

```json
{ "code": "QUOTA_EXCEEDED",           // 业务错误码独立命名空间
  "message": "本月流程执行次数已达上限",
  "data": { "upgradeUrl": "https://.../pricing" },
  "traceId": "..." }
```

错误码分层：参数错（400 类）/权限错（403 类）/配额超限（QUOTA_EXCEEDED + 升级链接）/资源不存在（404 归一化，不泄露租户外资源）。**配额错误与业务错误严格区分**——否则客户以为系统坏了。

## 2. open-api-service

### 2.1 自动 CRUD API（内部/外部同引擎）

```
GET    /api/open/v1/data/{modelKey}?filter=&sort=&page=&size=&fields=
GET    /api/open/v1/data/{modelKey}/{id}
POST   /api/open/v1/data/{modelKey}
PUT    /api/open/v1/data/{modelKey}/{id}
DELETE /api/open/v1/data/{modelKey}/{id}          # 逻辑删除
POST   /api/open/v1/data/{modelKey}/batch-upsert
POST   /api/open/v1/data/{modelKey}/query         # 复杂条件树
GET    /api/open/v1/data/{modelKey}/cursor?after=&size=   # P2 游标分页
```

执行统一转交 data-engine（§02）；**唯一差异是鉴权身份来源**——内部 JWT 用户 vs 外部 API Key 绑定身份，行为完全一致（同一套权限注入、字段过滤、审计）。

### 2.2 API Key 体系

```sql
CREATE TABLE open_api_key (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL,
  key_name VARCHAR(64), key_hash VARCHAR(128) NOT NULL,   -- 明文 sk_{tenant}_{random} 只展示一次
  scope JSONB NOT NULL,          -- [{modelKey, actions:['read','create']}]
  data_scope JSONB,              -- 可配数据范围（默认全部/仅本人创建等）
  bound_role_id BIGINT,          -- 字段权限按绑定角色执行
  ip_whitelist JSONB, expires_at TIMESTAMPTZ,
  status VARCHAR(16),            -- ACTIVE / REVOKED
  created_by BIGINT, created_at TIMESTAMPTZ
);

CREATE TABLE api_call_log (
  id BIGSERIAL, tenant_id BIGINT, api_key_id BIGINT,
  method VARCHAR(8), path VARCHAR(256), model_key VARCHAR(64),
  fields_used JSONB,             -- 按 fields 参数记录 → 影响面分析数据源（GIN 索引）
  status_code INT, duration_ms INT, result_count INT,
  occurred_at TIMESTAMPTZ NOT NULL
) PARTITION BY RANGE (occurred_at);   -- 按月分区
CREATE INDEX idx_apicall_fields ON api_call_log USING GIN(fields_used);
```

- 未授权模型（scope 不含）→ 403 且**不计配额不写调用日志的业务计数**；
- Key 吊销即时生效（Redis 黑名单 + 验签查缓存）。

### 2.3 配额与限流（Key 级）

```
默认：10 次/秒（令牌桶）、10000 次/日（滑动窗口）
超限：429 + Retry-After: N
实现：Redis Lua 原子扣减（KEYS[1]=quota:{tenant}:{key}:{metric}:{period}）
配额数据投递计量事件（护栏档位）
```

### 2.4 动态 OpenAPI 文档

- 标准 SpringDoc 注解是静态的——这里需要**运行时按元数据生成**：
  - 遍历租户 ACTIVE 模型 → 字段类型映射 JSON Schema（enum 列举值、required、示例值）；
  - 生成 `/api/open/v1/docs.json`（OpenAPI 3.1），带 Schema 版本 ETag，模型变更后失效；
- 调试台（Swagger UI）用测试 Key 调用，仅路由到测试租户数据（网关按 Key 的 tenant 标记强制）。

### 2.5 Webhook 出站（P2）

| 项 | 实现 |
|---|---|
| 订阅配置 | `webhook_subscription(event_type, model_key, target_url, headers_template, retry_policy)` |
| 事件源 | 消费 data-engine 领域事件 + flow 事件 → 匹配订阅 → 投递队列 |
| 投递 | At-least-once；载荷 `{eventId, eventType, before/after(脱敏), operator, ts}` |
| 签名 | HMAC-SHA256(ts + body)，头 `X-Schema-Signature`；时间戳窗口 5 分钟防重放 |
| 重试 | 5 次指数退避 1m/5m/30m/2h/6h → 死信 + 控制台告警 |
| SSRF | 目标 URL 复用 L4 连接器的出站校验管线（DNS 解析后 IP 校验 + 内网黑名单，见 §07 文档） |

## 3. 安全要点（本域 Checklist）

- [ ] 所有 `/api/open/**` 强制 Key 验签 + scope 校验 + IP 白名单三重
- [ ] filter 参数拒绝无白名单操作符（400）
- [ ] 深分页拒绝（page*size>10 万）引导 cursor
- [ ] 响应字段剔除不可见字段（data-engine 保证，网关抽查监控）
- [ ] 调用日志 fields_used 覆盖率监控（影响面分析依赖此数据）
- [ ] Key 明文零落库（只存 hash）；吊销黑名单延迟 < 1s

## 4. 单元测试硬性要求

- [ ] 过滤器链顺序与短路行为（验签失败不消耗配额）
- [ ] Key 越权：scope 外模型 403 且不扣配额
- [ ] 限流：并发突发下 429 正确返回且 Retry-After 递减
- [ ] OpenAPI 文档随模型变更刷新（ETag 变化）
- [ ] Webhook 签名：篡改 body/过期时间戳均拒绝
- [ ] SSRF：内网 IP/重绑定样本被出站校验拦截

## 附录 A · 对外接口契约

> 前端消费方：API 管理台（admin-console）、开放平台调试台、`ctx.api.call` 注册名路由（前端文档 08FE §5）。
> 说明：`/api/open/**` 为第三方系统调用（API Key 体系），前端仅需管理界面；内部用户请求经业务网关（Bearer + 租户头）。

### A.1 API Key 管理（管理台）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/open/keys` | `{name, scopes:[modelId...], expireAt?, ipWhitelist?}` | `{keyId, apiKey}`——**明文仅此一次返回**（零落库只存 hash），前端提示保存 |
| GET | `/api/open/keys` | — | `{list:[{keyId, name, scopes, status, lastUsedAt, calls30d}]}`（无明文） |
| PUT | `/api/open/keys/{keyId}/status` | `{status:'ENABLED'\|'DISABLED'}` | `{}`（DISABLED 即黑名单，生效 <1s） |
| DELETE | `/api/open/keys/{keyId}` | — | `{}`（吊销） |

### A.2 动态 OpenAPI 与调试台

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/open/v1/docs.json` | OpenAPI 3.1（运行时按元数据生成，带版本 ETag）；前端 `openapi-typescript` 以此生成 `api-types.gen.ts`（前端文档 01FE §6、07FE §2） |
| POST | `/api/open/v1/test-invoke` | 调试台代理调用：`{keyId(测试 Key), method, path, body}`——强制路由测试租户数据 |

### A.3 调用日志与配额（管理台）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/open/logs?keyId=&page=&size=` | `{list:[{traceId, method, path, status, durationMs, fieldsUsed[], occurredAt}]}`（fieldsUsed 供影响面分析展示） |
| GET | `/api/open/quota` | `{metrics:[{metric, used, limit, period}]}`（护栏档位展示） |

### A.4 第三方调用协议（`/api/open/v1/**`，非前端消费——供对客户交付说明）

| 项 | 约定 |
|---|---|
| 认证 | Header `X-Api-Key: {apiKey}`，验签失败 401 且**不消耗配额** |
| 数据操作 | `/api/open/v1/data/{modelKey}` 系列，filter 协议同文档 02 附录 A.2（操作符白名单一致） |
| 限流/配额 | 超限 `429 + Retry-After`；配额硬限返回 `QUOTA_EXCEEDED`（含升级引导 payload，前端统一弹层消费，前端文档 07FE §4） |
| 模型变更 | 模型变更后 docs.json ETag 失效；删除字段不立即破坏存量 Key（影响面分析以 `fields_used` 日志回溯，文档 01 §4.5） |

### A.5 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `API_KEY_INVALID` | 401 | 验签失败（不给线索区分不存在/已禁用） |
| `SCOPE_DENIED` | 403 | Key scope 外模型 |
| `RATE_LIMITED` | 429 | 限流（Retry-After 递减） |
| `QUOTA_EXCEEDED` | 429 | 配额硬限（升级引导 payload） |

### 前端对接要点

- Key 创建成功弹层必须强调「明文仅此一次」并附复制交互；后端不可二次找回（前端文档 06FE/管理台）；
- `docs.json` → 类型生成链路的 CI 契约校验见前端文档 01FE §6 与文档 11FE §5。
