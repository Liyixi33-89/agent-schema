# 详细技术文档 05 · 流程引擎集成（flow-service）

> 上游：《技术方案-后端(Java).md》v0.3 §6；PRD §3.3
> 本文定位：实现级技术设计——Transpiler、动态审批人、动作节点可靠性、实例绑定
> 服务：`flow-service`（封装 Flowable）；协作：notification-service、data-engine
> **分期声明（2026-10-28，对齐 PRD v0.3 §5）**：flow-service **整体 Phase 2 交付**——P1 无流程执行闭环（表单动作只触发数据写入与状态流转，不产生流程实例）。本文按 Phase 2 交付范围设计；P1 期间流程画布只读展示，Transpiler 校验可提前随 M2 元数据链路验证（保存时 dry-run 不执行）。

---

## 1. 架构原则

**不自研流程引擎。** 低代码流程 Schema（JSON）→ Transpiler 编译为 BPMN 2.0 XML → Flowable 执行。平台只做三件事：可视化编排层（前端）、业务数据桥接、可观测。

复用 BPMN 标准能力：UserTask 会签/或签、ExclusiveGateway/ParallelGateway、超时边界事件、历史查询。

## 2. 流程 Schema 与 Transpiler

### 2.1 FlowSchema → BPMN 映射

| 低代码节点 | BPMN 元素 | 转换要点 |
|---|---|---|
| 开始（触发器） | StartEvent + 事件监听/定时器 | 表单提交=消息启动；定时=Cron timer start |
| 审批节点 | UserTask | assignee 留空，TaskListener 运行时解析（§3）；会签=multiInstanceLoopCharacteristics |
| 条件分支 | ExclusiveGateway | 每条出线 conditionExpression = 编译后的表达式；**必须有 default 流线** |
| 并行分支 | ParallelGateway | 分/合网关配对校验 |
| 动作节点 | ServiceTask | 委派 `ActionTaskDelegate`（异步执行，§4） |
| 结束 | EndEvent | 可挂结束监听（通知发起人） |

### 2.2 编译期校验（保存阻断）

```
validate(flowSchema):
  1. 图完整性：所有节点可达、有终点、网关配对
  2. 表达式编译：L1 语法（Aviator 受限模式）→ 语法错给出节点定位
  3. 引用校验：审批人规则引用的 字段/角色 存在且 ACTIVE；
     表达式引用字段在绑定模型中（拉取 metadata 缓存）
  4. 转换 BPMN XML → Flowable RepositoryService 校验部署可行性（dry-run）
```

### 2.3 版本与在途实例

- 每次发布生成新 Flowable deployment（版本号递增）；
- **在途实例继续按发起时 deployment 执行**——不做实例级版本切换（明确为长期行为）；
- 停用流程：不可新发起，在途实例继续跑完。

## 3. 动态审批人（TaskListener）

```java
public class AssigneeListener implements TaskListener {
    public void notify(DelegateTask task) {
        AssigneeRule rule = readFromTaskVariable(task, "assigneeRule");
        List<Long> userIds = assigneeResolver.resolve(rule, buildExecContext(task));
        // 规则类型：FIXED_MEMBER / DEPT_LEADER(含fallback级数) / ROLE(去重/含子角色)
        //          / FIELD_VALUE(user类型字段,支持多值) / INITIATOR_PICK / PREV_NODE_HANDLER
        if (userIds.isEmpty()) {
            switch (rule.getEmptyStrategy()) {   // 兜底三选一
                case FORWARD_ADMIN -> task.setAssignee(adminUserId);
                case AUTO_PASS     -> task.complete();      // 记录自动通过原因
                case BLOCK         -> throw new BlockedNoAssigneeException(task); // 默认：挂起+告警
            }
        } else {
            task.addCandidateUsers(userIds);
        }
    }
}
```

- 解析上下文：发起人（userId/deptId）、流程变量（表单快照）、指定历史节点处理人（查 flow_task_log）；
- **实时解析**：组织架构调整后无需改流程定义；
- 解析失败/为空的告警走 notification-service（站内信 + 运营告警面板）。

## 4. 动作节点（ServiceTask 异步化）

### 4.1 执行模型

```
ServiceTask（流程内）→ 不直接执行 → 发 MQ 消息（topic: flow.action）
  → 动作执行器消费（独立线程池）→ 执行动作 → 回调 task.complete()/失败处理
```

### 4.2 动作类型实现

| 动作 | 执行器 | 要点 |
|---|---|---|
| 发通知 | notification-service RPC | 通道路由（站内/邮件/短信/IM 连接器）；模板变量 L1 表达式求值 |
| 写数据 | data-engine 内部 RPC | 透传发起人权限上下文（不绕过权限） |
| 调 API | data-engine / open-api | 参数映射（流程变量 → API 参数） |
| 调连接器 | connector-service | 继承连接器超时重试策略 |
| 更新流程变量 | 引擎内 | 表达式赋值 |

### 4.3 可靠性（幂等 + 重试 + 死信）

```
幂等键：executionId + nodeId + executionSeq（引擎执行序号）
消费端：幂等表 flow_action_exec(execution_id, node_id, seq) 唯一约束
重试：失败按动作策略（重试N次/立即中断）；重试间隔指数退避
最终失败：进入死信队列 → 流程实例标记 ACTION_FAILED
  → 详情页「动作失败待处理」→ 人工重放（重新投递同 seq 消息，幂等表防重）
计量：实例完成投递 flow.exec；触发条件不满足的前置过滤跳过不计（计费口径）
```

## 5. 流程与业务数据绑定

```sql
CREATE TABLE flow_instance_biz (
  id BIGSERIAL PRIMARY KEY,
  instance_id VARCHAR(64) NOT NULL,     -- Flowable processInstanceId
  tenant_id BIGINT, model_id BIGINT NOT NULL, record_id BIGINT NOT NULL,
  flow_def_id BIGINT, started_by BIGINT, started_at TIMESTAMPTZ,
  status VARCHAR(16),                   -- RUNNING / FINISHED / TERMINATED / SUSPENDED
  UNIQUE (instance_id)
);
CREATE UNIQUE INDEX uq_flow_active ON flow_instance_biz(model_id, record_id, flow_def_id)
  WHERE status IN ('RUNNING','SUSPENDED');   -- 同记录同流程默认拒绝并发发起
```

- 发起入口统一：`POST /api/flows/{defId}/instances {modelId, recordId}`——校验发起权限 + 并发约束；
- 业务记录逻辑删除 → 订阅 record.deleted 事件 → 进行中实例 SUSPENDED + 通知发起人；
- 详情页数据流：`flow_instance_biz` → Flowable HistoryService（节点轨迹）→ `flow_task_log`（操作/意见）→ 动作日志（脱敏摘要）。

## 6. 审批操作语义实现

| 操作 | Flowable API | 附加逻辑 |
|---|---|---|
| 同意 | taskService.complete(taskId, vars) | 意见必填校验；写 task_log |
| 驳回 | runtimeService.createChangeActivityStateBuilder() 回退 | 实例保持运行；P2 支持任意历史节点 |
| 转交 | taskService.setAssignee | 记录转交链 |
| 加签 | 运行时插入临时子任务/多实例 | 前/后加签语义映射 |
| 撤回 | 发起人在下一节点处理前：runtime 终止 + 重建至发起节点 | 可配窗口 |
| 催办 | notification RPC | Redis 限频 1 次/小时/任务 |

`flow_task_log(task_id, instance_id, node_id, action, operator_id, comment, operated_at)` 供 ApprovalTimeline 物料渲染。

## 7. 触发器（P2）

| 触发 | 实现 | 防抖/幂等 |
|---|---|---|
| record.created/updated/deleted | 消费 data-engine 领域事件 | 更新支持"仅当字段变化"；事件幂等键防重 |
| 定时 | Quartz 集群（DB 锁防多实例重复触发） | 跳过错过的触发（misfire 策略：DO_NOTHING） |
| 手动 | 表单按钮 TRIGGER_FLOW | 同并发约束 |
| 前置过滤 | 触发条件 L1 表达式不满足直接跳过 | 不投递实例、不计 flow.exec |

## 8. 单元测试硬性要求

- [ ] Transpiler：全部节点类型往返编译（Schema→BPMN→部署成功）；缺默认线/表达式错被阻断
- [ ] 审批人：六种规则解析正确；为空三策略行为正确（BLOCK 时实例挂起且告警产生）
- [ ] 幂等：同 executionId+nodeId+seq 重复投递只执行一次
- [ ] 死信：动作最终失败后实例标记 ACTION_FAILED 且可人工重放
- [ ] 并发约束：同记录重复发起第二个实例被唯一索引拒绝
- [ ] 业务删除联动：record.deleted 后实例 SUSPENDED
- [ ] 计量口径：前置过滤跳过的触发不产生 flow.exec 事件

## 附录 A · 对外接口契约

> 前端消费方：流程设计器保存/模拟（前端文档 10 §2）、ActionDispatcher 的 TRIGGER_FLOW（文档 02FE）、审批中心/ApprovalTimeline 物料（文档 05FE）、待办通知（文档 06FE 长连接）。

### A.1 流程定义（设计器）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/flows?appId=` | — | `{list:[{id, name, status, version, updatedAt}]}` |
| POST | `/api/flows` | `{appId, name, schema(FlowSchema)}` | `{id}` |
| PUT | `/api/flows/{id}/draft` | `{schema, baseVersion}` | `{version}` 或 `409 {serverVersion}` |
| POST | `/api/flows/{id}/publish` | — | `{version}`（发布前校验：连通性/网关配对/表达式编译全过） |
| POST | `/api/flows/{id}/simulate` | `{vars:{fieldKey:value}}` | `{path:[nodeId...], approvers:[{nodeId, resolvedUsers[]}], warnings[]}`（纯静态推演，不产生实例） |

### A.2 实例与任务（运行时 + 审批中心）

| 方法 | 路径 | 请求/说明 | 响应 |
|---|---|---|---|
| POST | `/api/flows/{defId}/instances` | `{modelId, recordId}`（§5 并发约束：同记录同流程 RUNNING 拒绝并发发起） | `{instanceId}` |
| GET | `/api/flows/instances?modelId=&recordId=` | 业务记录关联实例 | `{list:[{instanceId, flowDefId, status, startedAt}]}` |
| GET | `/api/flows/instances/{instanceId}` | 详情聚合 | `{status, nodes:[{nodeId, name, state, assignees[], operatedAt?}], taskLog[], actionLogs[]}`（ApprovalTimeline 数据源，§6 task_log） |
| GET | `/api/my/tasks?status=TODO\|DONE&page=&size=` | 我的待办/已办 | `{list:[{taskId, instanceId, flowName, bizTitle, nodeId, createdAt}], total, page, size}` |
| POST | `/api/tasks/{taskId}/complete` | `{approve:true\|false, comment}` | 同意/驳回合一（§6 语义映射）；意见必填校验 422 |
| POST | `/api/tasks/{taskId}/transfer` | `{targetUserId}` | 转交（记录转交链） |
| POST | `/api/tasks/{taskId}/urge` | — | 催办（Redis 限频 1 次/小时/任务，超限 429） |
| POST | `/api/flows/instances/{instanceId}/withdraw` | — | 撤回（下一节点处理前，可配窗口，超窗 422） |

### A.3 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `INSTANCE_ALREADY_RUNNING` | 409 | 同记录同流程唯一索引拒绝 |
| `COMMENT_REQUIRED` | 422 | 审批意见必填 |
| `URGE_RATE_LIMITED` | 429 | 催办限频 |
| `WITHDRAW_WINDOW_CLOSED` | 422 | 撤回窗口已关 |
| `ACTION_FAILED` | 500 | 动作节点死信（实例标记态，详情页人工重放入口） |

### 前端对接要点

- 模拟运行接口与前端图遍历推演共用同一 FlowSchema（前端文档 10 §2.3）；线上以 `/simulate` 为准；
- TRIGGER_FLOW 动作链：提交成功 → `POST instances` → 失败按 `INSTANCE_ALREADY_RUNNING` 提示（前端文档 02FE 中介者）；
- 待办/审批结果推送走 WS 长连接（前端文档 06FE §6），列表刷新用 React Query 失效。
