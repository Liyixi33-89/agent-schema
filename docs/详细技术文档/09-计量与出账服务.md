# 详细技术文档 09 · 计量与出账服务（metering-service）

> 上游：《技术方案-后端(Java).md》v0.2 §10；PRD §8（计费与计量体系）
> 本文定位：实现级技术设计——事件链路、幂等聚合、配额扣减、出账快照
> 服务：`metering-service`；采集端：前端 usage-tracker + 各服务埋点

---

## 1. 设计原则（不可违背）

| 原则 | 说明 |
|---|---|
| 明细与汇总分离 | 计费只读 `usage_daily`；明细只做对账追溯；汇总可从明细重算（灾备/纠错） |
| 幂等 | 客户端 eventId + 服务端去重表；聚合按 (tenant, metric, date) 全量覆盖写 |
| 服务端为准 | 前端埋点可伪造，**计费指标一律服务端埋点**；前端事件仅漏斗分析 |
| 合规红线 | payload 白名单只允许 ID/枚举/数值，**禁止任何业务字段值** |
| 一期不出账 | 但事件模型与聚合表一次设计对——计费历史无法回溯补录 |

## 2. 事件采集链路

```
前端 usage-tracker（批量：5s 或 20 条；visibilitychange 时 sendBeacon flush）
各服务服务端埋点（flow.exec / ai.tokens / api.calls / build.count / storage 定时）
        ↓
POST /api/metering/events（轻量签名 HMAC + eventId 幂等）
        ↓
Kafka topic: metering.raw（按 tenantId 分区，保证租户内顺序）
        ↓ metering-service 消费者
① 签名校验 + 去重（幂等表 eventId，TTL 7 天）
② 归一化 → 写明细 usage_event
③ 增量聚合 → usage_daily（覆盖写）
```

## 3. 表结构

```sql
CREATE TABLE usage_event (
  event_id    VARCHAR(64) PRIMARY KEY,     -- 幂等键（客户端 UUID）
  tenant_id   BIGINT NOT NULL,
  user_id     BIGINT,
  metric      VARCHAR(64) NOT NULL,        -- seat.active / flow.exec / ai.tokens.in / api.calls / storage.gb / build.count
  quantity    BIGINT NOT NULL DEFAULT 1,
  app_id      BIGINT,
  occurred_at TIMESTAMPTZ NOT NULL,        -- 客户端事件时间（跨天归属用）
  received_at TIMESTAMPTZ NOT NULL,
  attrs       JSONB,                       -- 白名单属性（ID/枚举/数值）
  signature   VARCHAR(128)
) PARTITION BY RANGE (received_at);        -- 按月分区；量大迁移 ClickHouse
CREATE INDEX idx_ue_agg ON usage_event(tenant_id, metric, occurred_at);

CREATE TABLE usage_daily (
  tenant_id BIGINT, metric VARCHAR(64), stat_date DATE,
  quantity  BIGINT,
  dims      JSONB,                          -- 可选维度：appId（席位不加维度）
  PRIMARY KEY (tenant_id, metric, stat_date)
);
```

## 4. 指标口径（与 PRD §8.4 一一对应）

| metric | 口径 | 采集点 | 归属日 |
|---|---|---|---|
| `seat.active` | 当日有**设计器写操作**的账号去重；仅登录不算；**滚动 30 天活跃 = 活跃席位口径**（席位三口径见 13BE §2.4——授权/活跃/账单，本文只采活跃；授权席位判定归 tenant-service 不产生计量事件） | 前端埋 + metadata/page 服务端写操作终审（保存/发布/脚本保存钩子） | 操作日 |
| `flow.exec` | 实例完成执行；前置过滤不满足不计；平台故障不计、客户逻辑失败计 | flow-service 服务端 | 完成日 |
| `ai.tokens.in/out` | AI 网关 token 消耗 | AI 网关服务端 | 调用日 |
| `api.calls` | 开放 API 调用**成功**数 | 网关服务端 | 调用日 |
| `storage.gb` | 对象存储日峰值 | 定时任务（每日 1 次） | 统计日 |
| `build.count` | 自定义代码编译执行次数（不含幂等复用） | build-service | 构建日 |
| `sla.availability` | 分钟级可用性采样（P0/P1 请求成功率，PRD 11 §2.1 统计口径） | 网关服务端 | 统计日（Pilot 起采集，内部看板不出账） |

**时间归属规则**：用 `occurred_at` 落日期，但限回溯 24h——超出按 `received_at`（防篡改归属月份躲避配额）。**迟到数据**：允许补算 T+3 天（出账在 T+3 后跑）。

## 5. 聚合任务

```
每日 T+1 03:00 跑前一日聚合（幂等可重跑）：
  INSERT INTO usage_daily (tenant_id, metric, stat_date, quantity)
  SELECT tenant_id, metric, occurred_at::date, SUM(quantity)
  FROM usage_event WHERE occurred_at >= :d AND occurred_at < :d+1
  GROUP BY tenant_id, metric, occurred_at::date
  ON CONFLICT (tenant_id, metric, stat_date) DO UPDATE SET quantity = EXCLUDED.quantity;
  -- 全量覆盖写 = 幂等重跑安全

seat.active 特殊处理：
  按 (tenant_id, user_id, date) 先去重再 count distinct user
  服务端终审口径：同一用户前端事件与服务端事件同时存在 → 只信服务端
  日汇总存 quantity=去重人数；滚动 30 天活跃从明细重算（不存月表，避免双写不一致）
  ⚠️ 口径边界：seat.active 只是「活跃席位」的原料；「授权席位」判定在 tenant-service
  （每日快照，不出计量事件）；「账单席位」P3 出账启动时冻结定义（PRD §8.4）——三者禁止混用
```

## 6. 配额与限流（护栏）

```lua
-- Redis Lua 原子扣减：KEYS[1]=quota:{tenant}:{metric}:{period}, ARGV=[增量, 上限]
-- 返回 1=成功并扣减, 0=超限
local current = redis.call('INCRBY', KEYS[1], ARGV[1])
if current == tonumber(ARGV[1]) then redis.call('EXPIRE', KEYS[1], 86400) end
if current > tonumber(ARGV[2]) then
  redis.call('DECRBY', KEYS[1], ARGV[1]) return 0
end
return 1
```

- 检查位置：网关/执行器**前置层**（QuotaFilter），业务代码禁止散落判断；
- 软限（应用数/存储）：超限提示 + 宽限 7 天；硬限（席位/流程执行/AI/API）：拒绝 + `QUOTA_EXCEEDED` + 升级链接；
- 日配额快照同步回写 usage_daily 维度表（对账：Redis 计数 vs DB 聚合每日校准）。

## 7. 出账（Phase 3）

> 启动前置：**账单席位口径冻结**（PRD §8.4 三口径之第三口径——计费周期、月中撤权折算、跨月入职比例；届时单独评审后写入本节，禁止直接沿用活跃口径出账）。

```
账单生成（每月 T+3 后）：
  读 usage_daily × 价格表 → 生成账单快照 → 写入【不可变账单表】
  出账后不再重算；纠错走「账单调整」单据流（关联原账单，正负调整项）

CREATE TABLE billing_invoice (
  id BIGSERIAL, tenant_id BIGINT, period CHAR(7),  -- '2026-10'
  subtotal NUMERIC, adjustments NUMERIC DEFAULT 0, total NUMERIC,
  line_items JSONB,      -- [{metric, quantity, unitPrice, amount}]
  status VARCHAR(16),    -- ISSUED / ADJUSTED
  created_at TIMESTAMPTZ,
  UNIQUE (tenant_id, period)
);

明细下钻：账单 → line_item.metric → usage_daily → usage_event
  （哪个用户/哪个应用/哪个流程产生的——计费争议的终结者）
预付额度包：购买记录 + 12 个月结转 + 不可退现（消耗顺序：预付优先于后付）
```

## 8. 防伪造与防薅

| 风险 | 对策 |
|---|---|
| 前端伪造 seat.active | 服务端终审口径；前端事件仅漏斗（§4） |
| 重放事件 | eventId 幂等表 + 签名时间窗口 |
| 跨月逃配额 | occurred_at 限回溯 24h |
| 刷 AI 额度/流程 | 环比突增 >300%/500% 告警 → 限流 + 人工审核队列（规则见详细 PRD 09） |
| 共享账号 | 多 IP/设备跳变检测 → 记录 + 管理员报表（不自动封禁） |

## 9. 单元测试硬性要求

- [ ] 幂等：同 eventId 重投递只计一次；聚合重跑结果不变
- [ ] 时间归属：伪造 25h 前 occurred_at 的事件按 received_at 落日
- [ ] seat 口径：仅登录事件不计；写操作计；前端+服务端重复只信服务端；**席位明细接口返回的是活跃口径且带「滚动 30 天」标注**（授权口径由 tenant-service 提供，本服务不出）
- [ ] flow.exec：前置过滤跳过的不产生事件；平台故障标记不计
- [ ] Lua 原子性：并发 100 扣减无超发
- [ ] 出账：账单金额 = usage_daily × 价格表；调整单不改历史快照；**账单席位口径冻结前出账接口不可用**（前置评审门）
- [ ] 合规：payload 含业务字段值的事件被拒绝（白名单校验）
- [ ] sla.availability：注入失败请求后月度报表可用性下降正确；排除项（维护窗口）不计入不可用分钟

## 附录 A · 对外接口契约

> 前端消费方：usage-tracker 独立上报通道（前端文档 09FE）、租户用量仪表盘（admin-console）、配额升级引导弹层（QUOTA_EXCEEDED 统一消费，前端文档 07FE §4）。

### A.1 事件上报（前端唯一写入入口）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/metering/events` | `{events:[{eventId(UUID), occurredAt, tenantId?, event(UsageEvent), signature(HMAC)}]}` 批量 ≤100 | `202 Accepted`（异步入 Kafka，不逐条回执）；合规校验失败整批 `422 {invalidIndices[]}` |

- **独立通道**：不经业务网关限流链路（计费准确性红线）；带 HMAC 轻签名 + 请求级配额；
- 幂等：`eventId` 客户端 UUID，服务端去重表 TTL 7 天——**重试必须复用原 eventId**（前端文档 09FE §3）；
- 合规：payload 白名单只允许 ID/枚举/数值，违规整批拒绝并返回违规下标。

### A.2 用量查询（仪表盘）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/metering/usage?metric=&from=&to=&dims=` | `{series:[{date, quantity}]}`（读 usage_daily，前端图表直连） |
| GET | `/api/metering/usage/summary` | `{metrics:[{metric, monthQty, activeSeats, quota, quotaStatus:'OK'\|'SOFT'\|'HARD'}]}`（租户首页卡片） |
| GET | `/api/metering/events/debug?limit=50` | 事件流水抽样（对账排障用，管理端权限） |

### A.3 配额与升级引导

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/metering/quota` | `{hardLimits:[{metric, limit, used}], softLimits:[...], graceDaysLeft?}` |
| 网关拦截响应 | （业务接口响应内） | `QUOTA_EXCEEDED` 附 `{upgradeUrl, metric, limit}` payload——前端统一弹层组件消费（前端文档 07FE §4） |

### A.4 账单（Phase 3，接口先行冻结）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/billing/invoices?year=&month=` | `{list:[{period, subtotal, adjustments, total, status, lineItems[]}]}` |
| GET | `/api/billing/invoices/{period}` | 单账单：lineItems → usage_daily → usage_event 三级下钻（计费争议终结者，§7） |
| POST | `/api/billing/adjustments` | `{period, items:[{metric, quantity, reason}]}` 调整单（关联原账单，正负调整，不改历史快照） |

### A.5 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `EVENT_PAYLOAD_INVALID` | 422 | 合规白名单校验失败（返回违规下标） |
| `SIGNATURE_INVALID` | 401 | HMAC 签名校验失败 |
| `QUOTA_EXCEEDED` | 429 | 硬限拦截（升级引导 payload，各业务接口透传） |

### 前端对接要点

- 上报管线（批量 5s/20 条、visibilitychange flush、sendBeacon 降级链）见前端文档 09FE §3；
- 仪表盘指标口径展示与 §4 指标表一致（席位 30 天活跃、flow.exec 完成口径等）——前端只展示不计算，避免双端口径漂移。
