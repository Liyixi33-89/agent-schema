## 1. 部署形态与演进路径

```
Phase 1（模块化单体）：
  Spring Boot Modulith——§2 的"服务"为 Maven 模块，单进程部署
  ├─ 优点：无分布式事务/服务发现开销，MVP 迭代快
  └─ 模块边界靠 ArchUnit 强制（模块间只走暴露的 api 包，禁止 internal 互访）

Phase 2 按瓶颈拆分（优先级）：
  ① data-engine（查询性能瓶颈） ② metadata（缓存失效广播敏感）
  ③ build-service（本来就是 Node 池） ④ flow（Flowable 独立资源）
  其余模块保持内嵌，直到流量证明需要拆

Phase 3：L3 沙箱独立 namespace（§08）；metering 可独立（消费型服务）
```

## 2. Schema 元数据缓存一致性

```
三级缓存：Caffeine(本地,30s) → Redis(1h) → PostgreSQL
读取带 version 比对：元数据版本单调递增，节点发现 version 过期自行刷新
                                                    —— 广播丢失兜底
失效广播：保存事务提交后 Redis pub/sub 'schema:invalidate' {modelId, version}
一致性分级：
  常规变更（增字段/改配置）：允许秒级脏读窗口
  字段删除：强一致——两阶段「广播失效 → 等节点 ACK（订阅计数）→ 提交元数据」
            ACK 超时放弃本次保存并告警（宁可不删，不可让已删字段短暂可见）
```

## 3. 异步任务框架（统一基建）

| 任务类型 | 载体 | 幂等 | 状态查询 |
|---|---|---|---|
| 提升列 DDL | MQ `ddl.promote` | 任务表唯一键 (model_id, field_key) | promote_status |
| 影响面全扫描 | MQ | 按变更集 dedup | 扫描报告表 |
| 批量导入/导出 | 任务表 + 线程池 | 任务 ID | 任务中心统一进度 |
| 数据体检 | 任务表 + 游标扫描 | 按模型+版本 | 体检报告表 |
| Webhook 投递 | MQ + 重试 | eventId | 死信告警面板 |
| 流程动作 | MQ `flow.action` | executionId+nodeId+seq | flow_action_exec |

统一规范：任务表含 `status(PENDING/RUNNING/SUCCESS/FAILED)、progress、retry_count、error`；管理端任务中心可见全部；失败任务一律**可人工重试**。

## 4. 可观测性

```
Metrics（Prometheus）：
  业务：api.calls、flow.exec、build.count 直方图（计量口径复用）
  技术：JVM/连接池/慢查询计数/DDL 队列深度/缓存命中率/沙箱执行耗时
  保障：sla.availability 分钟级采样（PRD 11 §2.1 统计口径，网关采集入 09BE §4）
        备份任务成功率/最近备份时间戳/恢复演练 RTO 实测值（Pilot 看板）
Tracing（SkyWalking）：网关→服务→data-engine→DB 全链路；跨到沙箱/连接器调用
Logging（ELK）：结构化 JSON；traceId 贯穿；敏感字段脱敏过滤器（写入前拦截）
告警分级：
  P0：服务不可用/数据不一致校验失败/出账异常/备份失败（备份连续失败=数据丢失风险，视同 P0）
  P1：慢查询熔断率、死信堆积、编译失败率、SSRF 拦截次数（安全事件）、恢复演练超 RTO
  P2：配额 80% 提醒（客户侧通知，非内部告警）
租户级健康页数据源：错误率/失败实例/编译失败——客户自助排障，减少工单
值班触达：P0/P1 告警 → IM webhook 值班通道（故障分级响应目标见 PRD 11 §2.1——
          这是产品承诺不是内部纪律，注入故障演练验证触达是 M16 门禁项）
```

## 5. 表达式引擎（L1，横切）

- 选型：后端 **Aviator 受限模式**（自定义函数白名单注册），前端 jsonata 类引擎——两端**共享同一函数白名单清单**（协议文件双端同步，CI diff 检查）；
- 约束：禁 eval/new Function；执行步数上限 1000（防死循环）；无 IO 无副作用；
- 静态分析：保存时提取 `dependsOn`（引用字段清单）→ 存 Schema（供影响面分析 + 前端字段级订阅）；
- 设计态即时校验协议：前端先行报红（行号+原因），后端保存终审——两端校验规则同源（JSON 规则文件驱动）。

## 6. 私有化预留约束（现在必须守，后补极贵）

- [ ] 外部依赖接口化：对象存储（S3 抽象）/MQ/缓存/短信/邮件/LLM 全部 interface + 配置化实现，业务代码禁止直调云 SDK
- [ ] CI 依赖扫描：业务模块出现 `com.aliyun.*` 等云 SDK 直接依赖 → 构建失败（收敛到 adapter 模块）
- [ ] 无硬编码：域名/密钥/bucket/region 走 Nacos/Apollo/env
- [ ] 多租户可退化：TenantContext 单租户模式恒返回默认值，业务代码零分支判断
- [ ] 核心元表 Flyway 管理（离线可升级）；用户动态业务表走元数据驱动 DDL 执行器（仅提升列）
- [ ] 服务无状态：不写本地磁盘（临时目录除外），随时可容器化
- [ ] 明确不做：License 校验/离线升级包/多形态安装器——触发条件「首个付费私有化客户」

## 7. 工程规范（CI 硬性项）

### 7.1 代码与测试

- 阿里巴巴 Java 开发手册 + Checkstyle/SpotBugs 门禁；
- 覆盖率红线：动态查询引擎、租户拦截器、表达式引擎、Transpiler >80%；
- **越权测试强制**：每个新增查询 Service 附「伪造租户上下文被拦截」用例，缺失不予合并。

### 7.2 契约同步

- `schema-protocol-java`（DTO 镜像）与前端 TS 协议同仓同步：CI 跑 OpenAPI diff + TS 类型生成比对；
- 表达式函数白名单、错误码表、计量指标字典均为**双端共享协议文件**，变更必须双端 PR 一起出。

### 7.3 安全 PR Checklist（评审硬性项）

- [ ] 新增 SQL 构建是否走元数据白名单（禁拼接）
- [ ] 新增查询是否带租户条件（拦截器覆盖验证）
- [ ] 新增日志是否过脱敏过滤器
- [ ] 新增外部调用是否走连接器（禁止裸 HttpClient）
- [ ] 新增接口是否校验功能权限 + 行级注入
- [ ] 新增计量事件是否服务端采集（前端仅漏斗）

## 附录 A · 横切接口契约（全局约定）

> 本域无业务接口；本附录固化**全部业务接口共同遵循的横切约定**——前后端各文档附录均引用此处，不再重复。

### A.1 请求通用约定

| 项 | 约定 |
|---|---|
| 租户头 | `X-Tenant-Id`（前端拦截器统一注入，前端文档 07FE §2；网关/Header/JWT claim 三源解析，服务端为准） |
| 链路头 | `X-Trace-Id` 请求级透传（前端生成或透传响应值） |
| 鉴权 | `Authorization: Bearer {accessToken}`；`/api/open/**` 例外走 `X-Api-Key` |
| 时间格式 | 全部 ISO-8601 带时区（`TIMESTAMPTZ` 序列化） |
| ID 类型 | 业务 ID 一律 string 传输（防 JS Number 精度丢失，Long 服务端内部） |

### A.2 响应通用约定

| 项 | 约定 |
|---|---|
| 成功 | 资源体直接返回（不包 `{code:0}` 信封）；分页统一 `{list, total, page, size}` |
| 错误 | `{code:'BIZ_XXX', message(用户可读), traceId, details?}`——前端 request-sdk 归一化为 `ApiError{httpStatus, bizCode, message, traceId, retryable}`（前端文档 07FE §4） |
| 409 冲突 | 统一携带服务端当前版本字段（`serverVersion` / `serverDraftVersion`），前端三方对比依赖此约定 |
| 字段权限 | 响应体物理剔除不可见/DELETED 字段（前端断言「键不存在」而非 null） |

### A.3 全局错误码分域登记表

| 前缀 | 域 | 文档 |
|---|---|---|
| `MODEL_*` / `FIELD_*` | 元数据 | 01 附录 A.5 |
| `FILTER_*` / `PAGE_*` / `RECORD_*` / `VALIDATION_*` | 数据引擎 | 02 附录 A.5 |
| `ACCOUNT_*` / `REFRESH_*` / `PERM_*` | 认证权限 | 03 附录 A.4 |
| `LOCK_*` / `DRAFT_*` / `PATH_*` / `BUILD_*` / `SECURITY_*` | 页面/编译 | 04 附录 A.6 |
| `INSTANCE_*` / `COMMENT_*` / `URGE_*` / `WITHDRAW_*` / `ACTION_*` | 流程 | 05 附录 A.3 |
| `API_KEY_*` / `SCOPE_*` / `RATE_*` / `QUOTA_*` | 网关开放 | 06 附录 A.5 |
| `DOMAIN_*` / `SSRF_*` / `REPLAY_*` / `CONNECTOR_*` / `MAPPING_*` | 集成 L4 | 07 附录 A.4 |
| `SCRIPT_*` / `CONCURRENCY_*` / `L3_*` | L3 沙箱 | 08 附录 A.4 |
| `EVENT_*` / `SIGNATURE_*` | 计量 | 09 附录 A.5 |

规则：新增错误码必须登记所属文档附录；跨域复用 `QUOTA_EXCEEDED` 保持 payload 结构一致（升级引导）。

### A.4 异步任务通用协议（导入/导出/DDL/体检共用）

### A.5 WebSocket 事件协议（长连接统一推送）

| 事件 | 载荷 | 前端消费 |
|---|---|---|
| `app:released` | `{appId, releaseVersion}` | 运行时缓存失效提示（前端文档 06FE §3） |
| `flow:task-created` | `{taskId, flowName, bizTitle}` | 待办通知 |
| `flow:instance-finished` | `{instanceId, modelId, recordId, status}` | 详情页/列表刷新 |
| `schema:invalidate`（广播内部） | `{modelId, version}` | 元数据缓存（不经前端） |

断线重连 + seq 补拉约定见前端文档 06FE §6；服务端实现见本域 §2 缓存一致性。
