# 详细技术文档 01 · 元数据服务（metadata-service）

> 上游：《技术方案-后端(Java).md》v0.2 §2/§3/§3.2/§3.3；PRD §3.1、§6.1 决策
> 本文定位：**实现级技术设计**——表结构、接口契约、状态机、核心算法、异常与边界
> 服务：`metadata-service` ★平台核心服务之一

---

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| 模型/字段/关系元数据 CRUD 与状态机 | 业务数据读写（归 data-engine） |
| Schema 版本快照、diff、回滚 | 页面 Schema 存储（归 page-service，但字段引用归本服务分析） |
| 变更影响面分析（precheck） | 物理表 DDL 执行（仅发任务，由 data-engine 的 DDL 执行器消费） |
| 元数据缓存失效广播 | 计量（仅发事件） |

## 2. 核心表设计

```sql
-- 模型表
CREATE TABLE meta_model (
  id              BIGSERIAL PRIMARY KEY,
  tenant_id       BIGINT NOT NULL,
  app_id          BIGINT NOT NULL,
  model_key       VARCHAR(64) NOT NULL,
  name            VARCHAR(128) NOT NULL,
  icon            VARCHAR(64),
  status          VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE / DELETED / ARCHIVED
  deleted_at      TIMESTAMPTZ,
  current_version INT NOT NULL DEFAULT 1,
  created_by      BIGINT, created_at TIMESTAMPTZ, updated_at TIMESTAMPTZ,
  UNIQUE (tenant_id, app_id, model_key)
);
CREATE INDEX idx_meta_model_tenant ON meta_model(tenant_id, status);

-- 字段元数据表（核心）
CREATE TABLE meta_field (
  id            BIGSERIAL PRIMARY KEY,
  tenant_id     BIGINT NOT NULL,
  model_id      BIGINT NOT NULL,
  field_key     VARCHAR(64) NOT NULL,
  label         VARCHAR(128) NOT NULL,
  field_type    VARCHAR(32) NOT NULL,   -- text/number/date/enum/boolean/file/richtext/relation/geo/user/dept/computed
  field_status  VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE / DELETED
  deleted_at    TIMESTAMPTZ,
  required      BOOLEAN DEFAULT FALSE,
  unique_flag   BOOLEAN DEFAULT FALSE,
  indexed       BOOLEAN DEFAULT FALSE,  -- 是否提升列
  promote_status VARCHAR(16),           -- NULL / PENDING / BUILDING / ACTIVE / FAILED
  default_value JSONB,
  validators    JSONB,                  -- [{type:'range',min,max},{type:'expression',expr}]
  enum_options  JSONB,                  -- [{value,label,color,status:'ACTIVE'|'DEPRECATED'}]
  relation_config JSONB,                -- {targetModelId, cardinality:'1:1'|'1:n'|'n:n', cascade:'FORBID'|'SET_NULL'|'CASCADE_SOFT_DELETE'}
  computed_config JSONB,                -- {expr, dependsOn:[fieldKey], persistMode:'READ_TIME'|'PERSISTED'}
  sort_order    INT NOT NULL DEFAULT 0,
  schema_version INT NOT NULL,          -- 该字段最后变更所在版本
  created_at TIMESTAMPTZ, updated_at TIMESTAMPTZ,
  UNIQUE (model_id, field_key)
);

-- 关系定义（n:n 中间表登记）
CREATE TABLE meta_relation (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  model_a_id BIGINT NOT NULL, model_b_id BIGINT NOT NULL,
  cardinality VARCHAR(8) NOT NULL,      -- '1:1','1:n','n:n'
  field_id BIGINT,                      -- 承载关系的表现字段（meta_field.id）
  cascade_strategy VARCHAR(32) NOT NULL,
  created_at TIMESTAMPTZ,
  UNIQUE (model_a_id, model_b_id, field_id)
);

-- 版本快照表（每次保存一条）
CREATE TABLE meta_schema_version (
  id BIGSERIAL PRIMARY KEY,
  model_id BIGINT NOT NULL,
  version INT NOT NULL,
  snapshot JSONB NOT NULL,              -- 完整字段定义快照（可整体还原）
  diff JSONB NOT NULL,                  -- [{op:'ADD_FIELD'|'MODIFY_FIELD'|'DELETE_FIELD'|'PROMOTE_COLUMN', fieldKey, detail}]
  operator_id BIGINT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL,
  rollback_from INT,                    -- 非空表示本版本由回滚产生
  UNIQUE (model_id, version)
);

-- 显式引用表（影响面分析主路径，§3.3）
CREATE TABLE meta_field_reference (
  id BIGSERIAL PRIMARY KEY,
  tenant_id BIGINT NOT NULL,
  model_id BIGINT NOT NULL,
  field_key VARCHAR(64) NOT NULL,
  ref_type VARCHAR(16) NOT NULL,        -- PAGE / FLOW / API_KEY / COMPUTED
  ref_id BIGINT NOT NULL,               -- pageId / flowId / apiKeyId / fieldId
  created_at TIMESTAMPTZ,
  UNIQUE (model_id, field_key, ref_type, ref_id)
);
CREATE INDEX idx_ref_field ON meta_field_reference(model_id, field_key);
```

所有核心表走 **Flyway** 管理（私有化预留约束）。

## 3. 字段状态机

```
              ┌────────── 保存回滚（恢复历史版本）──────────┐
              │                                             │
              ▼                                             │
         ┌────────┐    用户删除+影响面确认    ┌────────┐     │
         │ ACTIVE │ ───────────────────────▶ │ DELETED│ ────┘
         └────────┘                          └────────┘
              │  标记 indexed                     │
              ▼                                  │
         promote_status: PENDING→BUILDING→ACTIVE │ 永不物理删除行
              （FAILED 可重试）                    │ 物理列/数据键保留
```

**铁律（代码层强制，注释不算数）**：

1. `meta_field` 行永不 DELETE，只 UPDATE `field_status`；
2. 删除模型 = `meta_model.status='DELETED'` + 物理表改名 `biz_model_{id}_archived`（仅改名，不 DROP）；
3. 已删除提升列不执行 `DROP COLUMN`——仅元数据停止引用（PostgreSQL DROP COLUMN 重写全表且不可逆）。

## 4. 接口契约

### 4.1 模型 CRUD

```
POST   /api/models                        # 创建模型（初始版本 v1，自动建物理表）
GET    /api/models?appId=&keyword=        # 列表（过滤 DELETED，?includeDeleted=1 管理员）
GET    /api/models/{id}                   # 详情（含字段列表）
PUT    /api/models/{id}                   # 改名/图标
DELETE /api/models/{id}                   # 逻辑删除（走确认协议，§4.3）
```

### 4.2 变更保存（核心接口，两段式）

```
POST /api/models/{id}/precheck
Body: { changes: [ {op:'ADD_FIELD', field:{...}} ,
                   {op:'MODIFY_FIELD', fieldKey:'amount', patch:{required:true}},
                   {op:'DELETE_FIELD', fieldKey:'legacy_no'} ] }
Resp: { risks: [ {type:'PAGE_REF', refId:1, refName:'订单列表', severity:'HIGH'},
                 {type:'FLOW_REF', refId:3, severity:'MEDIUM'},
                 {type:'API_CONSUMER', keyName:'erp-sync', calls30d:230, severity:'HIGH'},
                 {type:'DATA_VOLUME', count:102400, severity:'INFO'} ],
        maxSeverity:'HIGH',
        confirmMode:'TYPE_MODEL_NAME' }   # INFO / CHECKBOX / TYPE_MODEL_NAME

POST /api/models/{id}/schema
Body: { changes:[...同上], baseVersion: 7,
        confirmToken: 'xxx' }             # precheck 后签发，服务端校验
Resp: { version: 8, promotedTasks:[{taskId, fieldKey}] }
```

**保存事务流程**：

```
@Transactional
saveSchema(changes, baseVersion, confirmToken):
  1. 乐观锁校验：meta_model.current_version == baseVersion，否则 409（前端弹冲突对比）
  2. 幂等校验：confirmToken 未消费过
  3. 逐条应用 changes → 内存构建新字段集合
     - DELETE_FIELD：field_status='DELETED' + deleted_at
     - ADD_FIELD：插入行（indexed=true 时 promote_status='PENDING'）
     - MODIFY_FIELD：按 patch 白名单更新（field_key、field_type 不可改）
  4. 校验器：循环依赖检测（计算字段依赖图）、枚举值引用、关系目标存在
  5. 生成 diff + snapshot → 插入 meta_schema_version (version+1)
  6. 元数据落库
  7. 事务提交后：
     - 投递 DDL 任务（提升列）到 MQ topic: ddl.promote
     - 广播缓存失效：Redis pub/sub channel 'schema:invalidate' {modelId, version}
     - 记审计（diff 全文）+ 计量事件
```

### 4.3 删除确认协议

- precheck 返回 `confirmMode`：
  - `INFO`：低风险（新增/改标签），前端一键确认；
  - `CHECKBOX`：中风险（删除/类型变更/必填收紧），勾选"我已了解影响"；
  - `TYPE_MODEL_NAME`：高风险（删被 ≥3 页面引用 或 近 30 天有外部调用的字段/删模型），前端必须回传模型名原文，服务端等值比对。
- 高风险操作额外：写审计 + 站内信通知应用 Owner。

### 4.4 版本与回滚

```
GET   /api/models/{id}/versions            # 版本时间线（version/diff摘要/操作人/时间）
GET   /api/models/{id}/versions/{v}        # 查看该版本完整字段定义
POST  /api/models/{id}/rollback            # Body: {targetVersion: 5}
```

**回滚实现**：读取 `meta_schema_version.snapshot` → 与当前字段集合做 diff → 以 `MODIFY/ADD/DELETE` 变更集形式**走同一保存流程**（复用全部校验）→ 生成新版本（`rollback_from=5` 标记）。**数据零操作**——数据从未删过，字段恢复 ACTIVE 后读取自然可用。

### 4.5 影响面分析实现

```
precheck(changes):
  for each change involving fieldKey:
    risks += field_reference 表同步查询          # 主路径：<10ms
    risks += 开放API聚合: SELECT count(*) FROM api_call_log
             WHERE api_key_id IN (...) AND fields_used ? 'fieldKey'
             AND occurred_at > now()-30d          # api_call_log 需按 fields_used JSONB GIN 索引
    risks += DATA_VOLUME:
             SELECT count(*) FROM biz_model_{id} WHERE data ? 'fieldKey'
             -- 行数 > 100万 时改采样：EXPLAIN 确认走 GIN，否则
             -- 用 pg_class.reltuples 估算 + 提示"估算值"
  # 异步兜底（不阻塞响应）：
  投递 fullscan 任务 → 全库扫描 page_schema/flow_schema JSON
  → 与 field_reference 对比 → 差异告警 + 回补引用表
```

**引用登记时机**：page-service 保存页面时解析 props/表达式 `dependsOn` → 调本服务 `POST /internal/references`（upsert）；删除页面时同步清理。COMPUTED 类型引用在字段保存时由本服务自己登记。

### 4.6 数据体检（P2）

```
POST /api/models/{id}/health-check    # 异步任务
```

- 按字段类型生成只读扫描 SQL（如 `data->>'amount' !~ '^[0-9.]+$'`），分页游标扫描，输出不兼容记录清单到体检报告表；
- 修复工具（三种：置空/替换/映射转换）生成更新任务交 data-engine 执行，前后统计快照落审计；**平台不自动发起**。

## 5. 元数据缓存设计

```
Redis key: schema:{tenantId}:{modelId} → 字段集合 JSON，TTL 1h
失效：保存事务提交后 pub/sub 广播，各节点删除本地 Caffeine + Redis 键
版本号单调递增：读取时比对 version，过期自行刷新（节点自行发现，避免依赖广播到达）
```

**一致性要求分级**：
- 字段新增/改配置：允许短暂脏读（秒级窗口，可接受）；
- **字段删除：强一致**——保存流程为「先广播失效 → 等待各节点 ACK（订阅计数）→ 再提交元数据事务」两阶段；超时未 ACK 则放弃本次保存并告警（宁可不删也不能让已删字段短暂可见）。

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 并发保存同一模型 | `current_version` 乐观锁，后者 409 + 返回最新版本供前端合并 |
| 删除字段时引用表有记录 | 不阻断（引用是提示性依赖），仅计入影响面 severity |
| 提升列任务失败 | promote_status='FAILED'，可重试；期间查询自动回退 JSONB 表达式（data-engine 逻辑） |
| 回滚到的版本引用了已删除的其他模型字段 | 保存流程校验拦截，提示先恢复依赖 |
| n:n 关系删除 | 中间表保留，仅关系元数据置删除标识 |
| 单租户模型数超上限（默认 200） | 创建时拒绝 + 引导升级；超大客户走「共享表 + model_id」模式（§02 详述） |

## 7. 单元测试硬性要求

- [ ] 字段状态机：DELETED 字段不可被任何查询路径返回（配合 data-engine 越权用例）
- [ ] 乐观锁：并发保存仅一方成功
- [ ] 回滚后字段 ACTIVE 恢复且 diff 正确标记 rollback_from
- [ ] 影响面：显式引用表命中 + 异步全扫描差异回补
- [ ] 高风险确认：confirmToken 一次性消费；模型名比对失败拒绝保存
- [ ] 缓存失效两阶段：删除场景无 ACK 不提交

## 附录 A · 对外接口契约（REST 汇总）

> 前端消费方：ER 建模器（前端文档 10）、属性面板字段绑定（文档 04/05）、协议层类型来源（文档 01FE）。
> 鉴权：全部 Bearer + 租户头；`includeDeletedFields` 仅管理员。错误体统一 `{code, message, traceId}`（文档 03）。

### A.1 模型 CRUD

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/models` | `{appId, modelKey, name, icon?}` | `{id, modelKey, currentVersion:1}` |
| GET | `/api/models?appId=&keyword=&includeDeleted=` | — | `{list:[ModelSummary], total}`（Summary：id/modelKey/name/icon/status/currentVersion/updatedAt） |
| GET | `/api/models/{id}` | — | `ModelSchema`（字段数组含 `fieldStatus`，见 §2 表映射） |
| PUT | `/api/models/{id}` | `{name?, icon?}` | `{}` 200 |
| DELETE | `/api/models/{id}` | — | `{}` 200（逻辑删除，走 §4.3 确认协议） |

### A.2 变更保存（两段式，核心）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/models/{id}/precheck` | `{changes:[ChangeOp]}` | `{risks[], maxSeverity, confirmMode, confirmToken}` |
| POST | `/api/models/{id}/schema` | `{changes, baseVersion, confirmToken}` | `{version, promotedTasks[]}` 或 `409 {serverVersion}` |

`ChangeOp` 联合体：`{op:'ADD_FIELD', field:{...FieldSchema}}` | `{op:'MODIFY_FIELD', fieldKey, patch:{...白名单}}` | `{op:'DELETE_FIELD', fieldKey}` | `{op:'PROMOTE_COLUMN', fieldKey}`（详见 §4.2）。
`risks[]` 元素：`{type:'PAGE_REF'|'FLOW_REF'|'API_CONSUMER'|'DATA_VOLUME', refId?, refName?, calls30d?, count?, severity:'HIGH'|'MEDIUM'|'INFO'}`。

### A.3 版本与回滚

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/models/{id}/versions` | — | `{list:[{version, diffSummary, operator, createdAt, rollbackFrom?}]}` |
| GET | `/api/models/{id}/versions/{v}` | — | `{version, snapshot}`（完整字段定义） |
| POST | `/api/models/{id}/rollback` | `{targetVersion}` | `{version}`（走同一保存流程，含 confirmToken） |

### A.4 内部接口（服务间，不经网关）

| 方法 | 路径 | 调用方 | 说明 |
|---|---|---|---|
| POST | `/internal/references` | page-service | upsert 字段引用（`{modelId, fieldKey, refType, refId}`）；页面删除同步清理 |
| POST | `/internal/cache/ack` | 全部节点 | 字段删除两阶段 ACK（§5） |

### A.5 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `MODEL_VERSION_CONFLICT` | 409 | baseVersion 过期（前端走三方对比，前端文档 04 §7） |
| `CONFIRM_TOKEN_INVALID` | 422 | token 未签发/已消费/模型名比对失败 |
| `MODEL_LIMIT_EXCEEDED` | 403 | 单租户模型数超上限 |
| `FIELD_KEY_IMMUTABLE` | 422 | MODIFY 尝试改 field_key/field_type |
| `CIRCULAR_DEPENDENCY` | 422 | 计算字段依赖成环 |

### 前端对接要点（指向消费文档）

- 列表/详情的 `fields[].fieldStatus` 驱动字段绑定下拉的 ACTIVE 过滤与 DELETED 置灰（前端文档 04 §5）；
- `precheck → confirmMode 分级交互 → confirmToken 一次性` 流程交互见前端文档 10 §1.3；DELETE_FIELD 前端永远升级为 CHECKBOX；
- `409 {serverVersion}` 响应结构由 request-sdk 归一化为 `VersionConflictError`（前端文档 07 §4）。
