## 1. 职责边界

| permission-service | tenant-service | 横切（common-security） |
|---|---|---|
| 用户/角色/权限点 CRUD | 租户生命周期（注册/配额/停服） | TenantContext（存储接口化 §2.1） |
| 行级/字段级数据权限规则 | 应用生命周期（成员/导航/发布记录） | MyBatis 租户拦截器 |
| 权限判定 RPC（网关与各服务调用） | 模板安装/应用导出导入 | JWT 解析与透传 |

## 2. 租户上下文与拦截器

### 2.1 TenantContext

```java
public final class TenantContext {
    // 存储实现接口化（M0 定版：JDK21 的 ScopedValue 尚为预览特性，不进主干）
    private static final TenantContextHolder HOLDER = TenantContextHolder.threadLocal();
    public static TenantInfo get() {          // 单租户模式恒返回默认租户（可退化约束）
        return HOLDER.get();
    }
    public static <T> T with(TenantInfo t, Supplier<T> action) {  // 结构化绑定：块级清理防泄漏
        return HOLDER.with(t, action);
    }
}
// TenantContextHolder：get / with / clear 三方法接口（ThreadLocal 为 M0 默认实现；
//   JDK ScopedValue 转正式后无缝切换，业务代码零改动）
// 纪律：业务代码只经 TenantContext 访问；异步边界（@Async/MQ 消费/线程池）入口必须
//   显式 with() 传递并 finally 清理——上下文泄漏检测为 M3.1 硬性测试用例
// 网关解析租户（子域/路径/JWT claim）→ 写入 header X-Tenant-Id → 各服务 Filter 还原为 TenantContext
// 内部 RPC（Dubbo/Feign）通过隐式附件透传，接口签名不出现 tenantId 参数
```

### 2.2 MyBatis 租户拦截器

```java
@Intercepts({@Signature(type = Executor.class, method = "query", args = {...}),
             @Signature(type = Executor.class, method = "update", args = {...})})
public class TenantInterceptor implements Interceptor {
    // 1. 解析 MappedStatement 的 SQL（JSqlParser）
    // 2. 所有含 tenant_id 列的表：WHERE 自动追加 tenant_id = ?
    //    INSERT 自动填充 tenant_id 列
    // 3. @TenantIgnore 注解（方法级）跳过——仅限平台级管理查询，使用处需代码评审说明理由
}
```

- 拦截器是**兜底防线**；data-engine 的 SQL 构建层再显式注入一次（双保险，§02 §3.3）。
- **CI 硬性项**：每个新增数据查询 Service 必须附带「伪造租户上下文被拦截」的单测，无此用例不予合并。

## 3. RBAC 权限模型

### 3.1 表结构

```sql
CREATE TABLE sys_user (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL,
  account VARCHAR(64) NOT NULL, name VARCHAR(64),
  password_hash VARCHAR(128),           -- bcrypt
  dept_id BIGINT,                       -- 主部门
  status VARCHAR(16) NOT NULL,          -- ACTIVE / DISABLED
  last_login_at TIMESTAMPTZ,
  UNIQUE (tenant_id, account)
);

CREATE TABLE sys_role (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL,
  code VARCHAR(64) NOT NULL, name VARCHAR(64),
  role_type VARCHAR(16),               -- TENANT / APP
  app_id BIGINT,                       -- 应用级角色非空
  UNIQUE (tenant_id, app_id, code)
);

CREATE TABLE sys_user_role (
  user_id BIGINT, role_id BIGINT,
  PRIMARY KEY (user_id, role_id)
);

CREATE TABLE sys_role_permission (
  role_id BIGINT, resource_type VARCHAR(32) NOT NULL,  -- APP/PAGE/MODEL/RECORD/FIELD/ACTION/FLOW
  resource_id BIGINT,                                  -- 资源 ID；FIELD 行资源用 model_id
  action VARCHAR(32) NOT NULL,                         -- 访问/查看/设计/新建/编辑/删除/可见/可编辑/可执行/发起
  PRIMARY KEY (role_id, resource_type, resource_id, action)
);

-- 行级数据权限（挂在角色 × 模型上）
CREATE TABLE sys_role_data_scope (
  role_id BIGINT, model_id BIGINT,
  scope_type VARCHAR(32) NOT NULL,     -- ALL / SELF / DEPT / DEPT_TREE / CUSTOM_EXPR
  scope_expr TEXT,                     -- CUSTOM_EXPR 时为 L1 表达式
  PRIMARY KEY (role_id, model_id, scope_type)
);

CREATE TABLE sys_dept (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL,
  parent_id BIGINT, path VARCHAR(512),  -- 物化路径 /1/5/12/
  name VARCHAR(64), sort INT
);
```

### 3.2 权限判定链

```
登录 → JWT(userId, tenantId)【不含权限明细，防止权限变更后仍有效】
  → 前端拉权限清单：GET /api/me/permissions
     → { apps:[{appId, pages:[pageId], actions:[...]}] }
     → 前端缓存 5 分钟 + 服务端失效推送（权限变更广播）
  → 后端每请求：
     网关：JWT 验签 → 解析租户 → 路由
     目标服务：功能权限 RPC（permission-service，结果本地 Caffeine 60s）
     data-engine：行级/字段级注入 SQL
```

**安全铁律**：前端隐藏是体验；后端逐请求校验是安全边界。

### 3.3 行级数据权限 SQL 生成

```
resolveDataScopes(userId, modelId):
  roles = user 的全部角色（租户级 + 当前应用级）
  scopes = roles 的 sys_role_data_scope（该 model）
  多角色取并集（最大可见范围）→ SQL 用 OR 连接：

  scope_type → SQL 片段：
    ALL        → TRUE
    SELF       → created_by = :userId
    DEPT       → dept_id = :userDeptId        （记录冗余部门列，写入时固化）
    DEPT_TREE  → dept_id IN (SELECT id FROM sys_dept WHERE path LIKE :userDeptPath || '%')
    CUSTOM_EXPR→ 表达式编译为 SQL 条件
                 （仅支持：字段 vs 当前用户属性比较；禁止子查询/函数调用白名单外）

  前端属性上下文：currentUserId/currentUserDeptId/currentUserRoles 注入为参数
```

### 3.4 字段级权限

- 查询时：不可见字段从 SELECT 投影与响应 JSON 中**物理剔除**（不是置 null——置 null 仍暴露字段存在性）；
- 写入时：不可编辑字段的写入请求静默忽略 + 记 debug 日志（兼容前端全量表单提交）；
- 与 DELETED 叠加：`不可见 ∪ 已删除 → 一律剔除`；
- 表达式引用了不可见字段：设计器保存时校验告警（信息性不阻断），运行时求值得 undefined 按空处理。

## 4. 认证与会话

| 项 | 实现 |
|---|---|
| 登录 | 账号密码 bcrypt；失败 5 次锁 15 分钟（Redis 计数）；响应统一 401 相同文案（防账号枚举） |
| JWT | access 2h / refresh 7d；refresh 支持吊销黑名单（Redis，登出/改密/停用写入）；refresh 每次滚动签发 + 旧 token 即刻入黑名单（重放检测：黑名单命中记安全审计） |
| CSRF | 平台认证为 **Bearer Header**（非 Cookie 自动携带）→ 传统 CSRF 面已收窄；仍强制三道兜底：①状态变更接口校验 `Origin`/`Referer`（缺失或不匹配即 403 `CSRF_ORIGIN_REJECTED`）②CORS 白名单（禁止反射任意 Origin；`credentials` 场景只放行显式列出的租户域）③GET/HEAD 一律无副作用（幂等约束入 CI 规约）。嵌入宿主域列入白名单管理 |
| 会话绑定 | JWT claim 内含 tenantId 与登录时租户绑定；请求头 `X-Tenant-Id` 仅作路由提示，**鉴权以 claim 为准**——头与 claim 不一致立即返回 403 TENANT_MISMATCH 并记安全审计，不继续执行业务查询或写入；未提供租户头时以已验证 claim 建立上下文（防伪造租户头跨租户） |
| 敏感操作 | 密钥查看/租户停服/强制解锁等二次认证（密码或短时重认证窗口） |
| SSO（P2） | OAuth2 授权码（对接企业 IdP）+ SAML 2.0 |
| 三方登录（P2） | 企微/飞书/钉钉扫码 → 邮箱/手机匹配置信度阈值决定绑定或建新账号 |
| 组织同步（P2） | 企微/飞书单向同步 + 定时对账，冲突以三方为准 |

### 4.1 前端 Token 存储（与前端 07FE §5 同源）

- accessToken：内存持有 + sessionStorage 镜像（刷新恢复），**不落 localStorage**；
- refreshToken：随请求体传输（非 Cookie），由 auth-sdk 内存持有；**P2 评估迁 HttpOnly Cookie + CSRF Token 双提交**（若引入 Cookie 认证端点，CSRF 防护升级为强制双提交——本节 §CSRF 三道兜底之上加随机 token）；
- 一次性 code（嵌入）：URL 只传 code 不传 token，60s 过期 + 单次使用。

> 前端消费方：auth-sdk（前端文档 07 §5）、路由/按钮守卫（文档 06FE §4）、组织选择器物料（UserPicker/DeptPicker，文档 05FE）。

### A.3.1 成员账号生命周期（P1 无邮件通道，2026-10-28 补）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/org/members` | 管理员建号：`{username, name, deptId?, initialPassword?}`——P1 不发激活邮件；`initialPassword` 缺省时服务端生成一次性初始密码返回一次（管理员线下交付）；建号记审计 |
| POST | `/api/org/members/import` | Excel 批量导入（模板下载 + 行级错误回报；同名/同账号去重校验） |
| POST | `/api/auth/reset-password` | 管理员重置：`{userId}` → 生成一次性新密码（返回一次）+ 强制下次登录改密 + 记审计；**P1 无自助找回**（邮件通道 P2 随 L4 连接器上线，届时补 `/api/auth/forgot` 自助流程） |
| PUT | `/api/me/password` | 本人改密：`{oldPassword, newPassword}`（密码策略校验：长度/复杂度）；改密后**全部旧 refresh token 入黑名单**，响应直接签发**新 access + refresh 对**（`{accessToken, refreshToken, mustChangePassword:false}`）——改密即换会话，用户不需要重新登录 |

- 首次登录强制改密：建号/重置后 `must_change_password=true`，除改密接口外全部请求返回 403 `PASSWORD_CHANGE_REQUIRED`；
- **改密期放行名单（2026-10-28 补——PASSWORD_CHANGE_REQUIRED 拦截的例外集）**：`PUT /api/me/password`（改密本体）+ `POST /api/auth/logout`（放弃改密退出）+ `GET /api/me`（渲染改密页需的用户名/策略提示）——其余接口（含业务读）一律 403；
- **改密后登录态恢复定版**：改密成功响应内联签发新 token 对（见上表），前端替换本地凭证即恢复完整登录态；旧 token（其他设备/标签页）下一个刷新周期收到 401 `REFRESH_REVOKED` → 清快照跳登录页（多设备踢出语义，07FE §5 同步）；
- 一次性密码只返回一次不落明文（bcrypt 入库）；审计记录「谁为谁建号/重置」。

### A.4 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `ACCOUNT_LOCKED` | 423 | 失败 5 次锁 15 分钟 |
| `REFRESH_REVOKED` | 401 | 黑名单内 refresh（前端清快照跳登录） |
| `PERM_DENIED` | 403 | 功能权限不足 |
| `CSRF_ORIGIN_REJECTED` | 403 | 状态变更请求 Origin/Referer 校验失败（§4 CSRF 兜底） |
| `TENANT_MISMATCH` | 403 | 请求头租户与 JWT claim 不一致（记安全审计，§4 会话绑定） |
| `PASSWORD_CHANGE_REQUIRED` | 403 | 建号/重置后未改密（仅放行改密接口，§A.3.1） |

### 前端对接要点

- token 存储/静默刷新/单飞锁见前端文档 07 §5（过期前 5min 刷新；并发 401 只发一次）；
- `hasPerm(perm)` O(1) 快照判断；登出/401 刷新失败/切租户失效（前端文档 06FE §4 双层守卫）；
- 嵌入场景 code 流：宿主 postMessage 传 code → `/exchange` → 标准登录态（前端文档 06FE §5）。

## 5. 应用角色与席位（tenant-service）

> 本节为**判定规则定义**；租户/应用生命周期、成员管理接口、模板安装、导航树的实现级设计见文档 13（tenant-service 专篇）。

- 应用角色：应用管理员 / 开发者 / 使用者（覆盖关系见详细 PRD 07）；
- **席位三口径**（口径定版 2026-10-28，与 PRD 04 §2.1/PRD §8.4 同源；实现归 13BE §2.4，本节只定规则）：
  - **授权席位** = 具备任一应用「开发者」或「应用管理员」角色（两角色均携带设计能力）的账号数——授权即计，无论是否操作；配额硬限口径；
  - **活跃席位** = 授权席位中**滚动 30 天**内有设计器写操作者（服务端埋点终审，见 09BE §4；仅登录不算）——席位明细展示与客户成功口径；
  - **账单席位** = 出账口径（计费周期冻结/月中撤权折算等）——**P3 出账功能启动时另行冻结定义**，不得提前沿用活跃口径；
  - 纯管理角色（未来引入的无设计能力角色）不计任何席位口径；
- 停用成员联动：登录失效（黑名单）→ 待办按租户配置转移 → 席位释放（计量口径次日生效）。

## 6. 审计日志

```sql
CREATE TABLE sys_audit_log (
  id BIGSERIAL, tenant_id BIGINT, user_id BIGINT,
  event_type VARCHAR(32),        -- LOGIN / SCHEMA_CHANGE / DATA_CHANGE / PERM_CHANGE / PUBLISH / SENSITIVE_OP
  resource_type VARCHAR(32), resource_id VARCHAR(64),
  diff JSONB,                    -- 变更前后快照；敏感字段存摘要哈希
  ip VARCHAR(64), ua VARCHAR(256), trace_id VARCHAR(64),
  created_at TIMESTAMPTZ NOT NULL
) PARTITION BY RANGE (created_at);   -- 按月分区，保留 1 年
```

- 采集点：网关（登录）、metadata（Schema diff）、data-engine（记录变更脱敏摘要）、permission（授权 diff）、发布、敏感操作（`includeDeletedFields` 读取/导出/密钥查看）；
- 查询界面按人/时间/类型过滤，导出行为本身记审计。

## 7. 单元测试硬性要求

- [ ] 拦截器：全表访问样本（含 JOIN/子查询/INSERT）租户条件注入正确；@TenantIgnore 白名单生效
- [ ] 行级并集：SELF + DEPT_TREE 叠加后可见范围为并集
- [ ] 字段交集：两角色一个可见一个不可见 → 结果不可见
- [ ] 字段剔除：响应 JSON 键物理不存在（断言无该键而非 null）
- [ ] 越权：伪造租户/伪造用户上下文的全部数据路径被拦截
- [ ] JWT 吊销：黑名单内 refresh token 刷新被拒
- [ ] 表达式转 SQL：含子查询/危险函数的 CUSTOM_EXPR 被拒绝
- [ ] 席位三口径：授权即计（有角色无操作仍计授权）；活跃仅滚动 30 天写操作（登录不算）；两口径独立可同值
- [ ] P1 建号/重置：一次性密码只返回一次；`PASSWORD_CHANGE_REQUIRED` 拦截除放行名单（改密/登出/me）外全部接口；管理员重置记审计
- [ ] 改密会话恢复：改密响应签发新 token 对（不强制重登录）；旧 refresh 刷新被拒（401 REFRESH_REVOKED）模拟多设备踢出
