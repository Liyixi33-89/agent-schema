# 详细技术文档 11 · 文件服务（file-service）

> 上游：《技术方案-后端(Java).md》v0.2 §1（对象存储选型）/§2（服务拆分第 9 位）/§11（外部依赖接口化红线）
> 本文定位：实现级技术设计——直传签名、分块上传、存储抽象、生命周期、防滥用
> 服务：`file-service`；下游依赖：S3 协议对象存储（MinIO / 阿里云 OSS 双实现，§3）
> 消费方：附件字段（data-engine）、批量导入（02 §7）、应用导出包（13 §模板）、编译产物（04）、头像/Logo（租户/应用）

## 1. 职责边界

| 负责 | 不负责 |
|---|---|
| 上传凭证签发（预签名 URL 直传，文件不过 Java） | 文件内容解析（Excel 解析归 data-engine 导入任务） |
| 分块上传会话管理与合并 | 图片处理/缩略图（P3，先直存原图） |
| 文件元数据登记与查询 | 病毒扫描（P2 接 ClamAV，一期只做类型白名单） |
| 下载凭证签发（私有读，URL 时效） | 业务字段值引用关系维护（字段里只存 fileId，引用检查归 data-engine） |
| 生命周期策略执行（临时文件过期清理） | CDN 刷新（部署层职责，接口化预留） |
| 存储配额统计（storage.gb 计量源） | 出账（归 metering，09） |

**核心决策：浏览器/客户端直传对象存储，file-service 只签凭证 + 记元数据。**
理由：文件字节流不经过 Java 应用（省带宽与内存）；上传失败重试不发生活锁；大文件与平台 API 吞吐解耦。

## 2. 存储抽象层（私有化红线，§11 外部依赖接口化）

```java
public interface ObjectStorage {
    PresignedUrl presignPut(String objectKey, Duration expiry, String contentType, long maxSize);
    PresignedUrl presignGet(String objectKey, Duration expiry);
    String completeMultipart(String uploadId, List<PartETag> parts);
    String initiateMultipart(String objectKey);
    PresignedUrl presignPartPut(String uploadId, int partNumber, Duration expiry);
    void delete(String objectKey);
    long sizeOf(String objectKey);
}
// 实现：S3StorageImpl（MinIO/OSS 同协议）、占位 LocalFsStorageImpl（本地开发零依赖启动）
// 业务代码禁止出现 com.aliyun.* / io.minio.* 直接 import（CI 依赖扫描，文档 10 §红线）
```

**对象 Key 规范**（扁平化、可按前缀清理、不承载业务语义）：

```
{tenantId}/{appId?}/{scope}/{yyyyMM}/{fileId}/{fileName}
  scope ∈ attachment | import | export | artifact | avatar | template
  例：1001/23/attachment/202610/9007199254740993/合同扫描件.pdf
```

- fileId 为雪花 ID，全局唯一，重名文件天然隔离；
- 业务引用存 fileId（永存），物理文件可按策略清理——**引用与物理存储解耦**。

## 3. 上传协议

### 3.1 小文件直传（≤ 20MB，默认路径）

```
① 客户端：POST /api/files/presign
   {fileName, contentType, size, scope, appId?}
   → 服务端校验：类型白名单 + 大小上限 + 配额（storage 软限，09 §6）
   → 响应 {fileId, uploadUrl(预签名 PUT, 10min), objectKey}
② 客户端：PUT uploadUrl 直传对象存储（file-service 不感知字节流）
③ 客户端：POST /api/files/{fileId}/complete
   → 服务端 HEAD 校验对象存在且 size 匹配 → 登记元数据 → 响应 {fileId, url?}
④ 未 complete 的预签名：15min 后清理（孤儿对象，§5 生命周期）
```

### 3.2 分块上传（> 20MB）

```
① POST /api/files/multipart  {fileName, contentType, size, scope}
   → {fileId, uploadId}
② POST /api/files/{fileId}/parts  {partNumber}（循环调用）
   → {partUrl}（每块预签名，块大小 8MB，1-10000 块 → 上限 ~80GB）
③ 客户端逐块 PUT；断点续传 = 已传块号集合持久化，客户端跳过
④ POST /api/files/{fileId}/complete  {parts:[{partNumber, etag}]}
   → 服务端调 completeMultipart 合并 + 登记元数据
```

### 3.3 类型与大小白名单

| scope | 类型限制 | 大小上限 |
|---|---|---|
| attachment（附件字段） | pdf/office/图片/zip/文本等业务白名单 | 100MB（超限引导分块） |
| import（批量导入） | xlsx/csv | 50MB |
| avatar / appLogo | png/jpg/webp/svg | 2MB |
| artifact（编译产物） | js（build-service 内部写入，不走预签名） | 10MB |
| template（应用导出包） | .schema-app（json） | 50MB |

- 类型判定依据**魔数探测**（Apache Tika）而非扩展名——扩展名可伪造；complete 时若存储侧支持 content-type 校验则双重核对；
- 白名单外类型 400 + `FILE_TYPE_FORBIDDEN`；私有化部署白名单可配置追加。

## 4. 元数据模型

```sql
CREATE TABLE file_object (
  id            BIGINT PRIMARY KEY,            -- fileId（雪花）
  tenant_id     BIGINT NOT NULL,
  app_id        BIGINT,
  scope         VARCHAR(32) NOT NULL,          -- §2 对象 Key 的 scope
  object_key    VARCHAR(512) NOT NULL,
  file_name     VARCHAR(255) NOT NULL,         -- 原始文件名（下载时还原）
  content_type  VARCHAR(128),
  size_bytes    BIGINT NOT NULL,
  sha256        VARCHAR(64),                   -- complete 时由客户端提供（可选，去重用）
  status        VARCHAR(16) NOT NULL,          -- PENDING(已签名未完成) / ACTIVE / EXPIRED
  uploaded_by   BIGINT, created_at TIMESTAMPTZ NOT NULL,
  expire_at     TIMESTAMPTZ                    -- 临时文件过期时间（NULL=永久）
);
CREATE INDEX idx_file_tenant ON file_object(tenant_id, scope, created_at);
CREATE INDEX idx_file_expire ON file_object(expire_at) WHERE expire_at IS NOT NULL;
```

- **下载**：`GET /api/files/{fileId}/url` → `{downloadUrl}`（预签名 GET，5min 时效，前端每次要用时现取，不缓存长链接）；
- **删除**：附件字段值被清空/记录删除**不触发**物理删除（引用多对一，删除判定成本高）；物理清理统一走生命周期（§5）或显式管理操作；
- 引用完整性：字段值中的 fileId 若 `status != ACTIVE`（已过期/清理），读取时该字段渲染为「文件已失效」占位——与 `_invalid` 同级的读时容错（文档 02 §3.5）。

## 5. 生命周期与清理

| 对象 | 策略 |
|---|---|
| PENDING 未 complete | 15min 后删除对象 + 元数据（签名放弃/浏览器关闭） |
| import/export 临时文件 | `expire_at = complete 后 7 天`，定时任务扫描删除 |
| 被引用附件（attachment/avatar） | 永久（跟随租户存储配额治理，不自动删） |
| 租户注销/停服 | 延迟 30 天后整租户前缀清理（与数据保留期一致，PRD 04 §租户生命周期） |

- 清理任务幂等：`delete WHERE expire_at < now() LIMIT 500` 循环，对象存储删除 + 元数据置 EXPIRED 双写，失败重试不重复删；
- **storage.gb 计量**：每日定时 `SUM(size_bytes) WHERE status='ACTIVE' GROUP BY tenant_id` → 投递计量事件（09 §4 口径：日峰值）。

## 6. 安全设计

| 风险 | 对策 |
|---|---|
| 越权下载（拿到 fileId 枚举他人文件） | 下载凭证签发前校验：同租户 + 字段引用可达（附件字段有行级权限的场景，下载链接签发走与记录读取相同的权限判定 RPC） |
| 预签名 URL 泄露 | 时效 5-10min + URL 不落日志；上传 URL 一次性（objectKey 含 fileId，重复签名同 key 但旧 URL 自然过期） |
| 恶意文件（WebShell 上传后直链访问） | 私有读（bucket 禁公共读）+ 类型白名单 + P2 病毒扫描；**对象存储域名与平台 API 域名隔离**，文件域名不执行任何服务端逻辑 |
| 存储滥用（配额绕过：签名后反复上传） | 预签名带 content-length 条件（size 上限）；complete 时 size 校验不匹配即删除；租户级签名 QPS 限流 |
| 文件名注入（路径穿越/钓鱼名） | objectKey 由服务端生成（不含用户输入）；原始 file_name 仅作下载头 `Content-Disposition` 值并做 RFC 5987 编码 |

## 7. 与消费方的集成契约

| 消费方 | 约定 |
|---|---|
| 附件字段（data-engine） | 字段值 `{fileId, name, size}` JSON 对象；字段类型校验：fileId 必须存在且 ACTIVE 且 scope=attachment 且**同租户** |
| 批量导入（02 §7） | 上传 scope=import → 导入任务引用 fileId → 任务结束后 7 天过期 |
| 应用导出/模板（13） | 导出包 scope=template；模板安装时下载→解析，不复制存储 |
| build-service（04） | 内部 RPC 直接调 ObjectStorage 写 artifact（不经预签名）；产物 URL 带 contentHash 长缓存 |
| 头像/Logo | scope=avatar；前端裁剪后上传，引用存租户/应用配置 |

## 8. 单元测试硬性要求

- [ ] 类型白名单：伪造扩展名（.png 实为 exe）被魔数探测拦截
- [ ] 直传流程：complete 时对象不存在/size 不匹配 → 删除元数据返回 409
- [ ] 分块：中断后续传跳过已传块；乱序 complete parts 被合并拒绝
- [ ] 越权：跨租户 fileId 取下载凭证被拒（伪造上下文用例，§03 纪律）
- [ ] 生命周期：PENDING 超时清理；EXPIRED 后字段读取返回「文件已失效」占位
- [ ] 计量：storage.gb 日峰值 = ACTIVE 文件 SUM(size_bytes)，删除后次日下降
- [ ] 存储抽象：MinIO/OSS/LocalFs 三实现契约测试同套用例通过（接口化红线）

## 附录 A · 对外接口契约

> 前端消费方：UploadFile 物料（前端文档 05 §附件类）、头像/Logo 上传控件（文档 06FE）、导入向导（详细 PRD 01 §批量导入）、下载中心（02 §A.4 导出任务）。

### A.1 上传凭证

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/files/presign` | `{fileName, contentType, size, scope, appId?}` | `{fileId, uploadUrl, objectKey}`（预签名 10min） |
| POST | `/api/files/multipart` | 同上（size > 20MB 时） | `{fileId, uploadId, partSize: 8388608}` |
| POST | `/api/files/{fileId}/parts` | `{partNumber}` | `{partUrl}` |
| POST | `/api/files/{fileId}/complete` | `{parts?:[{partNumber, etag}], sha256?}` | `{fileId, fileName, size}` 201 |

### A.2 下载与元数据

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/files/{fileId}/url` | `{downloadUrl}`（预签名 5min，现取现用不缓存） |
| GET | `/api/files/{fileId}` | 元数据（fileName/size/contentType/status；无内容流） |
| DELETE | `/api/files/{fileId}` | 管理操作：删除对象 + 元数据（引用中的字段渲染为失效占位） |

### A.3 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `FILE_TYPE_FORBIDDEN` | 400 | 类型白名单外（魔数判定） |
| `FILE_TOO_LARGE` | 413 | 超过 scope 上限 |
| `FILE_NOT_FOUND` | 404 | fileId 不存在或跨租户（同响应不给线索） |
| `FILE_EXPIRED` | 410 | 临时文件已过期 |
| `UPLOAD_MISMATCH` | 409 | complete 时对象缺失/size 不符 |

### 前端对接要点

- UploadFile 物料封装四步直传（presign → PUT → complete → 写字段值），PUT 失败重试 3 次后报错并释放凭证；
- 分块上传进度回调：`已传块 / 总块数` 粒度（物料 props.onProgress）；
- 字段值 `{fileId, name, size}` 为平台标准附件结构，物料渲染与 data-engine 校验双端契约锁定。
