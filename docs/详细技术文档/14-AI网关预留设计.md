# 详细技术文档 14 · AI 网关（ai-gateway，P3 架构预留）

> 上游：《技术方案-后端(Java).md》v0.2 §12 Phase 3「AI 辅助建模网关」；PRD §5 三期「AI 概念预留」（功能范围未定义）；顶层 PRD 标注：**AI 为概念预留，不做功能范围承诺**
> 本文定位：**架构预留设计**——只定义骨架与必须提前守住的约束（接口化/计量/限流/审计），不定义 AI 功能范围（提示词工程、模型能力、产品交互均待需求确认后另行设计）
> 服务：`ai-gateway`（P3 独立部署；P1-P2 以接口占位 + 依赖接口化红线形式存在）
> 对接：metering-service（`ai.tokens.in/out` 指标，09 §4 已定）、网关（配额前置，06 §1.1）、L3 沙箱（未来 AI 生成代码的验证执行，08）

## 1. 为什么现在写预留设计（不做功能设计）

| 现在必须守的（后补成本极高） | 可以等到 P3 的 |
|---|---|
| LLM 供应商接口化（§11 外部依赖红线） | AI 辅助建模的功能范围与提示词 |
| 计量口径与链路（`ai.tokens.in/out` 已在 09 定死，采集点必须是网关侧服务端） | 具体模型选型与降级策略 |
| 配额硬限与限流入口（QUOTA_EXCEEDED 体系已定） | Token 精确计数的供应商差异抹平 |
| Prompt/响应不留存业务数据的合规边界 | AI 生成代码的沙箱验证流程 |
| 出网隔离（LLM API 调用必须走连接器化通道） | 应用场景（建模助手/表达式生成/页面生成…） |

**红线重申（PRD 顶层 §5 已标注）**：AI 功能一期/二期不交付；本文仅锁定骨架契约，防止 P3 启动时发现计量对不上、合规没守住、供应商耦合写死三座大山。

## 2. 架构定位

```
设计器/运行时（AI 面板，P3 前不存在）
        ↓ ①
gateway（QuotaFilter：ai.tokens 硬限前置扣减预估，06 §1.1）
        ↓ ②
ai-gateway（本服务：会话管理 + Prompt 组装 + 供应商路由 + 计量采集）
        ↓ ③
LLM Provider Adapter（接口化，禁止业务代码直连 OpenAI/千问/…SDK）
```

- ai-gateway 是**平台封装层**而非透传代理：租户不接触供应商密钥（密钥是平台的，成本通过配额/计价转售）；Prompt 模板、上下文裁剪、输出校验都在这层；
- 与 L4 连接器的边界：LLM 调用**不走**客户自建连接器（连接器是客户出站场景）；ai-gateway 用平台级供应商凭证，走独立的 Provider Adapter 接口（同为 §11 接口化纪律）。

## 3. Provider 接口化（P1-P2 就要存在的接口定义）

```java
public interface LlmProvider {                 // 平台级 SPI，实现可插拔
    String providerKey();                      // openai / qwen / deepseek / ...
    ChatResponse chat(ChatRequest req);        // 同步补全
    Flux<ChatChunk> chatStream(ChatRequest req); // 流式（SSE，设计器打字机效果）
    UsageReport usage();                       // token 计数（prompt/completion）
}
// P1-P2：接口 + NoopProvider（所有调用返回 503 AI_NOT_AVAILABLE）进代码库；
// CI 保证业务代码对 AI 的依赖只有此接口（依赖扫描同 §11 红线）
```

## 4. 计量与配额对接（契约已冻结部分）

| 契约项 | 已冻结定义 | 本文补充 |
|---|---|---|
| 指标 | `ai.tokens.in` / `ai.tokens.out`（09 §4） | in = prompt tokens，out = completion tokens；按供应商 usage 字段归一（无 usage 返回的供应商按字符近似并标记 `approx:true`） |
| 采集点 | AI 网关服务端（09 §4 表） | 每次 chat 完成投递计量事件，attrs 白名单：`{provider, model, appId, sessionId}`——禁 Prompt 内容与输出内容 |
| 配额 | 硬限（09 §6：超限拒绝 + QUOTA_EXCEEDED） | 前置预估扣减（按 Prompt 字符近似）+ 完成后按实际 usage 校准（多退少补）；流式响应超限中断推流 |
| 归属日 | 调用日（occurred_at，09 §4） | — |

## 5. 安全与合规边界（P3 启动前不可破坏）

| 边界 | 规则 |
|---|---|
| 数据出域 | Prompt 组装只允许携带：Schema 定义（模型/字段元数据）、用户显式输入。**禁止**携带业务记录值（数据行内容）——客户数据出域需租户显式签约同意，一期直接不做 |
| 留存策略 | Prompt/响应默认零留存（过内存即弃）；调试采样需租户管理员开启且独立审计；日志只记 `{sessionId, tokens, duration, provider, model}` |
| 生成代码 | AI 产出代码（L2 钩子/L3 脚本）一律按逃生舱既有闸门执行：L2 走前端三道闸（08FE）、L3 走沙箱六闸（08）——AI 产出不豁免任何安全检查 |
| 出网 | Provider Adapter 出网走平台统一出网通道（与 L4 连接器共用 SSRF 管线基础设施，域名白名单为供应商官方域名） |
| 审计 | 每次 AI 调用记审计事件（AI_CALL：谁/哪个应用/多少 token）——出账争议与滥用追溯 |

## 6. 单元测试硬性要求（P3 实现时；接口定义期先锁骨架测试）

- [ ] NoopProvider：P1-P2 任何路径调用 AI 接口返回 `503 AI_NOT_AVAILABLE`（依赖扫描断言无直连 SDK）
- [ ] 计量归一：无 usage 字段的供应商输出按近似计数且 `approx:true`；in/out 不串号
- [ ] 预估配额：超限请求在进入供应商前被拒（QUOTA_EXCEEDED + 升级 payload，06 错误协议）
- [ ] 流式中断：流式响应途中配额耗尽 → 立即断流 + 已产生 token 照常计量
- [ ] 合规：Prompt 组装含业务记录值的代码路径断言失败（构造性测试）；attrs 含 Prompt 内容的计量事件被白名单拒绝（09 合规红线）
- [ ] 审计：AI_CALL 事件全字段落审计（不含 Prompt 内容）

## 附录 A · 骨架接口契约（P3 实现时冻结，先发布占位）

> 前端消费方：P3 前无消费方；接口定义进 OpenAPI 供类型生成预埋。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/ai/chat` | `{sessionId, appId, scene, messages:[{role, content}], stream?: false}` | `{content, usage:{in, out, approx?}}`（P3 前恒 503） |
| POST | `/api/ai/chat/stream` | 同上（`stream: true`） | SSE 事件流（P3 定义） |
| GET | `/api/ai/quota` | — | `{usedTokens, limit, resetAt}`（复用 09 §A.3 配额协议） |

| code | HTTP | 场景 |
|---|---|---|
| `AI_NOT_AVAILABLE` | 503 | P1-P2 占位期（NoopProvider） |
| `AI_QUOTA_EXCEEDED` | 429 | 硬限拦截（转标准 QUOTA_EXCEEDED payload，06 错误协议） |
| `AI_SCENE_INVALID` | 400 | scene 不在已开放场景清单（P3 需求确认后维护） |
