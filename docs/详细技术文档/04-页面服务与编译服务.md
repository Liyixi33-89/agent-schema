# 详细技术文档 04 · 页面服务与代码编译服务（page-service / build-service）

> 上游：《技术方案-后端(Java).md》v0.2 §3.4；PRD §3.2/§3.6、§6.2（双轨渲染决策）
> 本文定位：实现级技术设计——Schema 存储、发布快照、编译 Worker 池、产物管理
> 服务：`page-service`、`build-service`（Node Worker 池）

---

## 1. page-service

### 1.1 职责

- 页面 PageSchema 的草稿/发布态 CRUD 与版本管理；
- 发布快照生成与回滚（继承 §06 运行时机制）；
- 编辑锁（Redis）、自动保存草稿；
- 字段引用上报 metadata-service（影响面分析数据源）。

### 1.2 表结构

```sql
CREATE TABLE page_schema (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT NOT NULL, app_id BIGINT NOT NULL,
  page_key VARCHAR(64) NOT NULL, name VARCHAR(128),
  page_type VARCHAR(16),             -- FORM / LIST / DETAIL / DASHBOARD
  model_id BIGINT,
  path VARCHAR(256) NOT NULL,        -- 路由路径，租户内唯一
  draft JSONB NOT NULL,              -- 设计器编辑态
  draft_version INT NOT NULL,        -- 草稿版本（自动保存/手动保存点递增）
  published JSONB,                   -- 运行时读取态（未发布为 NULL）
  published_version INT,             -- ETag/If-None-Match 用
  artifact_hash VARCHAR(64),         -- 自定义代码产物（轨道 B）
  schema_etag VARCHAR(64),           -- = published_version 的 hash
  status VARCHAR(16) NOT NULL,       -- ACTIVE / DELETED
  updated_by BIGINT, updated_at TIMESTAMPTZ,
  UNIQUE (tenant_id, app_id, page_key)
);
CREATE INDEX idx_page_path ON page_schema(tenant_id, path);

-- 发布快照（应用级，发布时聚合页面/模型引用/产物hash）
CREATE TABLE app_release (
  id BIGSERIAL PRIMARY KEY, tenant_id BIGINT, app_id BIGINT,
  release_version INT NOT NULL,
  snapshot JSONB NOT NULL,           -- {pages:[{pageId, schemaVersion, artifactHash}], modelRefs:[...]}
  changelog JSONB, operator_id BIGINT, created_at TIMESTAMPTZ,
  status VARCHAR(16),                -- ACTIVE / ROLLED_BACK
  UNIQUE (app_id, release_version)
);
```

### 1.3 发布与回滚流程

```
发布：
  1. 校验编辑锁释放（不允许发布他人持锁草稿）
  2. draft → published 全量拷贝；published_version++
  3. 生成 app_release 快照（页面清单 + 模型引用版本 + 产物 hash）
  4. 缓存失效：Redis 删 page:{tenantId}:{pageId}，广播 schema:invalidate
  → 运行时 ETag 失效，下次请求拉新版（发布不发版）

回滚：
  选历史 release → 其页面快照回写 published → 版本继续递增（回滚也是一次"发布"）
```

### 1.4 运行时读取接口

```
GET /api/runtime/pages/{pageId}
Headers: If-None-Match: "v12"
→ 304（未变） 或 200 + 新 schema + ETag: "v13"
```

- 响应含权限过滤后的可绑定字段元数据摘要（页面渲染需要）；运行时容器侧缓存（内存 + HTTP）。

### 1.5 编辑锁

```
Redis: lock:PAGE:{pageId} = {userId, sessionId, acquiredAt} EX 30（心跳续期）
掉线 60s 自动释放；强制解锁（管理员）记审计；
被解锁者保存时 baseVersion 比对 → 409 冲突 → 前端三方对比（我的/他的/合并起点）
```

## 2. build-service（自定义代码编译，轨道 B）

### 2.1 架构

```
build-service (Java 调度层)
  ├─ 任务表管理 / 配额 / 审计 / 版本记录
  └─ HTTP → Node Worker 池（独立容器组，K8s HPA 按队列深度扩缩容）
             └─ esbuild 编译（不执行客户代码）
```

**铁律：Java 进程绝不运行 JS 工具链**（内存/线程模型完全不匹配）；编译过程**绝不执行**客户代码（只做语法转换与打包）。

### 2.2 接口

```java
public interface CodeBuildService {
    BuildResult build(BuildRequest req);
}

class BuildRequest {
    Long tenantId; Long appId; Long pageId;
    String sourceCode;          // TS/JSX
    String runtimeVersion;      // 平台 SDK 版本 → 决定 tsconfig/lib/白名单依赖
    Boolean enableArtifact      // 产物是否入库
}

class BuildResult {
    boolean success;
    String artifactUrl;         // 对象存储 URL: artifacts/{tenantId}/{contentHash}.js
    String contentHash;         // SHA-256
    List<CompileError> errors;  // 失败时：行号/列号/原因
}
```

### 2.3 编译流水线

```
① 静态安全扫描（编译前置，红线不通过直接拒绝）：
   禁：window/document/localStorage 直接访问
   禁：fetch/XMLHttpRequest/动态 import()
   禁：process/require/Node API
   禁：未在白名单的 npm import（仅平台 SDK + 白名单库清单）
   实现：esbuild 前跑 AST 扫描（acorn/ts-morph），命中即返回 CompileError(SECURITY_BLOCKED)

② esbuild 打包：
   format=esm, target=es2020, minify, bundle
   外部依赖：白名单库以 pre-bundle 形式注入，产物只含客户代码

③ 产物校验：
   必须导出约定的 render(ctx) 或 default 组件；
   size 上限（如 2MB）与构建时长上限（10s）超限失败

④ 产物上传：
   对象存储 artifacts/{tenantId}/{sha256}.js —— contentHash 命名天然去重与不可变
   （同代码多次保存不产生新对象；URL 长缓存 immutable）

⑤ 结果落库：
   成功 → page_schema.artifact_hash 更新 → 线上下一版生效
   失败 → artifact_hash 不更新（线上继续跑上一版）→ 错误返回设计器展示
```

### 2.4 任务表与配额

```sql
CREATE TABLE build_task (
  id BIGSERIAL, tenant_id BIGINT, app_id BIGINT, page_id BIGINT,
  source_hash VARCHAR(64), content_hash VARCHAR(64),
  status VARCHAR(16),        -- QUEUED / RUNNING / SUCCESS / FAILED / SECURITY_BLOCKED
  errors JSONB, duration_ms INT,
  created_at TIMESTAMPTZ,
  UNIQUE (tenant_id, source_hash)      -- 同源码幂等：直接复用上次产物
);
```

- 单租户并发上限（如 2）+ 队列隔离：高频保存打不爆构建集群；
- `build.count` 计量投递（护栏档位，§09）；
- Worker 池按队列深度 HPA；构建日志（编译器输出）保留 30 天供排障。

### 2.5 CSP 与运行时加载约定

- 前端 CSP：`script-src 'self'` + **禁 `unsafe-eval`**——运行时字符串编译在浏览器侧根本不可行，架构上强制"预编译产物"路线；
- 产物加载：`import(artifactUrl)`，带 3 次重试；失败节点级 ErrorBoundary 占位（不白屏）；
- 页面 Schema 记录 `artifactHash`：可审计"线上跑的是哪版代码"，回滚快照亦包含它。

## 3. 双轨边界回顾（决策 §6.2）

| | 轨道 A 动态解析 | 轨道 B 编译产物 |
|---|---|---|
| 适用 | 默认组件 + 物料协议组件（propsSchema 可描述） | 客户手写源码（需逻辑/操作 DOM） |
| 发布 | 改 Schema 即时生效（不发版） | 保存即编译，产物 hash 更新 |
| 失败表现 | 表达式错误设计态阻断 | 编译失败线上跑旧版 |
| 统一点 | 均经 `MaterialMeta.runtime` 字段分派；NodeRenderer 单入口 | 同左 |

## 4. 单元测试硬性要求

- [ ] 发布后运行时接口返回新版 ETag；未发布 draft 不影响 published 读取
- [ ] 回滚 = 新发布版本，快照含 artifactHash
- [ ] 编辑锁：心跳超时释放、强制解锁记审计、baseVersion 冲突 409
- [ ] 编译红线：window/fetch/未白名单 import 各样本构建返回 SECURITY_BLOCKED
- [ ] 编译失败不更新 artifact_hash（线上版本不变）
- [ ] 同源码幂等：第二次构建复用产物，不产生新对象

## 附录 A · 对外接口契约

> 前端消费方：设计器保存/发布（前端文档 04FE）、运行时容器 Schema 拉取（文档 06FE §3）、L2 脚本编辑器保存（文档 08FE §2）、轨道 B 产物加载（文档 02FE §3）。

### A.1 页面 CRUD 与草稿

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/pages?appId=&keyword=` | — | `{list:[{id, pageKey, name, type, path, status, updatedAt}]}` |
| POST | `/api/pages` | `{appId, pageKey, name, type, modelId?, path, generateFromModel?}` | `{id}`（generateFromModel=true 走默认页生成） |
| GET | `/api/pages/{id}/draft` | — | `{schema(PageSchema), draftVersion}` |
| PUT | `/api/pages/{id}/draft` | `{schema, baseDraftVersion}` | `{draftVersion}` 或 `409 {serverDraftVersion}`（自动保存/手动保存同接口） |
| DELETE | `/api/pages/{id}` | — | `{}` 200（二次确认在前端；被菜单引用时返回 `{menuRefs[]}` 提示） |
| PUT | `/api/pages/{id}/path` | `{path, name?}` | `{}`（租户内唯一性校验，冲突 422） |

### A.2 发布与回滚

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/apps/{appId}/publish` | `{pageIds[], changelog?}` | `{releaseVersion}`（校验编辑锁已释放） |
| GET | `/api/apps/{appId}/releases` | — | `{list:[{releaseVersion, changelog, operator, createdAt, status}]}` |
| POST | `/api/apps/{appId}/rollback` | `{targetReleaseVersion}` | `{releaseVersion}`（回滚也是一次发布） |

### A.3 编辑锁

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/pages/{id}/lock` | 获取锁；已被持 → `409 {holder:{userId, name, acquiredAt}}` |
| POST | `/api/pages/{id}/lock/heartbeat` | 续期 30s；掉线 60s 自动释放 |
| DELETE | `/api/pages/{id}/lock` | 释放；强制解锁（管理员）记审计 |

### A.4 运行时读取（发布态，ETag 协议）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/runtime/apps/current` | 应用清单 `{pages:[{pageId, path, name, perm}], menus}`（运行时路由生成唯一来源） |
| GET | `/api/runtime/pages/{pageId}` | `If-None-Match: "v12"` → 304 或 `200 + published Schema + ETag: "v13"`；响应含权限过滤后的字段元数据摘要 |

### A.5 代码编译（轨道 B / L2 脚本共用构建服务）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/build/pages/{pageId}/code` | `{sourceCode(TS/JSX), runtimeVersion}` | 成功 `{artifactUrl, contentHash}`；失败 `{errors:[{line, column, message, code?}]}` 且 `SECURITY_BLOCKED` 时含 `code` |
| GET | `/api/build/tasks/{taskId}` | — | `{status:'QUEUED'|'RUNNING'|'SUCCESS'|'FAILED'|'SECURITY_BLOCKED', errors?, artifactUrl?, contentHash?}`（前端轮询） |

- 同源码幂等：服务端按 source_hash 复用产物（§2.4），前端无需去重；
- 编译失败**不更新** `page_schema.artifact_hash`——线上继续跑旧版（§2.3⑤）。

### A.6 错误码（本域）

| code | HTTP | 场景 |
|---|---|---|
| `LOCK_HELD_BY_OTHER` | 409 | 编辑锁被持有（响应含持锁人） |
| `DRAFT_VERSION_CONFLICT` | 409 | 草稿 baseVersion 过期（三方对比流程） |
| `PATH_DUPLICATED` | 422 | 路径租户内唯一性冲突 |
| `SECURITY_BLOCKED` | 422 | 编译红线命中（errors 内含规则标识） |
| `BUILD_QUOTA_EXCEEDED` | 429 | 单租户并发构建上限（§2.4） |

### 前端对接要点

- 运行时三层缓存 + `If-None-Match` 消费见前端文档 06FE §3（304 不重渲染，发布广播失效）；
- 保存流程「PUT draft → 409 → 三方对比」交互见前端文档 04FE §7；
- 轨道 B 加载：`artifactUrl` 即 `import()` 目标（contentHash 长缓存 immutable），失败 3 次重试后 ErrorBoundary 占位（前端文档 02FE §3）。
