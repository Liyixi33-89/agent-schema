# 详细PRD 09 · 运营与计量

> 上游文档：《PRD-低代码平台产品规划》v0.2 §3.9 + §8（计费与计量体系）
> 本文定位：功能操作级 PRD——入口、界面、操作步骤、配置项、规则与反馈
> 交付阶段：Phase 1（**埋点全量采集，不出账**），Phase 2（配额护栏 + 报表），Phase 3（出账 + 单位经济）

---

## 1. 模块概述

### 1.1 是什么

四类能力递进：

1. **用量计量**（Metering）——席位/流程执行/AI/存储/API 的精确采集（计费与客户成功的数据底座）；
2. **系统监控**——接口/错误/慢查询的技术健康度；
3. **用户行为分析**——页面使用率、功能触达（产品决策依据）；
4. **商业化报表**——漏斗/NRR/配额饱和度（销售线索与定价校准）。

**核心原则（PRD §8.5）**：MVP 只埋点不出账，但采集从第一天全量开启——**计费历史无法回溯补录**。

### 1.2 服务角色

| 角色 | 触点 |
|---|---|
| 租户管理员 | 控制台「用量」页：席位/配额/趋势 |
| 平台运营 | 内部大盘：饱和度榜、异常告警、行为漏斗 |
| 财务 | P3 账单/明细/对账 |

### 1.3 入口

- 租户侧：控制台 →「用量与配额」
- 平台侧：内部运营后台（不对外开放）

## 2. 页面与操作明细

### 2.1 计量指标字典（计费口径类）

| metric | 口径 | 采集点 |
|---|---|---|
| `seat.active` | 当日有**设计器写操作**的账号（仅登录不算）；月活 = 当月任一天出现 | 前端埋 + 服务端终审 |
| `flow.exec` | 流程实例完成执行（触发条件不满足不计；平台故障不计、客户逻辑失败计） | flow-service 服务端 |
| `ai.tokens.in/out` | AI 能力 token 消耗 | AI 网关服务端 |
| `api.calls` | 开放 API 调用成功数 | 网关服务端 |
| `storage.gb` | 对象存储日峰值 | 定时任务 |
| `build.count` | 自定义代码编译次数（护栏） | build-service |

**采集链路约束**：

- 前端事件可被伪造——**计费指标一律以服务端埋点为准**，前端数据仅用于漏斗分析；
- payload 白名单：只允许 ID/枚举/数值，**禁止任何业务字段值**（合规红线）；
- 时间归属用客户端 occurred_at 但限回溯 24h，超出按 received_at（防跨月逃配额）。

### 2.2 租户控制台「用量与配额」页

**用量总览卡片**：当前席位数/上限、本月流程执行/配额、AI 额度余量、存储与 API 调用量。

**席位明细**：成员列表 + 各自 30 天活跃状态——管理员可**清理不活跃席位**降低成本（活跃计费口径给客户可控感）。

**趋势图**：近 90 天各指标曲线。

### 2.3 配额护栏（P2）

| 配额 | 限额类型 | 超限行为 |
|---|---|---|
| 活跃席位 | 硬限 | 新成员加入设计器角色被拒 + 引导升级 |
| 应用数 | 软限 | 可继续创建，顶部横幅提示 + 宽限 7 天 |
| 流程执行/月 | 硬限 | 触发器暂停（进行中实例跑完），提示 + 升级入口 |
| AI 额度 | 硬限 | AI 功能返回 `QUOTA_EXCEEDED` + 升级引导 |
| 存储 | 软限 | 上传限流提示，宽限后降速 |
| 开放 API | 硬限 | 429 + Retry-After |

- 配额检查统一在网关/执行器前置层（原子扣减），**禁止业务代码散落判断**；
- 错误码 `QUOTA_EXCEEDED` 与业务错误严格区分，响应带升级链接；
- 配额触达 80%/100%/宽限期均发通知给租户管理员。

### 2.4 平台运营内部报表

**商业化线索**：

- 配额饱和度榜：饱和度 ≥ 80% 的租户清单（排序：饱和度 × 席位数）→ 销售/CSM 跟进队列；
- 空闲租户榜：付费但席位活跃 < 20% → 流失预警，触发 CS 介入；
- 指标异常：环比突增 > 300% 告警（刷量或业务暴涨都需人工确认）。

**行为分析**：

- 页面 PV/UV（按应用/页面）；物料使用频次（指导物料库建设优先级）；
- 功能触达漏斗：建模 → 生成页面 → 发布 → 活跃使用的衰减率——**产品北极星过程指标**。

### 2.5 防薅检测（P2）

| 检测 | 规则 | 处置 |
|---|---|---|
| 共享账号 | 同席位多 IP/多设备高频切换（1h 内 > 3 地域跳变） | 记录 + 管理员报表提醒（不自动封禁，避免误伤出差） |
| AI 刷量 | 单租户 token 环比突增 > 500% 且无席位增长 | 限流 + 人工审核队列 |
| 脚本刷流程 | 执行 QPS 异常 + 触发源集中单一 API Key | 限流 + 通知 |
| 欠费未停 | 账单逾期清单 | T+7 宽限 → 只读模式 → T+30 停服（全程通知） |

### 2.6 系统监控

- 技术大盘：接口 P95 延迟、错误率、可用性（SLA 99.9% 日检）、慢查询 TopN、DDL 任务队列积压；
- **租户级健康页**（客户自助排障入口，减少工单）：该租户接口错误率、失败流程实例、编译失败记录；
- 监控栈为内部能力，不作为对外产品界面。

### 2.7 出账（P3）

- 账单生成：月度定时任务读日聚合 × 价格表 → **不可变账单快照**（出账后不再重算，纠错走「账单调整」单据流）；
- 明细下钻：账单 → 指标 → 日 → 事件来源（哪个用户/应用/流程）——**计费争议的终结者**；
- 预付额度包：购买记录 + 12 个月结转 + 不可退现；
- 发票/对账单导出（含审计）。

## 3. 业务规则汇总

| # | 规则 | 来源 |
|---|---|---|
| R1 | MVP 只埋点不出账；采集第一天全量开启 | 决策 §8.5 |
| R2 | 计费指标以服务端埋点为准，前端仅漏斗分析 | §2.1 |
| R3 | 席位活跃 = 30 天内有设计器写操作（仅登录不算） | §2.1 |
| R4 | 流程触发条件不满足不计执行；平台故障不计、客户逻辑失败计 | §03/§09 |
| R5 | 配额检查前置统一，禁止业务代码散落判断 | §2.3 |
| R6 | 出账后账单不可变，纠错走调整单据 | §2.7 |
| R7 | 计量 payload 禁止业务字段值（合规红线） | §2.1 |

## 4. 权限点

| 权限点 | 说明 |
|---|---|
| 用量查看 | 租户管理员（席位明细含个人信息需权限） |
| 配额管理 | 平台侧配置；租户侧只读 |
| 内部运营报表 | 仅平台运营角色 |

---

## 5. 验收标准

- [ ] P1 上线即有全部计量指标日聚合数据；历史日可从明细重算且一致
- [ ] 席位口径：成员仅登录设计器不产生 seat.active；任意写操作当日计入
- [ ] 流程触发条件不满足的实例不产生 flow.exec 计量
- [ ] 前端伪造的 seat.active 事件不影响服务端口径统计
- [ ] 配额超限返回独立错误码且带升级链接；宽限期通知触达管理员
- [ ] 共享账号检测只提醒不自动封禁
- [ ] P3：任一账单金额可下钻到事件级明细；账单调整不改历史快照

---

## 6. 边界与不做的事

- 实时计量（全部 T+0 日聚合粒度，实时仅用于限流判断）
- 按标签的用量分摊（部门级成本分摊）—— P3
- 对外用量查询 API —— P3
- 多币种/税务计算 —— P3（随商业化地区决策）
