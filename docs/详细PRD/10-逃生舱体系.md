# 详细PRD 10 · 逃生舱体系

> 上游文档：《PRD-低代码平台产品规划》v0.2 §7（分级开放边界）、决策 §6.4
> 本文定位：功能操作级 PRD——入口、界面、操作步骤、配置项、规则与反馈
> 交付阶段：L1/L2 = Phase 1，L4 = Phase 2，L3 = Phase 3（企业版默认关闭）

---

## 1. 模块概述

### 1.1 是什么

**核心原则：边界不按「前端/后端」划，按「这段代码能拖垮谁」划。**

| 级别 | 形态 | 影响半径 | 开放对象 | 阶段 |
|---|---|---|---|---|
| L1 表达式 | `{{ }}` 无副作用 | 单字段 | 全员 | P1 |
| L2 前端钩子脚本 | 页面级 JS 钩子 | 单页面 | 业务开发者 | P1 |
| L4 外部服务连接器 | 客户自有 HTTP 服务 | 平台外 | 企业客户 | P2 |
| L3 后端受管函数 | 沙箱脚本节点 | 可影响平台 | 高级开发者（申请制） | P3 |

配套机制：**反向收编**——高频脚本模式定期沉淀为配置能力，长期控脚本量。

### 1.2 设计立场

- 优先级：**L4 先于 L3**（客户自建服务当连接器，扩展成本由客户基建买单，平台不担安全责任）；
- L2 不开放「随便写 JS」，只开放一套**窄而稳的钩子契约**（开放性体现在覆盖场景，而非 API 面积）；
- 红线靠**代码强制**，不靠文档约定。

---

## 2. L1 表达式（P1）

### 2.1 场景与入口

场景：显隐/禁用/必填条件、计算字段、校验规则、流程分支、数据权限自定义规则。
入口：各配置处的表达式输入框（设计态即时报错）。

```
{{ amount > 10000 }}
{{ status === 'draft' && dept === 'sales' }}
{{ DATE.now() - createdAt > 7 * 86400000 }}
{{ CONCAT(firstName, '·', lastName) }}
```

### 2.2 使用规则

- 白名单函数约 20 个：日期（now/dateDiff/format）、字符串（concat/upper/lower/replace/split）、数值（round/abs）、集合（includes/length）——逐版本评审增补；
- 无 IO、无副作用、执行步数上限 1000（防死循环）；
- **设计态即时校验**：语法错、引用字段不存在/已删除、类型不匹配（`string > number`）立即标红含原因，保存阻断；
- 保存时静态分析产出 `dependsOn` 存入 Schema（供影响面分析与字段级订阅）。

## 3. L2 前端钩子脚本（P1）

### 3.1 钩子契约

入口：页面设计器 → 属性面板「脚本」区 → 脚本编辑器（Monaco）+ **脚本测试台**。

```js
async function beforeSubmit(ctx) {
  if (ctx.form.get('amount') > 100000 && !ctx.form.get('attachment')) {
    ctx.ui.toast('大额申请必须上传附件', 'error');
    return false;                      // 阻断提交
  }
  const dept = await ctx.api.call('getDeptBudget', { deptId: ctx.user.dept });
  ctx.form.set('budgetLeft', dept.left);
}
```

可用钩子：`onLoad / onFieldChange(fieldKey, value) / beforeSubmit / afterSubmit(result) / onActionClick(actionKey) / onBeforeDelete(record)`。

### 3.2 受控 ctx 能力表

| 能力 | 说明 |
|---|---|
| `ctx.form.get/set/getValues/setValues` | 仅当前表单（写入触发引擎联动重渲染） |
| `ctx.api.call(name, params)` | 仅平台已注册 API/流程（统一网关，继承用户权限） |
| `ctx.ui.toast/confirm/dialog` | UI 交互 |
| `ctx.logger.info/warn/error` | **强制提供**：自动带 pageId/traceId/脚本版本上报（否则客户用 console，线上问题不可查） |
| `ctx.user` | 只读脱敏（id/roles/dept，无手机号邮箱） |
| `ctx.page.params/query/mode` | 页面上下文 |

### 3.3 红线与强制手段（靠代码不靠文档）

| 红线 | 强制手段 |
|---|---|
| `window`/`document`/DOM 操作 | 构建期静态扫描拒绝 + 运行时不注入全局 |
| 原生 `fetch`/`XMLHttpRequest`/动态 `import()` | 静态扫描拒绝；外部调用只能走 `ctx.api`（保住网关的鉴权/审计/限流/密钥托管） |
| `localStorage` 裸访问 | 不注入；用户偏好走平台封装 API |
| 读他人/他租户数据 | `ctx.api` 服务端鉴权兜底（前端隔离不可信） |
| 死循环卡页面 | 钩子 500ms 超时告警 + AbortSignal 硬中断（10s） |

### 3.4 配套体验（上线前置条件）

- **脚本测试台**：右侧抽屉 Monaco + mock ctx（可编辑 form/user/params 样例），一键运行看日志/返回值/耗时/报错堆栈；
- **执行日志面板**：按钩子分组展示最近真实执行（耗时/异常），客户自助排障；
- 脚本报错**不白屏**：节点级降级 + ErrorBoundary 包裹 + 上报；
- 脚本 API 语义化版本 + **12 个月兼容承诺**；`ctx` 接口变更提前公告。

## 4. L4 外部服务连接器（P2，优先于 L3）

**理由**：平台只做「HTTP 代理 + 密钥托管 + 日志重放」，客户用任何语言/算力，扩展成本由客户基建买单。

### 4.1 产品能力

- 创建向导（详见 §05 §2.6）：基本信息 → 鉴权（NONE/BASIC/BEARER/HMAC/OAuth2）→ 动作定义 → **字段映射可视化连线** → 测试调用 → 保存；
- 流程编排中作为动作节点被引用（参数用 L1 表达式引用流程上下文）；
- 调用日志：最近 500 次（密钥无条件脱敏）、耗时、状态；失败一键重放（非幂等需显式确认）。

### 4.2 工程红线

- **SSRF 防护**：域名白名单管理员审批；DNS 解析后校验真实 IP（防 rebinding）；禁 30x 跳内网；内网 CIDR 全黑名单；
- 密钥 KMS 加密存储，只存 secretRef；日志按敏感字段配置脱敏（Header/URL query 同样）；
- 超时默认 3s/10s；仅幂等方法自动重试（指数退避 + 抖动）；
- 单连接 QPS/日配额（计入护栏档位）；
- **一期只做出站**，入站 Webhook 托管 P3。

## 5. L3 后端受管函数（P3，企业版默认关闭）

**本质：自建轻量 FaaS。六道闸门缺一不可：**

1. **进程隔离**：独立执行器（GraalVM 受限 Context 或独立 Pod）；**绝不在主应用 eval 客户代码**；
2. **资源上限**：5s 硬超时 / 256MB 内存 / CPU 上限；出网白名单默认全禁；
3. **数据访问走封装接口**：只能调 dataEngine 封装接口，**透传调用者租户+角色上下文，SQL 层二次校验数据权限**（最易忽略的越权入口）；
4. **可观测**：每次执行落 `script_exec_log`（traceId/耗时/错误），客户控制台自查；
5. **版本灰度**：DRAFT/PUBLISHED/CANARY 状态机；线上改动审核 + 10% 灰度 + 一键回滚；
6. **计费配额**：执行计入 flow.exec 类计量；单租户并发上限（防死循环拖垮平台）。

- 序列化边界：入参/ctx 深拷贝 + JSON 序列化（防拿 Java 对象引用反射逃逸）；
- **默认关闭的产品理由**：迫使客户先评估 L4 是否够用；开通需企业版 + 书面确认责任边界（脚本正确性客户自担）。

## 6. 反向收编策略（长期机制）

| 动作 | 说明 | 周期 |
|---|---|---|
| 脚本模式扫描 | 识别高频模式（金额阈值/日期计算/字段拼接/跨字段比较）→ 沉淀为内置函数、公式库、可视化条件配置器 | 季度 |
| API 使用统计 | 低使用率 API 阻碍重构 → 公告迁移 → 下线（12 个月兼容承诺期内） | 半年 |
| 合同边界 | 脚本正确性与安全客户自担；平台保证执行环境隔离与版本兼容 | 签约时 |

**产品北极星过程指标**：L2 脚本渗透率（含脚本的页面占比）应随平台成熟**下降**而非上升——上升说明声明式能力欠账。

## 7. 业务规则汇总

| # | 规则 | 来源 |
|---|---|---|
| R1 | 边界按影响半径划，不按前后端划 | §1.1 |
| R2 | L1 禁 eval/new Function，受限 AST 解释器 + 白名单函数 | §2.2 |
| R3 | L2 红线靠构建期静态扫描 + 运行时不注入强制 | §3.3 |
| R4 | L2 外部调用只能走 ctx.api（保网关鉴权/审计/限流） | §3.3 |
| R5 | L4 只做出站；域名白名单审批制 | §4.2 |
| R6 | L3 六道闸门缺一不可；默认关闭 | §5 |
| R7 | 脚本 API 12 个月兼容承诺 | §3.4 |

## 8. 权限点

| 权限点 | 说明 |
|---|---|
| L1 使用 | 全员默认 |
| L2 编写 | 页面设计权限即有 |

## 9. 验收标准

- [ ] L1：表达式引用已删除字段在设计态被阻断；运行时依赖订阅正确且无整页重渲染
- [ ] L2：测试台 mock 运行结果与线上一致；含 `fetch`/`document` 的脚本保存被拒
- [ ] L2：`beforeSubmit` 返回 false 阻断提交；脚本抛错页面不白屏且日志可查
- [ ] L2：脚本执行超 10s 被硬中断，500ms 告警日志可查
- [ ] L4：指向内网 IP 的连接器创建被拒；调用日志密钥全脱敏；失败可重放
- [ ] L3（P3）：脚本执行超时被硬中断；数据访问被数据权限过滤（用无权限用户跑脚本验证）
- [ ] 收编：季度报告输出脚本模式统计与内置函数候补清单

---

## 10. 边界与不做的事

- L2 脚本的 npm 依赖支持（只允许平台 SDK + 白名单库）
- L3 的 Python/Java 多语言（先 JS 单语言）
- 脚本市场/共享（脚本归属应用，不做跨租户流转）
- 入站 Webhook 托管（P3 安全评审后开放）
