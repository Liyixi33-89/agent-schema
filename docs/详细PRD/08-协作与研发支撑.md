# 详细PRD 08 · 协作与研发支撑

> 上游文档：《PRD-低代码平台产品规划》v0.2 §3.8
> 本文定位：功能操作级 PRD——入口、界面、操作步骤、配置项、规则与反馈
> 交付阶段：Phase 1（编辑锁 + 预览 + 自动保存），Phase 2（变更通知 + 发布审批 + 草稿版本 + 物料市场），Phase 3（实时协同 CRDT）

---

## 1. 模块概述

### 1.1 是什么

多人同时在平台搭建时会互相踩踏：A 在改页面布局、B 在改同一页面、C 刚把模型字段删了。本模块提供**协作秩序**：编辑锁防覆盖、变更通知知会、发布审批控生产、物料市场扩生态。

协作复杂度刻意分两步走：**P2 先做「悲观锁 + 冲突提示」**（成本低、心智简单）；**CRDT 实时协同放 P3**（价值高但工程量大，验证 PMF 后投入）。

### 1.2 服务角色

| 角色 | 在本模块做什么 |
|---|---|
| 开发者（协作方） | 被编辑锁约束；收到变更通知 |
| 应用管理员 | 强制解锁、发布审批 |
| 租户开发者 | 上架自定义物料 |

## 2. 功能与操作明细

### 2.1 资源编辑锁

- **粒度**：页面按 pageId、模型按 modelId、流程按 flowId；不同资源互不阻塞（A 改页面、B 改模型可并行）；
- **获取**：进入设计器时自动申请；持锁心跳 30s，掉线 60s 后锁自动释放（防"死锁"）；
- **他人持锁时**：页面顶部横幅「XXX 正在编辑（开始于 xx:xx）」+「申请接管」按钮 → 持锁人收到弹窗，60s 未响应自动移交；
- **强制解锁**：应用管理员可强制解锁（记审计）；被解锁者后续保存触发**版本冲突检测**（baseVersion 不匹配弹三方对比：我的/他的/合并起点）。

### 2.2 自动保存与草稿版本（P1 自动保存 / P2 版本列表）

- 自动保存草稿：30s 节流；浏览器崩溃后重开恢复最近草稿；
- 手动保存点：可命名（如「双十一布局前」）；
- 版本列表（P2）：时间线 + 操作人 + 变更摘要（节点数增减、字段 diff 数）；
- 对比视图（P2）：布局树 diff（新增/删除/移动节点高亮）+ 属性变更表；**不做字段级合并**（复杂度过高，恢复旧版覆盖即可）。

### 2.3 变更通知（P2）

| 事件 | 通知对象 | 内容 |
|---|---|---|
| 模型 Schema 变更（删字段/改类型） | 引用该模型的所有应用开发者 | 字段 + 影响页面清单链接 |
| 页面被他人接管/强制解锁 | 原持锁人 | 操作人与时间 |
| 发布/回滚 | 应用成员 | 版本、操作人、变更摘要 |
| 审批结果 | 申请人 | 通过/驳回 + 意见 |
| 连接器密钥即将过期 | 创建人 | 7 天/1 天两档提醒 |

- 渠道：站内信中心（P1 已有）+ 可选邮件（P2 开关）；
- 防轰炸：按「资源 + 用户」聚合，5 分钟窗口合并。

### 2.4 发布审批（P2）

- 触发条件：目标环境 = **生产**（测试环境免审，保持迭代速度）；
- 审批人：应用管理员（可配多人，任一通过即通过）；
- 审批内容：发布版本 diff 摘要（页面清单、模型变更清单、自定义代码变更清单）+ 申请人备注；
- 超时策略：48h 未审批自动提醒，7 天未处理自动过期（**不自动通过**）；
- 驳回必须填意见；重新提审显示历史记录；
- 灰度发布（P3）：按用户白名单分批切换运行时 Schema 版本。

### 2.5 设计态实时预览

- 设计器「预览」按钮 → 独立预览链接（沙箱机制详见 §06 F10）；
- mock/真实数据（只读）切换；写操作默认拦截。

### 2.6 插件/物料市场（P2，租户内先行)

- **租户内市场**：租户开发者把自定义物料（MaterialMeta + 编译产物）发布为「租户物料」，全租户应用可拖拽使用；
- 上架流程：发布物料 → 填名称/图标/描述/propsSchema 文档 → 租户管理员审核 → 入库；
- 版本管理：物料多版本共存，引用方锁定版本；升级需在引用页面**显式确认**（propsSchema 不兼容时给出迁移提示）；
- 跨租户公开市场（P3）：含计费、备案、安全扫描（产物静态扫描禁止危险 API），不在本期范围。

### 2.7 实时协同（P3 预研说明）

- 技术路线：Yjs + WebSocket，Schema JSON CRDT 化；
- 前置条件：设计器状态管理原子化改造（immer 快照栈与 CRDT 不兼容）；
- 范围收敛：**只协同页面设计器**——建模/流程仍用锁（模型变更影响面大，实时协同收益低风险高）。

## 3. 业务规则汇总

| # | 规则 | 来源 |
|---|---|---|
| R1 | 锁粒度到单资源，不同资源并行编辑 | §2.1 |
| R2 | 掉线 60s 锁自动释放；强制解锁记审计 | §2.1 |
| R3 | 强制解锁后被解锁者保存触发版本冲突检测 | §2.1 |
| R4 | 通知按资源+用户聚合，5 分钟窗口合并 | §2.3 |
| R5 | 生产发布必须审批；测试环境免审 | §2.4 |
| R6 | 审批过期不自动通过；驳回必填意见 | §2.4 |
| R7 | 草稿自动保存 30s 节流；不做字段级三方合并 | §2.2 |

---

## 4. 权限点

| 权限点 | 说明 |
|---|---|
| 强制解锁 | 应用管理员 |
| 发布审批 | 应用管理员（可配多人） |
| 物料上架 | 租户开发者；审核为租户管理员 |
| 接收通知 | 按事件类型自动匹配（无需配置） |

---

## 5. 验收标准

- [ ] 两人同时打开同一页面设计器，后进入者看到持锁横幅且保存被拦截
- [ ] 持锁人关闭浏览器 60s 后锁自动释放，他人可正常获取
- [ ] 管理员强制解锁有审计记录；被解锁者后续保存触发版本冲突弹窗
- [ ] 字段删除后，引用页面的开发者收到站内信并可跳转影响面清单
- [ ] 生产发布必须经审批；驳回后申请人可见意见并可重新提审
- [ ] 草稿自动保存；浏览器崩溃重开恢复最近草稿
- [ ] 物料上架经审核后，全租户应用可在物料面板拖拽使用；升级需引用页面显式确认
- [ ] 设计器全模块操作响应 < 200ms（P95）：编辑锁获取/释放、通知聚合展示、审批提交交互均在预算内（顶层 PRD §4 指标落地）

---

## 6. 边界与不做的事

- 三方合并编辑器（字段级 merge UI）—— 恢复旧版覆盖即可
- 建模/流程的实时协同 —— 锁机制长期保留
- 跨租户公开插件市场 —— P3（含计费与安全扫描体系）
- 设计器内评论/批注（Figma 式）—— P3
