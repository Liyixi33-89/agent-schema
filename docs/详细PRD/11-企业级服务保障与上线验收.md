# 详细PRD 11 · 企业级服务保障与上线验收

> 上游文档：《PRD-低代码平台产品规划》v0.3 §5.1（三级上线门禁）、§4（非功能需求）
> 本文定位：**生产服务保障基线的操作级真源**——SLA、备份与灾难恢复、数据生命周期、容量基线、支持体系、发布与升级治理、上线门禁验收清单
> 交付阶段：Phase 1 只需满足 L-Pilot 受控试点门禁（G1-G7）；L-GA 商用门禁（G8）在 Phase 2 末期评估；L-Enterprise 行业门禁（G9）按客户需求触发
> 服务角色：平台运维/SRE、客户成功（CSM）、平台运营、法务与合规、租户管理员

---

## 1. 为什么需要这篇文档

顶层 PRD v0.2 及之前的文档体系回答了「做什么产品」，详细技术文档回答了「怎么实现」；但**「以什么等级的服务承诺交付给客户」没有统一真源**。后果：

- 销售/官网若宣称 99.9% SLA，但无人定义统计口径与排除项 → 承诺无法兑现也无法验证；
- 「永不物理删列」被误读为业务数据永久保留 → 与租户注销、隐私删除义务冲突；
- 各模块验收标准都是功能性的 → 没有任何一条验收覆盖「真实恢复演练」「容量压测」。

本文档把这些**服务级验收**集中定义，并给出三级上线门禁（与顶层 PRD §5.1 对齐——那边是结论层，本文是操作真源）。

## 2. 服务保障基线

### 2.1 SLA 与故障管理

**SLA 定义（对外承诺口径）**：

| 项 | 承诺 | 说明 |
|---|---|---|
| 月度可用性 | 99.9% | 统计对象：运行时应用访问 + 平台 API 网关；**不含设计器**（设计器可用性目标 99.5%，故障只影响搭建不影响线上业务）。不可用分钟预算 = 月总分钟 × 0.1%**按自然月实际天数计算**（31 天月 ≈ 44.6 分钟、28 天月 ≈ 40.3 分钟——43.8 分钟仅为 30 天月示例值，**不可当固定额度使用**） |
| 统计口径 | 按月历自然月，全租户聚合；分钟级可用性 = (总分钟 - 不可用分钟) / 总分钟 | **不可用分钟定义（可计算闭环）**：以 1 分钟为采样粒度，该分钟满足下列任一条件即记 1 不可用分钟——① 核心接口（登录/Schema 拉取/数据 CRUD）错误率 > 5%（分母 = 该分钟总请求数，**失败率不做 P95 分位**——分钟级按总量错误率判定，避免分位语义歧义）；② 核心接口全不可达（探测 + 真实流量双确认）；**连续性判定**：孤立 1 分钟故障不计（抖动容忍），连续 ≥ 5 分钟不可用才计入 SLA 统计（故障开始时间 = 连续段第 1 分钟，回溯计时起点） |
| 排除项 | 计划内维护窗口（须提前 72h 公告，每月 ≤ 1 次、单次 ≤ 2h，且安排在业务低峰）、客户侧网络/配置问题、客户应用自身缺陷（如客户脚本死循环被隔离）、不可抗力 | 排除项必须写入服务条款；**维护窗口分钟数从当月总分钟中扣除再计算**（不是从不可用分钟中扣） |
| 赔付 | 按未达标时长折算服务费减免（阶梯：<99.9% 减 10%、<99.5% 减 30%、<99.0% 减当月全部） | MVP/试点期不签赔付条款，仅内部达标要求 |

**故障分级与响应目标（内部运营纪律）**：

| 级别 | 定义 | 响应 | 恢复目标 | 客户通知 |
|---|---|---|---|---|
| P0 | 平台全局不可用 / 数据丢失风险 / 安全入侵 | 15 分钟内响应，全员投入 | 2h 内恢复或给出明确预期 | 30 分钟内公告 + 每小时更新 |
| P1 | 单租户不可用 / 核心功能受损（发布/登录/数据写入失败） | 30 分钟内响应 | 4h | 受影响租户即时通知 |
| P2 | 非核心功能受损 / 性能降级（如慢查询未达熔断） | 4h | 24h | 状态页记录 |
| P3 | 单客户咨询 / 缺陷不影响使用 | 1 工作日 | 排期修复 | 工单回复 |

- 值班要求：L-Pilot 起必须有人工值班通道（工作时间 IM 群 + 非工作时间电话转接）；L-GA 起 7×24 P0 响应；
- 每次 P0/P1 故障须在 48h 内输出**事后复盘**（时间线/根因/改进项/负责人），复盘文档归档且改进项纳入追踪。

### 2.2 备份与灾难恢复

**备份策略（数据库 / 对象存储 / 配置三层一致）**：

| 对象 | 备份方式 | 频率 | 保留期 |
|---|---|---|---|
| PostgreSQL（业务数据 + 元数据） | 物理全量 + WAL 归档（PITR 能力） | 全量每日 1 次；WAL 连续归档 | 全量 30 天，WAL 14 天 |
| 对象存储（上传文件/编译产物） | 服务端版本化或跨区复制 | 实时 | 版本保留 30 天 |
| 发布快照 / Schema 版本 | 随数据库备份 | — | 永久（版本记录本身轻量） |
| 平台配置（网关/环境变量） | Git 化管理 | 变更即提交 | 永久 |

**恢复目标**：

| 指标 | L-Pilot 目标 | L-GA 目标 |
|---|---|---|
| RPO（最大可容忍数据丢失窗口） | ≤ 15 分钟（WAL 归档粒度） | ≤ 5 分钟 |
| RTO（恢复时间目标） | ≤ 4h（区域级故障重建） | ≤ 1h（热备切换） |

**恢复的产品规则（必须实现为功能，不是运维口头承诺）**：

1. **恢复申请与审批**：数据恢复是高危操作——租户管理员在控制台提交（选恢复时间点/范围），平台管理员审批后执行；全程审计；
2. **恢复粒度分级**：
   - **单记录误删恢复**：逻辑删除的数据本就未物理删（PRD 01 §2.7），提供「已删除数据」管理员找回入口（P2）；
   - **单租户恢复**：从备份重建该租户数据到独立验证环境，客户确认后回灌；
   - **全量恢复**：仅 P0 场景，由平台管理员执行；
3. **恢复演练**：**每季度至少 1 次真实演练**（抽取备份在隔离环境完整恢复 + 数据抽样校验 + 记录 RTO 实测值），演练报告归档——**未演练的备份等同没有备份**；
4. 演练失败（备份不可用/数据损坏）视为 P1 事故处理。

### 2.3 数据生命周期与合规

> 关键纠偏：「字段永不物理删列」是 **Schema 演进策略**（PRD §6.1，防误删与兼容性），**不是业务数据保留承诺**。租户注销与隐私删除义务不受该策略约束。

| 场景 | 规则 | 交付阶段 |
|---|---|---|
| 审计日志 | 默认保留 1 年，按月分区归档（PRD 04 §2.8 已定） | P1 |
| 租户注销 | 注销申请（租户管理员发起 + 全员二次确认）→ 30 天冷静期（可撤销）→ 执行清除：业务数据/上传文件/元数据物理删除或匿名化，备份按保留期自然滚动清除；注销证明文件生成 | P2 |
| 个人信息删除（用户离职/注销账号） | 账号停用 + 个人标识匿名化（业务数据归属 created_by 保留外键语义）；如客户提出法定删除请求，走租户级流程 | P2 |
| 备份数据删除 | 备份随保留期滚动自然覆盖——**不追溯清除历史备份中的单租户数据**（技术上不可行），该限制写入服务条款 | 条款层 |
| 数据导出 | 全量导出（租户管理员发起，含审计）；导出行为本身记审计（PRD 04 已定） | P1 入口/P2 全量 |
| 存储地域 | 一期单区域部署；数据出境/多地域合规在 L-Enterprise 门禁逐客户评估 | 按需 |
| 敏感数据分类 | 平台侧仅区分「计量 payload 禁业务字段值」（PRD 09 已定）；客户业务数据的敏感级分类由客户自管，平台提供字段级加密存储能力（P3，PRD 04 §6 已定） | P3 |

**法务条款依赖清单**（L-GA 前法务定稿）：服务等级协议、数据处理协议（DPA）、安全事件通知义务（发现后 72h 内通知受影响客户）、备份清除限制声明、试点期 SLA 例外声明。

### 2.4 容量与性能基线（压测验收）

| 场景 | 基线 | 验收方式 |
|---|---|---|
| 单租户数据容量 | 单模型 100 万行 CRUD 达标（PRD 01 §5 已定 <1s P95） | 预置数据集回归测试（每次大版本） |
| 并发用户 | 500 并发在线用户（混合场景：70% 读 / 20% 写 / 10% 发布）P95 < 1.5s，错误率 < 0.5% | L-GA 前压测；L-Pilot 基线减半（250 并发） |
| 平台租户数 | L-Pilot ≤ 10 租户；L-GA 单区域 ≤ 500 租户（触发容量规划评审） | 容量看板监控 |
| 发布吞吐 | 并发 10 个应用同时发布不互相阻塞 | 集成测试 |
| 资源护栏 | 单租户慢查询熔断（PRD 06 §2.5 已定 3s）；L2 脚本单租户并发上限（PRD 10 已定）；租户级限流（网关 06BE） | 专项测试 |

### 2.5 发布与升级治理（平台侧）

客户应用的发布/回滚已在 PRD 06/08 定义；本节是**平台自身**的升级纪律：

- **平台升级兼容矩阵**：每次升级前声明兼容性——Schema 协议版本（向后兼容，旧版本 Schema 必须可渲染）、OpenAPI 契约（不 breaking，字段只加不删）、物料协议（老物料必须持续可加载）；违反兼容性 = 升级阻断；
- **升级窗口**：跟 SLA 维护窗口共用（72h 公告 + 业务低峰）；
- **灰度顺序**：内部环境 → 试点租户 → 全量；P0 级功能（数据库结构变更）先在影子库验证 Flyway 脚本；
- **回滚边界**：应用层回滚 = 重新部署上一镜像版本；**数据库 Flyway 脚本不自动回滚**（回滚脚本单独评审）；页面 Schema 回滚 ≠ 业务数据回滚（PRD 01 §2.8 已定）；
- **紧急变更通道**：安全补丁可跳过灰度直接全量，但须事后补公告与复盘。

### 2.6 支持体系

| 阶段 | 支持渠道 | 响应保障 |
|---|---|---|
| L-Pilot | IM 群（工作时间）+ 邮件工单 | P1 30 分钟（工作时间）；非工作时间 P0 电话 |
| L-GA | 工单系统（分级路由）+ CSM 名单制 + 状态页 | 按 §2.1 分级表 |
| L-Enterprise | 专属支持群 + 客户侧驻场选项（私有化） | 合同约定 |

- 自助排障优先：租户级健康页（PRD 09 §2.6）、脚本执行日志（PRD 10）、L3 控制台（P3）——目标是工单量随产品成熟下降；
- 客户成功职责：试点租户每周例会、配额饱和度跟进（PRD 09 §2.4）、流失预警介入。

## 3. 三级上线门禁验收清单（操作级）

> 门禁结论层见顶层 PRD §5.1；本节是逐项验收操作。每项标注**责任角色**与**证据物**——上线评审报告必须附证据物编号。

### G1-G7 · L-Pilot 受控试点门禁

| 门禁 | 验收项 | 责任角色 | 证据物 |
|---|---|---|---|
| G1 功能验收 | MVP 范围内详细 PRD 01/02/04/06/07 Phase 1 验收标准全过（依赖图 M15 demo 端到端） | 产品 + 研发 | 验收报告 + demo 演示录像 |
| G2 安全基线 | ①安全攻防用例（依赖图 M15 已列六类）全过；②越权测试：伪造租户头/资源 ID/文件 ID 全拒（PRD 04 §5）；③CSP 三态策略生效验证（Report-Only 阶段收集清零误报） | 安全负责人 | 攻防用例执行记录 + 渗透测试摘要 |
| G3 数据保障 | 真实备份恢复演练通过：从最近备份完整恢复到隔离环境 + 数据抽样校验 ≥ 99.9% 一致 + 实测 RTO 记录；恢复申请/审批流程文档化 | 运维/SRE | 演练报告（含时间线与实测值） |

| G5 人工支持 | 值班表 + 升级路径文档；试点客户支持群建立；P0/P1 响应 SLA 内部承诺签署 | 客户成功 | 值班表 + 升级路径文档 |
| G6 试点协议 | 客户书面确认：试点范围（业务场景白名单）、数据风险告知、SLA 例外（试点期不适用赔付条款）、数据退出机制（注销/导出路径） | 法务 + 销售 | 签署的试点协议 |
| G7 L2 隔离 | Worker 隔离验收全过（08FE §8 硬性要求：DOM 不可达/token 不进 Worker/死循环硬中断/网络出口三层兜底）；**未通过则 L2 功能整体关闭上线**（feature flag），不以「客户自担」替代平台责任 | 安全 + 前端 | 08FE §8 测试执行记录 |

### G9 · L-Enterprise 行业门禁（按客户触发，逐项评估）

| 评估项 | 说明 |
|---|---|
| 监管映射 | 按客户行业与部署地区逐条映射监管要求（等保 2.0 级别/金融行业规范/医疗数据条例/数据出境规则）——输出差距清单，逐项给出「平台已覆盖/需改造/无法承诺」三态结论 |
| 私有化交付件 | 按 PRD §6.3 触发条件启动：License 体系、离线升级包、安装器（当前明确不做） |
| 审计与取证 | 满足客户侧审计要求：操作日志导出格式、时间戳可信、管理员行为留痕完整性 |
| 安全认证 | 按客户要求评估 ISO 27001/SOC 2 等认证路径（成本与周期另立项） |

## 5. 验收标准（本模块自身）

- [ ] SLA 统计看板可用：按月输出可用性实测值，与承诺口径一致（含排除项标注）
- [ ] 备份自动执行且成功率看板可查；连续 7 天备份完整性抽检通过
- [ ] 恢复演练完成一次并归档报告：实测 RTO ≤ 4h、数据抽样一致率 ≥ 99.9%
- [ ] 故障注入测试：模拟 P0 场景，值班 15 分钟内响应、30 分钟内客户公告触达
- [ ] 租户注销流程（P2）：申请 → 冷静期 → 清除 → 证明文件，全流程审计可查
- [ ] 平台升级兼容矩阵在 CI 有断言（Schema 旧版本渲染回归 + OpenAPI diff 不 breaking）
- [ ] L-Pilot 上线评审报告出具（G1-G7 全部附证据物编号，五方会签）

## 6. 边界与不做的事

- 多区域容灾/异地多活—— L-Enterprise 按客户触发（一期单区域 + 备份出域）
- 实时数据订阅/CDP 同步类合规工具 —— 不做（平台是搭建工具不是数据中台）
- SOC 2 / ISO 27001 认证 —— G9 按客户要求评估立项，不预先投入
- 客户业务数据的敏感级自动分类引擎 —— 不做（客户自管，平台提供加密存储能力 P3）
- SLA 自动赔付结算 —— P3 随出账（当前人工核算）
- 7×24 全时段中文电话热线 —— L-GA 起评估（成本随客户数决策）
