# 详细PRD 03 · 流程编排引擎

> 上游文档：《PRD-低代码平台产品规划》v0.2 §3.3；技术基座 Flowable（BPMN 2.0）
> 本文定位：功能操作级 PRD——入口、界面、操作步骤、配置项、规则与反馈
> 交付阶段：Phase 1（流程画布只读 + 与表单动作衔接的数据登记闭环；**审批流执行闭环移 Phase 2**，2026-10-28 与顶层 PRD §5/依赖图 M15 对齐），Phase 2（顺序/分支审批执行 + 自动化触发器），Phase 3（L3 脚本节点）

---

## 1. 模块概述

### 1.1 是什么

两类能力共用一个引擎底座：

1. **审批流**：人工任务为核心（提交→审批→通过/驳回），与表单/模型绑定；
2. **自动化编排**：触发器驱动的无人值守流程（数据变更/定时→动作链），类 Zapier。

设计原则：**不自研流程引擎**——低代码流程 Schema 编译为 BPMN 交给 Flowable 执行；平台只做可视化编排层 + 业务数据桥接 + 可观测。

### 1.2 服务角色

| 角色 | 在本模块做什么 |
|---|---|
| 低代码开发者 | 画流程图、配审批人规则与动作节点 |
| 业务人员（发起人） | 提交表单触发流程、查看进度、撤回 |
| 审批人 | 待办处理（同意/驳回/转交/加签） |
| 应用管理员 | 处理失败任务重放、催办策略配置 |

### 1.3 入口与页面层级

- 设计态入口：应用工作台 →「流程」→ 流程列表 →（点「设计」）流程画布
- 运行态入口：顶部「待办/已办」中心 + 业务详情页内嵌审批时间线

## 2. 页面与操作明细

### 2.1 流程列表页

| 操作 | 触发 | 系统行为 |
|---|---|---|
| 新建流程 | 「新建流程」 | 选类型（审批流/自动化）→ 命名 → 进入画布 |
| 设计 | 「设计」 | 打开流程画布（编辑锁） |
| 发布/停用 | 「···」 | 发布后可被表单按钮/触发器引用；停用后不可新发起，在途实例继续 |
| 复制 | 「···」 | 拷贝定义生成副本 |
| 删除 | 「···」 | 逻辑删除；有在途实例时禁止 |

### 2.2 流程画布（设计态）

**节点面板（左）→ 画布（中）→ 节点属性面板（右）**，纵向节点流。

**节点类型**：

| 节点 | 用途 | 关键配置 |
|---|---|---|
| 开始（触发器） | 流程入口 | 触发方式：表单提交 / 数据变更 / 定时 Cron / 手动 |
| 审批节点 | 人工任务 | 审批人规则（§2.3）、超时策略、意见必填开关 |
| 条件分支 | 走向判断 | 每条出线一个 L1 表达式，必须有默认线 |
| 并行分支 | 同时推进 | 分支汇聚方式（全部完成/任一完成） |
| 动作节点 | 无人值守动作 | 动作类型 + 参数映射（§2.5） |
| 结束 | 终点 | 可配结束动作（通知发起人） |

**保存校验（阻断式）**：分支表达式语法错、存在不可达节点、审批人规则引用 DELETED 字段或不存在角色、表达式引用字段不在绑定模型中。

**绑定业务对象**：流程必须绑定一个模型（发起时带 recordId 关联业务记录）；表单按钮 TRIGGER_FLOW 自动传当前记录。

### 2.3 审批人规则（动态解析）

配置在审批节点属性面板，支持**多条规则组合**（按顺序取第一批命中）：

| 规则 | 解析逻辑 | 配置项 |
|---|---|---|
| 指定成员 | 直接取 | 选人（多选） |
| 部门主管 | 按发起人部门向上找 | 兜底级数（主管空缺时向上几级） |
| 角色 | 取角色成员 | 去重开关 / 含子角色开关 |
| 表单字段 | 字段值为 user 类型时取该值 | 选字段（支持多值字段） |
| 发起人自选 | 提交时弹窗选择 | 提示文案 |
| 上级节点处理人 | 取指定历史节点实际处理人 | 选节点（转办/连续审批场景） |

**解析时机：运行时实时解析**（不在建模时固化名单）——组织架构调整后无需改流程定义。

**解析结果为空时兜底策略**（节点级配置，三选一）：转交管理员 / 自动通过 / 阻塞并告警（默认）。

### 2.4 审批操作（运行态）

待办详情页 = 业务记录详情（只读）+ 审批操作栏 + 审批时间线。

| 操作 | 行为 | 规则 |
|---|---|---|
| 同意 | 完成任务流转下一节点 | 意见可配必填 |
| 驳回 | 回退到指定节点（默认发起节点），实例保持运行 | P2 支持驳回到任意历史节点 |
| 转交 | 当前任务改派他人 | 记录转交链 |
| 加签 | 当前节点插入临时审批人（前加签/后加签） | 会签场景 |
| 撤回 | 发起人在下一节点处理前撤回，实例终止 | 可配撤回窗口 |
| 催办 | 给当前待办人发通知 | 限频 1 次/小时 |

所有操作写入 `flow_task_log`（操作人/时间/意见/动作），详情页用 ApprovalTimeline 物料展示。

### 2.5 自动化触发器（P2）

| 触发器 | 实现 | 防抖/幂等 |
|---|---|---|
| 数据创建/更新/删除 | data-engine 写操作后发领域事件 | 更新支持"仅当字段变化"条件 |
| 定时 | Quartz Cron，单次或重复 | 分布式锁防多实例重复触发 |
| 手动 | 页面按钮 TRIGGER_FLOW | — |
| Webhook 入站 | P3（签名/重放防护） | — |

- 一个流程可配多个触发器；触发条件可加 L1 表达式**前置过滤**——不满足直接跳过且**不计执行次数**（影响计费口径）。

### 2.6 动作节点（P2）

| 动作 | 参数配置 | 失败策略 |
|---|---|---|
| 发通知 | 通道（站内/邮件/短信/IM 连接器）+ 接收人规则 + 模板 | 重试 3 次后记失败，默认不中断流程（可配） |
| 写数据 | 目标模型 + 字段映射（L1 表达式引用流程上下文） | 可配重试/中断 |
| 调 API | 选已注册 API + 参数映射 | 同上 |
| 调连接器 | 选 L4 连接器 + 请求映射 | 继承连接器自身超时重试 |
| 更新流程变量 | 表达式赋值 | — |

**执行可靠性**：动作一律经 MQ 异步消费，幂等键 `instanceId+nodeId+executionSeq`；失败进死信队列，流程详情页标记「动作失败待处理」，支持人工重放。

### 2.7 流程实例详情页

- **节点图实时高亮**当前节点；每个节点展示进入/离开时间、处理人、意见、动作节点输入输出（脱敏摘要）；
- 发起人/审批人/应用管理员可见（权限随业务记录）；
- 失败动作节点提供「重放」按钮（幂等保护，不重复执行）；
- 执行日志按租户隔离保留 90 天。

### 2.8 单步调试（P2）

- 设计态「调试」按钮 → 用 mock 数据发起沙箱实例 → 逐节点显示表达式求值结果（含分支走了哪条、为什么）；
- 排查「流程为什么走错分支」是客服最高频问题，此功能为上线前置条件之一。

### 2.9 流程与业务记录的绑定

```
流程定义 1 ─ n 流程实例 ─ 1 业务记录（modelId + recordId）
```

- 同一记录并发发起同一流程：默认拒绝（提示已有进行中实例），可配置允许并行；
- 业务记录逻辑删除时：进行中实例自动挂起并通知发起人。

## 3. 业务规则汇总

| # | 规则 | 来源 |
|---|---|---|
| R1 | 审批人运行时实时解析，不固化名单 | §2.3 |
| R2 | 审批人解析为空默认阻塞并告警 | §2.3 |
| R3 | 条件分支必须有默认线 | §2.2 |
| R4 | 触发条件不满足不计流程执行次数（计费口径） | §09 |
| R5 | 动作节点幂等键防重复执行；失败可人工重放 | §2.6 |
| R6 | 在途实例按发起时流程版本执行，不随定义更新切换 | 长期行为 |
| R7 | 业务记录删除 → 进行中实例挂起并通知 | §2.9 |
| R8 | 有在途实例的流程定义不可删除 | §2.1 |

## 4. 权限点

| 权限点 | 说明 |
|---|---|
| 流程发起 | 通过表单按钮/手动入口发起 |
| 流程设计 | 画布编辑（编辑锁） |
| 流程审批 | 由动态审批人规则决定（不挂 RBAC） |
| 实例查看 | 发起人/历史处理人/应用管理员 |

## 5. 验收标准

- [ ] P2：表单提交触发顺序审批流，两节点依次审批，驳回后回到发起人重新提交（**Phase 1 不含审批执行闭环**——Phase 1 仅验证数据登记闭环，见交付阶段）
- [ ] P2：审批人规则「部门主管」在组织架构调整后无需改定义即正确解析
- [ ] 审批人为空且兜底=阻塞时，任务停在节点并触发告警通知
- [ ] 条件分支引用 DELETED 字段时保存被阻断并提示
- [ ] 实例详情页完整展示每个节点处理记录与意见时间线
- [ ] P2：定时触发器按 Cron 准时执行；动作失败可人工重放且不重复执行
- [ ] 触发条件不满足的实例不产生流程执行计量

---

## 6. 边界与不做的事

- 自由绘制泳道图（只做纵向节点流）
- 跨租户流程（外部供应商审批）—— P3
- 流程版本迁移（在途实例不切版本）—— 明确为长期行为
- 入站 Webhook 触发 —— P3（安全成本高）
- L3 脚本节点 —— P3 企业版（§10）
