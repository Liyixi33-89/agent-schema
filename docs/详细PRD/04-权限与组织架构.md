# 详细PRD 04 · 权限与组织架构

> 上游文档：《PRD-低代码平台产品规划》v0.2 §3.4
> 本文定位：功能操作级 PRD——入口、界面、操作步骤、配置项、规则与反馈
> 交付阶段：Phase 1（登录 + RBAC 菜单/按钮权限 + 组织架构 + 基础审计，单租户），Phase 2（多租户 + 行级/字段级权限 + SSO + 审计完整版）

---

## 1. 模块概述

### 1.1 是什么

三层能力：

1. **认证**：谁能登录（账号密码 / SSO / 三方登录）；
2. **功能权限（RBAC）**：登录后能用哪些应用/页面/按钮/字段；
3. **数据权限**：同一页面，不同人看到不同的行（以及不同的列）。

多租户是横切约束：**任何数据读取都必须限定在租户内**，由基础设施强制（后端拦截器），不依赖业务代码自觉。

### 1.2 服务角色

| 角色 | 在本模块做什么 |
|---|---|
| IT 管理员 | 管组织架构、角色、授权、审计、登录策略 |
| 应用管理员 | 管应用内角色绑定与页面权限 |
| 所有用户 | 被权限约束的对象；管理员可查自己可见范围 |

### 1.3 入口与信息架构

- 管理后台（租户级）：成员与部门 / 角色权限 / 登录与安全 / 审计日志
- 应用级：应用设置 → 成员与角色

## 2. 页面与操作明细

### 2.1 成员管理

**界面**：成员列表（姓名/账号/部门/角色/状态/最近活跃）+「邀请成员」。

| 操作 | 触发 | 系统行为 |
|---|---|---|
| 邀请成员 | 「邀请成员」 | 填账号（邮箱/手机）+ 选角色 + 选部门；**P1 无邮件通道时由管理员直接建号 + 首次登录强制改密**（或生成一次性安全链接，不走邮件发送）；P2 邮件通道上线后恢复激活邮件；也可批量导入 Excel |
| 编辑成员 | 行「编辑」 | 改部门（主部门决定数据权限默认范围）、改角色（多选） |
| 停用/启用 | 行操作 | 停用即登录失效；待办按配置转移；席位释放（活跃口径见 §09） |
| 移除成员 | 行操作 | 需二次确认；数据归属保留 created_by；席位释放 |

**席位三口径联动**（口径定版 2026-10-28，与 PRD 09 §2.1/后端 13BE 同源）：

| 口径 | 定义 | 用途 |
|---|---|---|
| **授权席位** | 当前持有设计能力授权（任一应用「开发者」或「应用管理员」角色）的有效账号数 | 配额硬限（新增授权被拒即超限）；管理口径 |
| **活跃席位** | 授权账号中**滚动 30 天**内有设计器写操作的人数（仅登录不算） | 席位明细展示、客户自助清理、客户成功跟进 |
| **账单席位** | 出账口径（计费周期冻结、月中撤权折算等） | **P3 出账功能启动时另行冻结定义**，不直接沿用活跃口径 |

判定规则：按**设计能力授权**判定，不看角色名称字面——拥有任一应用「开发者」或「应用管理员」角色即具备设计能力，计**授权席位**。纯管理用途、不具备设计能力授权的账号不计授权席位。授权与活跃是两个独立口径：授权即计（无论是否操作），活跃只看写操作窗口。

### 2.2 组织架构（部门/岗位）

**界面**：左侧部门树（拖拽调整层级）+ 右侧部门详情（岗位/成员列表）。

- 部门树支持多级，path 物化路径加速「部门及下级」查询；
- 岗位挂在部门下（岗位仅用于业务语义，不直接产生权限）；
- 成员可属多部门，**主部门**唯一；
- 组织变更联动：调岗后数据权限即时切换；离职停用自动释放席位；审批人规则实时解析自动生效；
- P2 三方同步（企微/飞书）：单向同步 + 定时对账，冲突以三方为准。

### 2.3 角色与权限配置

**权限模型**：`User ─(n:n)─ Role ─(n:n)─ Permission(资源+动作)`，数据范围（DataScope）挂在角色上。

**界面**：角色列表 → 「权限配置」弹层，按资源树勾选：

| 资源 | 动作 |
|---|---|
| 应用 | 访问、管理（发布/成员） |
| 页面 | 查看、设计 |
| 模型 | 查看、设计、导入导出 |
| 记录 | 查看、新建、编辑、删除（行级数据权限再过滤范围） |
| 字段 | 可见、可编辑（列级） |
| 按钮/动作 | 可执行 |
| 流程 | 发起、查看（审批权由动态审批人规则决定，不走 RBAC） |

**判定链**：前端拉权限清单（应用树/页面/按钮点集，5 分钟缓存 + 失效推送）做渲染隐藏；**后端每个请求逐请求校验**——前端隐藏只是体验，后端校验才是安全边界。

### 2.4 行级数据权限（P2）

配置位置：角色 → 「数据范围」页签，按模型配置规则模板，可多条叠加取**并集**：

| 模板 | 效果 |
|---|---|
| 全部 | 不限 |
| 仅本人 | 只看 created_by = 自己 |
| 本部门 | 主部门相同 |
| 本部门及下级 | 部门子树 |
| 自定义规则 | L1 表达式（仅支持字段与当前用户属性比较，禁止子查询） |

- 用户多角色：**行级取并集（最大可见），字段级取交集（最少可见）**——不对称是刻意的：行级放宽利于协作，列级收紧保安全；
- 范围外记录：列表直接过滤不显示；详情页访问返回 403 归一化错误（不泄露记录是否存在）。

### 2.5 字段级权限（P2）

- 模型字段配置区：对角色 X 可见（不可见则 API 响应剔除该键）、可编辑（编辑则表单只读）；
- 与「字段 DELETED 隐藏」叠加：不可见 ∪ 已删除 → 一律剔除响应；
- **高频陷阱**：字段被剔除后，计算字段/联动表达式引用它会得到 undefined——设计器保存表达式时校验「引用字段对执行角色是否可见」给出警告（信息性，不阻断）。

### 2.6 登录与安全

- P1：账号密码（bcrypt）+ JWT（access 2h / refresh 7d，支持吊销黑名单）；**P1 密码找回走管理员重置**（邮件通道 P2 随 L4 连接器上线，见依赖图 M10 通知分期），管理员重置记审计并强制首次登录改密；
- P2：SSO（OAuth2 授权码 / SAML 2.0）、三方扫码登录（企微/飞书/钉钉，邮箱/手机匹配置信度阈值决定绑定或建新账号）；
- 登录安全策略（管理员可配）：失败 5 次锁定 15 分钟、异地登录提醒、密码策略（长度/复杂度/更换周期）。

### 2.7 多租户（P2，P1 单租户预留）

| 维度 | 隔离方式 |
|---|---|
| 数据 | 所有业务表 tenant_id 行级隔离，拦截器强制注入 |
| 元数据 | 模型/页面/流程定义带 tenant_id；租户间不可见 |
| 文件 | 对象存储按 `tenant/{id}/` 前缀隔离 |
| 域名 | 子域或路径前缀识别租户 |
| 缓存 | key 前缀 `t:{tenantId}:` |

- **P1 实现要求**：租户上下文已存在且恒返回默认租户（PRD §6.3 可退化约束），P2 上线不迁移数据只放开注册；
- 租户级定制（P2）：主题/Logo/登录页背景；
- 越权测试是 CI 硬性项：每个新增查询接口必须附「伪造租户上下文被拦截」单测。

### 2.8 操作审计日志

| 事件类别 | 内容 |
|---|---|
| 登录事件 | 成败/IP/UA/时间 |
| Schema 变更 | diff 全文（保存前后快照） |
| 数据变更 | 记录 ID、变更字段前后值（敏感字段脱敏存摘要哈希） |
| 权限变更 | 角色/授权 diff |
| 发布/回滚 | 应用版本、操作人 |
| 管理员敏感操作 | includeDeletedFields 读取、导出、连接器密钥查看 |

- 查询界面：按人/时间/事件类型过滤，支持导出（导出行为本身也记审计）；
- 保留策略：默认 1 年，按月分区归档。

| # | 规则 | 来源 |
|---|---|---|
| R1 | 前端隐藏只是体验，后端必须逐请求校验 | 安全铁律 |

## 4. 权限点

本模块自身的管理权限点：成员管理 / 角色管理 / 组织架构管理 / 安全策略配置 / 审计查看（仅租户管理员）。

---

## 5. 验收标准

- [ ] 无权限页面直接输 URL 返回 403，且不泄露页面存在性
- [ ] 角色 A（仅本人）+ 角色 B（本部门及下级）叠加后能看到全部门数据
- [ ] 字段对角色不可见时：API 响应不含该键、导出不含该列、表达式引用不报致命错误
- [ ] 伪造 tenantId 的请求被拦截（附自动化越权测试报告）
- [ ] 离职停用成员：登录失效、席位释放、待办转移配置生效
- [ ] 所有删除/变更操作可在审计日志查到操作人与 diff
- [ ] 登录失败 5 次锁定 15 分钟；异地登录收到提醒

## 6. 边界与不做的事

- **部分脱敏展示**（如手机号 `138****1234`、身份证掩码）—— 本平台字段权限为**二元模型**（可见 = 全量明文 / 不可见 = 键剔除），不做字段值级掩码。有掩码需求的字段建议改为「可见角色收窄 + 单独展示脱敏副本字段」的组合实现；如后续需求普遍再评估独立脱敏引擎（P3 后）
- 字段级加密存储 —— P3（详见 §01 边界：本模块只管可见性，加密存储归数据引擎）
- 租户间数据共享/协作（同一模型跨租户可见）—— 明确不做（合规风险）
- 自定义权限插件（判定逻辑可编程）—— P3 且需严格评审
- 密钥/证书用户侧托管（KMS 透明加密）—— P3
- 数据权限字段值黑名单类复杂规则 —— 表达式模板已覆盖主场景
