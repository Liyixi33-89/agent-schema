## 1. 产品定位

Schema 定位为"**面向企业内部业务系统/中后台的低代码搭建平台**"——以数据模型（Schema）为核心驱动引擎，支持页面、流程、权限、API 的可视化编排，让业务人员/初级开发者能在数据建模的基础上快速生成可用系统，同时保留专业开发者的扩展能力（代码逃生舱）。

**核心价值主张**：
- 从"写代码"到"配模型"：以数据结构（Schema）为单一事实来源，驱动表单、列表、流程、权限、API 自动生成。
- 降低中后台系统（CRM/OA/ERP/审批/数据管理类）的开发成本和周期。
- 保留扩展性：复杂逻辑可用代码块/插件机制逃生。

**目标用户角色**：
| 角色 | 需求 |
|---|---|
| 业务分析师/产品 | 不写代码，通过拖拽/配置快速验证业务流程原型 |
| 低代码开发者 | 用组件库+逻辑编排完成 80% 标准功能 |
| 专业前端/后端 | 通过 SDK/插件/自定义代码扩展平台能力边界 |
| IT 管理员 | 管理租户、权限、审计、部署 |

## 3. 模块详细拆解与需求点

### 3.1 数据建模引擎（最核心，决定平台天花板）

- **可视化建模器**：类 ER 图拖拉建表，字段类型（文本/数字/日期/枚举/关联/富文本/文件/地理位置等）
- **字段级配置**：默认值、校验规则（必填/正则/长度/唯一）、枚举选项、计算字段/公式字段
- **关系管理**：一对一/一对多/多对多，级联删除策略
- **模型继承/复用**：模板模型、模型片段（Mixin）复用公共字段（如审计字段 created_by/updated_at）
- **版本化 Schema**：模型变更需支持版本管理 + 变更差异（diff）留痕
- **Schema 导入导出**：支持 JSON Schema / OpenAPI / Excel 导入建模，便于迁移存量系统
- **多数据源支持**：内置数据库为主（P1）；外部数据源虚拟模型（MySQL/PostgreSQL/第三方 API）P3 评估（详见详细 PRD 01 边界）

#### 3.1.1 Schema 变更策略（已定稿，见 §6.1）

原则：**给足自由度，但不碰历史数据、不物理删列、变更前必须知情。**

| 变更类型 | 是否允许 | 执行方式 |
|---|---|---|
| 新增字段 | ✅ 允许 | 直接生效，无需确认（新字段对存量数据为空值，列表/表单展示为空） |
| 修改字段（标签/校验/组件类型/枚举新增值/排序/必填性） | ✅ 允许 | 直接生效，但**必填性从非必填改为必填不回溯校验存量数据**（仅对新数据生效） |
| 修改字段物理类型（如 string→number） | ✅ 允许 | 需影响面确认 + 目标格式声明。仅**新写入**的数据按新类型校验存储 |
| 删除字段 | ✅ 允许（逻辑删除） | **数据库列永不物理删除**。置字段 `status = DELETED` + `deleted_at` 标识，存量数据原样保留在库 |
| 删除模型 | ✅ 允许（逻辑删除） | 同上，表保留，元数据置删除标识 |
| 变更关联关系类型 | ⚠️ 受限 | 一对多→多对多等结构级变更需影响面确认，且不自动改写存量关联数据，由用户自行校验 |

**数据迁移策略：不迁移。** 所有变更采用"**新数据新规则，老数据保持原样**"（Schema 演进采用"读时兼容 + 写入时新校验"模式）：

- 存量数据不做批量格式转换，避免长时间锁表与数据损坏风险；
- 读取时由运行时按"当前 Schema 版本 + 记录写入时的 schema 版本"做渲染适配（记录中留存 `schema_version` 快照，可选）；
- 若存量数据格式与当前 Schema 不兼容（如旧值不是合法数字），前端展示为 `--` 并提供"数据修复"工具页，交由用户按需批量修正，**平台不自动改数据**。

**删除的落地方式（前后端分工）：**

1. 后端在元数据中写入删除标识（字段级/模型级），物理列与数据一律保留；
2. 后端自动生成 API 的响应**默认过滤已删除字段**（可从 `?includeDeletedFields=true` 白名单读取，仅管理员可用，供历史数据查看/导出）；
3. 前端渲染层拿到元数据后**自动隐藏**已删除字段：列表不展示列、表单不渲染该控件、筛选器不出现该条件、表达式中引用该字段时给出显式报错提示（而非静默返回 undefined）；
4. 已删除字段**不可再被新页面/新流程引用**，但已存在的引用（存量页面/流程）继续按隐藏逻辑工作，不报错阻断。

**二次确认与撤销：**

- **二次确认：必须**。任何删除在保存前弹出影响面清单（§3.1.2），用户需显式勾选"我已了解影响"才能提交；影响面涉及"外部 API 调用方"时升级为**输入模型名确认**的高摩擦交互。（类型变更不在确认清单中——类型创建后冻结，换类型走新建字段路径，见决策 §6.1）
- **审批流程：MVP 不做，二期作为企业版能力**（生产环境 + 特定危险操作才触发，避免日常开发被卡）。
- **撤销：支持，但分两层**——① 设计器内 `Ctrl+Z` 撤销未保存的编辑；② 保存后支持"恢复到某个历史 Schema 版本"（版本回滚），回滚仅恢复元数据定义，**不恢复数据**（因为数据本来就没删）。物理删除数据不提供撤销（本来也不删）。

#### 3.1.2 影响面分析（保存前强制）

保存前调用后端影响面分析接口，前端以清单形式展示，覆盖四类依赖：

| 依赖类型 | 统计口径 | 展示信息 |
|---|---|---|
| 页面/表单引用 | 扫描全部 PageSchema 的组件 props 与数据绑定 | 页面名称 + 引用字段 + 所属应用，可跳转 |
| 流程/自动化引用 | 扫描流程条件表达式与动作节点参数 | 流程名称 + 引用位置 |
| 开放 API 消费方 | 统计近 30/90 天该字段的对外调用记录 | 调用量、调用方 API Key 名称 |
| 存量数据量 | `SELECT count(*) WHERE data ? 'field'` | 影响记录条数（仅提示，不阻断） |

风险分级与交互：

- 🟢 **低风险**（新增字段 / 改标签 / 新增枚举值）：展示影响面即可，一键确认。
- 🟡 **中风险**（删除字段 / 必填性收紧）：必须勾选确认，附"推荐做法：先隐藏字段观察 1-2 周再删除"。（类型变更已移出风险矩阵——类型创建后不可变，见 §6.1）
- 🔴 **高风险**（删除被 ≥3 个页面引用 或 近 30 天有外部 API 调用的字段 / 删除模型）：输入模型名二次确认 + 记录审计 + 通知应用 Owner。

### 3.2 页面设计器

- **表单设计器**：基于 Schema 自动生成默认表单，支持拖拽调整布局、字段联动（显示/隐藏/禁用条件）、分组/分步表单
- **列表/表格设计器**：列配置、筛选器、排序、导出、批量操作、自定义列（计算列）
- **详情页/仪表盘设计器**：卡片、图表（接入 BI 组件）、Tab 布局
- **组件库**：基础组件（输入框/选择器/日期等）+ 业务组件（地址选择器、组织架构选择器、文件上传）+ 自定义组件接入协议
- **响应式/多端适配**：PC 中后台优先，兼顾移动端表单填报场景（分期兑现：P1 保底可用——栅格堆叠/表格转卡片；P2 断点级配置与移动专属物料，详见详细 PRD 02 §2.9）
- **页面逻辑绑定**：按钮点击→触发流程/API/脚本
- **主题与品牌定制**：企业 Logo、配色、自定义 CSS 变量

### 3.3 流程/逻辑编排引擎

- **审批流引擎**：可视化流程图（节点：审批人/条件分支/并行/会签）、动态审批人（按组织架构/角色/字段值计算）
- **业务逻辑编排**：触发器（新建/更新/删除/定时/手动）→ 动作（发消息/调API/写数据/发邮件）的低代码流程（类 Zapier/钉钉宜搭工作流）
- **脚本逃生舱**：代码扩展按四级边界分级开放，详见 §7
- **流程调试与追踪**：流程执行日志、单步调试、失败重试/补偿机制

### 3.4 权限与多租户

- **RBAC + 数据权限**：角色-权限-资源三层模型；数据权限需支持"按部门/按创建人/按自定义规则"行级过滤
- **多租户隔离**：SaaS 模式下租户间数据/Schema/资源完全隔离，支持租户级定制（主题、字段扩展）
- **组织架构管理**：部门/岗位/人员，与审批流/数据权限联动
- **登录与身份**：SSO（P2：OAuth2 授权码 / SAML 2.0；CAS 按客户需求 P3 评估）、第三方登录集成（P2：企业微信/飞书/钉钉）——分期详见详细 PRD 04 §2.6
- **操作审计日志**：谁在何时改了什么（Schema变更、数据变更、权限变更全量留痕）

### 3.5 API/集成能力

- **自动生成 REST API**：基于 Schema 自动产出 CRUD API，支持过滤/分页/排序标准协议（P1）；GraphQL 为 P3 扩展预留（REST + 聚合接口已覆盖主场景，详见详细 PRD 05）
- **Webhook/事件订阅**：数据变更对外推送
- **第三方系统集成**：预置连接器（企业微信/飞书/钉钉/短信/邮件/OSS存储/支付）
- **开放平台**：API Key 管理、调用额度、API 文档自动生成（Swagger）

### 3.6 运行时引擎（渲染 + 部署）

- **双轨渲染策略（已定稿，见 §6.2）**：
  - **默认组件与自定义组件库中的组件** → 走 **Schema 完全动态解析渲染**：运行时根据 `componentName` + props 从物料注册表查表渲染，设计器与运行时共享同一渲染核心，发布不发版（改 Schema 即时生效，无编译等待）。
  - **自定义代码（客户手写的前端脚本/自定义组件源码）** → 走 **设计时编译 + 运行时加载产物**：设计态用 Monaco 编辑，保存时在服务端（或构建 Worker）编译/打包为 chunk 产物，运行时按需加载执行。**不在浏览器运行时动态编译源码**（避免 CSP 冲突、包体积与编译耗时的用户体验问题）。
  - 两条轨道的边界：组件能否被"配置化"决定走哪条。能用 propsSchema 描述的一律走动态解析；需要写逻辑/直接操作 DOM 的才走编译产物。
- **多环境发布**：开发/测试/生产环境隔离，发布需走审批/版本控制
- **部署形态**：**纯 SaaS 为主**，架构上预留私有化部署能力（见 §6.3、§9）
- **性能与容灾**：大数据量列表的虚拟滚动、慢查询保护、Schema 变更导致全量页面重渲染的性能优化

### 3.7 应用管理

- **应用市场/模板中心**：行业模板（CRM/进销存/报修工单等）一键安装二次定制
- **应用生命周期**：创建→开发→测试→发布→下线，版本回滚
- **应用间依赖管理**：模型跨应用引用、组件共享

### 3.8 协作与研发支撑

- **多人协同编辑**：Schema/页面设计器支持锁定冲突提示（类似文档协作，避免互相覆盖）
- **变更评审/发布审批**：生产环境发布需要走审核流程
- **调试与预览**：所见即所得预览、沙箱数据模拟
- **插件/扩展市场**：第三方组件/连接器上架机制

### 3.9 运营与可观测性

- **用量计量**：活跃设计者席位、自动化/流程执行次数、AI 额度消耗、API 调用量、存储用量（详见 §8，是计费与客户成功的数据基础）
- **系统监控**：慢接口、错误率、Schema 变更影响面分析报表
- **用户行为分析**：页面使用率，辅助判断哪些应用/功能该优化或下线
- **升级触发点线索**：套餐配额饱和度、功能使用触达上限的租户清单（客户成功/销售的动作线索）

## 4. 非功能性需求

| 维度 | 要求 |
|---|---|
| 性能 | 单模型支持百万级数据分页查询 <1s（已落详细 PRD 01 §2.5/§5）；设计器操作响应 <200ms（已落详细 PRD 02/08 §5） |
| 安全 | 脚本沙箱隔离、SQL注入防护（自动生成API需防越权查询）、租户数据隔离 |
| 可用性 | SaaS 服务 99.9% SLA（统计口径/排除项/维护窗口与故障分级见《详细PRD 11》§2.1；上线走三级门禁，见 §5.1）；架构预留私有化容器化交付能力（一期不做交付件） |
| 扩展性 | 插件机制、自定义组件协议、开放 API，避免"平台天花板低于业务需求" |
| 兼容性 | 主流浏览器 + 移动端 H5 |
| 数据安全/合规 | 数据导出审计、敏感字段加密脱敏；数据生命周期/租户注销/隐私删除见《详细PRD 11》§2.3；行业合规按 §5.1 行业交付门禁单独评估（不以通用 SaaS 设计直接承诺） |

## 5. MVP 范围建议（第一期，建议 3-4 个月）

**目标**：验证"建模→生成页面→基础权限→跑通一个完整业务流"的核心闭环；上线等级为**受控试点**（门禁见 §5.1），不承诺正式商用。

1. 数据建模（基础字段类型 + 关联 + 简单校验）
2. 表单/列表设计器（基于模型自动生成 + 基础拖拽调整）
3. 业务登记闭环（表单提交→数据落库→列表/详情/状态流转；**审批流闭环移第二期**——见详细 PRD 03 交付阶段修订与《MVP开发任务依赖顺序图》M15）
4. RBAC 权限（角色+菜单权限，暂不做复杂行级数据权限）
5. 自动生成 REST API（CRUD）
6. 单租户 + 基础登录（SaaS 云端）
7. 应用发布（开发→生产，无需多环境审批流程）
8. Schema 变更：新增/修改/逻辑删除 + 影响面清单（基础版：仅页面引用 + 数据量统计）
9. L1 表达式 + L2 前端钩子脚本（逃生舱最小可用；L2 隔离验收未通过前不对试点租户开放，见 §5.1 门禁 G7）
10. 用量埋点采集（**只采集不出账**，为后续计费保留历史数据）

**第二期（4-6个月）**：审批流与自动化编排引擎、多租户、数据权限细化、第三方集成、应用市场、组件扩展协议、Schema 版本回滚、L4 HTTP 连接器、SSO。

**第三期**：开放平台生态、性能优化（大数据量）、移动端深度适配、AI 辅助建模/生成、L3 受管后端函数、私有化部署交付件（按客户需求触发）。

### 5.1 三级上线门禁（企业级可上线的验收真源）

> 详细规则、验收清单与责任分工见《详细PRD 11 · 企业级服务保障与上线验收》——本节是门禁结论，PRD 11 是操作级真源。

| 等级 | 定位 | 前置门禁（全部通过才可进入） |
|---|---|---|
| **L-Pilot 受控试点** | 少量企业、限定业务场景、限定席位 | G1 功能验收：MVP 范围内详细 PRD 01/02/04/06/07 Phase 1 验收全过；G2 安全基线：安全攻防用例（依赖图 M15）+ 越权测试全拒；G3 数据保障：真实备份恢复演练通过 + 恢复流程文档化；G4 可观测：租户级健康页 + 告警触达值班；G5 人工支持：值班响应与升级路径就绪；G6 试点协议：客户书面确认试点范围/数据风险/SLA 例外；G7 L2 隔离：Worker 隔离验收（08FE §8）通过前 L2 不开放 |
| **L-GA 正式商用** | 对外开放注册与付费 | G8 商用门禁：跨租户隔离渗透测试 + 容量压测达标（PRD 11 §2.4 容量基线）+ 恢复演练常态化（季度）+ 平台升级回滚演练 + SLA/支持/数据处理条款法务定稿 + 对应模块端到端验收 |
| **L-Enterprise 行业交付** | 金融/医疗等强监管行业 | G9 行业门禁：按部署地区、数据类型与客户监管要求逐项评估（等保/数据出境/行业认证），**不以通用 SaaS 设计直接承诺合规**；私有化交付件按 §6.3 触发条件启动 |

- 试点期限制：不承接依赖审批闭环、复杂数据权限或高敏感数据（人事薪酬/医疗档案等）的业务；
- L2 前端脚本隔离未通过安全评审前，**关闭 L2 功能**而非以「客户自担」免责——脚本安全边界是平台责任，不是合同条款可以转移的；
- 「永久不物理删列」是 **Schema 演进策略**（字段定义层面），不是业务数据保留承诺——租户注销/隐私删除/备份清理按 PRD 11 §2.3 数据生命周期独立执行。

> ⚠️ **AI 能力范围声明**：三期「AI 辅助建模/生成」目前仅为**概念预留**——计量体系（§8.4 AI token 口径）与配额 UI（详细 PRD 09）已先行落地，但 AI 功能本身（辅助建模？生成页面？生成脚本？）**范围未定义**。启动前需单独输出 AI 功能 PRD 明确场景清单，避免"计费表已就绪、产品形态为空"的误解。

## 6. 关键产品决策（已拍板 v0.2）

### 6.1 Schema 变更策略 ✅

**结论：允许新增/修改/删除（软删除），数据库不做物理删除；保存前强制影响面告知；不做数据迁移（仅对新数据生效）。**

| 决策项 | 结论 |
|---|---|
| 新增/修改字段 | 允许，直接生效 |
| 删除字段/模型 | 允许，但**仅逻辑删除**（后端写删除标识，物理列与数据永久保留） |
| 前端表现 | 渲染层按元数据标识自动隐藏；已删除字段不可被新增引用，存量引用降级为隐藏而非报错 |
| 数据迁移 | **不做批量迁移**，存量数据原样保留；不兼容旧值展示 `--` + 提供人工「数据修复」工具 |
| 二次确认 | **必须**（影响面清单 + 勾选确认；高风险需输入模型名） |
| 审批流程 | MVP 不做，二期企业版可选（仅生产环境危险操作触发） |
| 撤销 | 支持键盘撤销未保存编辑 + 保存后 Schema 版本回滚（仅恢复定义，数据本就未删） |

实现细节见 §3.1.1 / §3.1.2。

### 6.2 渲染方式 ✅

**结论：双轨——默认组件库/自定义组件库（遵循物料协议）走 Schema 完全动态解析渲染；客户自定义代码走「设计时编译 + 运行时加载产物」。**

- 判据不是「内置还是自定义」，而是「**能否用 propsSchema 描述**」。
- 动态解析轨道：发布不发版，Schema 改完即时生效，设计器与运行时共享渲染核心（保证所见即所得）。
- 编译轨道：自定义源码在设计态由 Monaco 编辑，保存时由服务端编译打包为 ES chunk，运行时按需 `import()` 加载；**不在浏览器运行时动态编译**（规避 CSP 冲突、包体积与首屏耗时）。
- 两条轨道通过统一 `MaterialMeta` 协议对齐（`component` 字段既可为同步组件，也可为返回 Promise 的远程加载器）。

### 6.3 交付形态 ✅

**结论：纯 SaaS 为主，架构上预留私有化部署能力（一期不产出交付件、不做 License 体系）。**

「预留」意味着现在就必须遵守的约束（成本低、后补极贵）：

1. **外部依赖全部抽象**：对象存储、MQ、缓存、短信/邮件、LLM 走接口 + 配置化，不散落 SDK 调用。
2. **不依赖云厂商专有能力**：必须用的收敛到单点适配层，私有化时可换开源自建。
3. **配置外置**：不写死域名/密钥；多租户逻辑可退化为单租户（`tenantId` 恒为 1）。
4. **核心元表用 Flyway 管理**，保证可版本化升级。
5. **不为私有化过度设计**：不做 License 校验、离线升级包、多形态安装器——触发条件为「出现首个愿意付费的私有化客户」。

### 6.4 逃生舱边界 ✅

**结论：按「影响半径」分四级开放，L1/L2 标配，L4 二期主推，L3 三期企业版默认关闭。** 详见 §7。

### 6.5 计费模式 ✅

**结论：设计者席位订阅（主）+ 自动化执行/AI 用量（次）+ 套餐配额护栏（应用数/API/存储）；不以应用数、注册用户数作为计价主体。** 详见 §8。

## 7. 逃生舱：分级开放边界

**核心原则：边界不按「前端/后端」划，按「这段代码能拖垮谁」划。**

| 级别 | 形态 | 开放对象 | 影响半径 | 发布流程 | 交付阶段 |
|---|---|---|---|---|---|
| **L1 表达式** | 受限表达式 `{{ }}`，无副作用 | 全员默认 | 单字段 | 保存即生效 | Phase 1 |
| **L2 前端脚本** | 页面/组件级 JS 钩子 | 业务开发者 | 单页面 | 保存即生效（有调试台） | Phase 1 |
| **L3 后端函数（受管）** | 脚本节点跑在隔离沙箱 | 高级开发者，需申请 | 单流程/单应用，**可影响平台** | 审核 + 灰度 + 可回滚 | Phase 3，企业版默认关 |
| **L4 外部服务** | 客户自有 HTTP 服务，平台只做连接器 | 企业客户 | 平台外部 | 仅注册连接 + 密钥托管 | Phase 2 |

### 7.1 L1 表达式（标配）

- 场景：显隐条件、计算字段、校验规则、流程分支、数据权限条件。
- 实现约束：**禁止 `eval`/`new Function`**，用受限 AST 解释器（前端 jsonata 类引擎 / 后端 Aviator），只暴露白名单函数（日期/字符串/数值/集合），无 IO、无副作用、有执行步数上限。
- 体验要求：设计态立即报红（含行号与原因），不允许「保存成功但线上炸」。

### 7.2 L2 前端钩子脚本（标配）

**不开放「随便写 JS」，只开放一套窄而稳的钩子契约**（开放性体现在覆盖场景，而非 API 面积）：

```js
onLoad(ctx)                        // 页面初始化
onFieldChange(fieldKey, value, ctx)
beforeSubmit(ctx)                  // return false 可阻断提交
afterSubmit(result, ctx)
onActionClick(actionKey, ctx)
onBeforeDelete(record, ctx)
```

`ctx` 为受控对象，只给这些能力：

| 能力 | 说明 |
|---|---|
| `ctx.form.get/set/getValues/setValues` | 仅当前表单字段读写 |
| `ctx.api.call(name, params)` | 仅能调平台内已注册的 API/流程（走统一网关，继承调用者权限） |
| `ctx.ui.toast/confirm/dialog` | UI 交互 |
| `ctx.logger.info/warn/error` | **强制提供**（否则客户用 console，线上问题不可查） |
| `ctx.user` | 只读且脱敏（id/roles/dept） |
| `ctx.page.params/query/mode` | 页面上下文 |

**明确不提供（红线）：**

- `window` / `document` 直接访问、DOM 操作（破坏虚拟树一致性）
- **原生 `fetch` / `XMLHttpRequest`**（一旦开放，外部调用绕过网关 → 丢失鉴权、审计、限流、密钥托管、可观测的全部价值）
- `localStorage` 裸访问（走平台封装的用户偏好 API）
- 任何可读其他租户/其他用户数据的入口

配套：脚本测试台（mock ctx 调试）、执行错误上报到控制台、执行时长上限（如 500ms 告警）、脚本 API 语义化版本 + 12 个月兼容承诺。

### 7.3 L3 后端受管函数（企业版，默认关闭，Phase 3）

**本质是自建轻量 FaaS，六道闸门缺一不可：**

1. **进程隔离**：独立执行器（GraalVM 受限 Context / 独立 Pod），**绝不在主应用进程 eval 客户代码**。
2. **资源上限**：CPU、内存、硬超时（如 5s）、出网白名单，默认禁内网访问。
3. **数据访问走封装接口**：不许直连数据库，只能调 `dataEngine.query()` 等带权限校验的接口，且**必须继承调用者数据权限**（最易忽略的越权入口）。
4. **可观测**：每次执行记录 traceId/耗时/错误，客户可在控制台自查报错（否则全变工单）。
5. **版本与灰度**：脚本版本化、可回滚，线上改动需审核 + 10% 灰度。
6. **计费与配额**：执行次数计入用量计费；单租户并发上限（防一个客户的死循环拖垮全平台）。

**默认关闭的产品理由**：不是技术限制，而是让客户先想清楚是否真的需要，避免平台早期被定制脚本淹没。

### 7.4 L4 外部服务连接器（Phase 2，性价比最高）

**优先做 L4 而非 L3 的理由**：平台只做「HTTP 连接器 + 密钥托管 + 超时重试 + 调用日志 + 出网白名单」，客户用任何语言、任何算力，**扩展性由客户自己的基建买单**，平台不承担托管成本与安全责任。

能力要求：连接配置（URL/鉴权/超时/重试）、密钥加密存储与轮换、请求响应字段可视化映射、调用日志与失败重放、按连接统计调用量（计入护栏档位）。

### 7.5 反向收编策略（长期控脚本量）

- 定期扫描脚本，识别高频模式（金额阈值判断、日期加减、字段拼接、跨字段比较）→ 沉淀为内置函数/公式库/可视化条件配置器。
- 统计「脚本 API 使用分布」，仅少数客户在用却阻碍重构的 API 推动迁移下线。
- 合同层面明确：脚本正确性与安全由客户自担，平台只保证执行环境隔离。

## 8. 计费与计量体系

### 8.1 计费维度选择（为什么这么定）

| 候选维度 | 是否作为计价主体 | 理由 |
|---|---|---|
| 应用数 | ❌ | 客户把功能塞进一个应用即可绕开，收入天花板低且逼客户做烂架构 |
| 注册用户数 | ❌ | 共享账号/僵尸账号普遍，收不到钱还污染数据 |
| API 调用量 | ❌ 仅作护栏 | 按量主计价会惩罚客户做集成，压制平台网络效应 |
| 存储 | ❌ 仅作护栏 | 客户第一反应是删数据/搬走，降低粘性 |
| **设计者席位（Builder Seat）** | ✅ **主计价** | 与客户组织扩张同步；口径清晰无争议；终端填报用户不当主计价 |
| **自动化/流程执行次数 + AI 额度** | ✅ **次计价** | 边际成本随用量增长，符合成本结构；随客户业务量自然增长 |

**收入结构目标**：订阅占 60-70%（可预测性），用量占 30-40%（增长弹性），对应 NRR > 120%。

### 8.2 套餐分层（3 档 + 1 企业版）

| 档位 | 计费方式 | 定位 |
|---|---|---|
| 免费/试用 | 限席位 + 限应用数 + 低配额 | 漏斗，不做成完整产品 |
| 团队版 | 席位订阅 | 主流成交档 |
| 专业版 | 席位 + 含固定额度 + 高级权限/审计 | 升级档 |
| 企业版 | **年付打包，不按席位**（含 SSO、Schema 级隔离、L3 沙箱、专属支持） | 5-10 倍溢价来源，20% 客户贡献 60% 收入 |

定价锚点：锚「客户自研成本」而非「平台成本」——席位年单价约为客户所在地一名开发年薪的 15-25%（替代约 0.3-0.5 人产能，客户算得过账）。

### 8.3 扩张机制（利益最大化的真正杠杆）

| 机制 | 做法 |
|---|---|
| Land & Expand | 低摩擦进场，靠搭建者与应用数量增长自然触发升级 |
| 活跃口径计费 | 席位按「30 天内有设计器操作」计费，降低采购阻力，客户敢买更多 |
| 升级触发器产品化 | 客户想用高级能力的瞬间弹升级（跨应用引模型、看审计、SSO），替代销售电话 |
| 预付额度包 | 预付享折扣、可结转不退现——现金流最好的杠杆 |
| 单位经济红线 | 每档位「平均用量 × 单位云成本 ≤ 档位价格 30%」，**毛利率 <70% 说明定价错了** |

### 8.4 计量指标清单（运营统计模块验收标准）

**① 计费口径类（100% 准确、可对账、幂等）**

三个席位口径严格区分，不得混用（口径真源见详细 PRD 04 §2.1 与 PRD 09 §2.1，判定服务见后端 13BE）：

- **授权席位**：当前持有设计能力授权（开发者/应用管理员角色）的有效账号数——控制授权上限与配额硬限；
- **活跃席位**：授权账号中滚动 30 天内有设计器写操作的人数——客户成功与席位明细展示口径；
- **账单席位**：商业化出账口径——计费周期冻结规则、月中撤权折算、跨月入职比例等**在出账功能启动时另行冻结定义**（PRD 09 §2.7），不直接沿用活跃口径；
- 自动化/流程执行次数（需明确失败是否计价，建议：平台故障不计、客户逻辑失败计）
- AI token 消耗、存储 GB、API 调用次数（护栏档位用；**AI 功能范围见 §5 声明——先有计量口径，产品形态三期定义**）

**② 商业化漏斗类（判断定价是否调对）**
- 试用→付费转化率、成交周期
- 席位扩张率、Logo Churn、**NRR（北极星）**
- 各档位配额饱和度（≥80% 为最热升级线索）

**③ 单位经济类（判断是否在亏卖）**
- 每租户平均云成本（计算/存储/LLM/带宽拆分）
- 各档位毛利率、每席位毛利
- 免费档成本占总收入比（>10% 需收紧）

**④ 风险类（防薅）**
- 共享账号检测（同一席位多 IP/多设备高频切换）
- 用量异常突增告警（防刷 AI 额度、脚本刷流程）
- 配额超限仍在用 / 欠费未停服的租户清单

### 8.5 落地节奏

**MVP 阶段只埋点、不出账单**（免费期打包销售，精力放在验证 PMF），但**数据采集从第一天全量开启**——计费能力上线后历史数据无法回溯，缺失就无法定价。触发上线信号：客户主动要求走内部采购流程。用量计费最后上，因其依赖精确 metering 基础设施（事件采集 → 聚合 → 幂等出账 → 对账）。

## 9. 私有化部署预留清单（对应 §6.3）

- [ ] 元表结构 Flyway 版本化，可离线升级
